# BubblePilot 产品路线图

路线图按可验证的垂直切片推进，不预先创建没有实现入口的模块。

当前进度：M0、M1、M2、M3、M4 已完成；M5 的功能与运维工具已实现，目标环境备份恢复和升级回滚演练待执行。

M2-M5 的用户视角验收场景见[典型用户交互故事](典型用户交互故事.md)。

## M0：文档与工程规范

完成标准：

- 需求、架构、数据、工作流、BlueBubbles 集成、安全、开发、部署和发布文档建立。
- `main` 分支保护、短期功能分支、英文提交规范和 PR 模板确定。
- 明确消息数据边界、节点合同和幂等原则。

## M1：消息接入与归档闭环

范围：

- BlueBubbles Webhook 适配器。
- 消息信封、外部事件去重和监听范围配置。
- 聊天、群聊和消息的持久化。
- 最小查询接口和健康检查。

完成标准：同一事件重复投递不会重复入库，监听范围外的消息不会进入业务归档。

## M2：事件匹配与基础动作

状态：已完成。

范围：

- 关键词、正则、聊天、发送者、消息类型和 IANA 时区时间窗口匹配，并提示活动触发器的潜在重复回复冲突。
- 持久化入站自动化判定，区分无活动触发器、条件未命中和已命中执行。
- 归档与调度之间使用可恢复的 `evaluation-pending`，容量拒绝后的 Webhook 重投能安全补齐判定且不重复回复。
- 工作流版本和激活状态。
- 条件、日志、回复等基础节点。
- 执行记录与失败重试。

完成标准：可以配置一个事件，把匹配到的消息回复到原聊天，并能查看完整执行轨迹。

## M3：可编排工作流与 AI

状态：已完成。

范围：

- 节点注册表和配置 Schema。
- 分支、变量映射、上下文窗口和超时策略。
- 多 OpenAI 兼容 AI Provider 的增删改、启停、排序和连通性测试。
- 有序 Provider 路由、候选 Fallback、节点级 Retry、自动降级和冷却恢复。
- AI 输出安全检查和回复策略。

完成标准：新增一个节点只需实现节点合同、配置校验和测试，不修改核心调度器；首选 Provider 不可用时可以有界切换到后备 Provider，并在执行轨迹中解释每次尝试和健康状态变化。

## M4：Web 管理与搜索

状态：已完成。

范围：

- 登录、会话和敏感操作二次验证。
- 二次授权和管理会话按服务端绝对时间在 Web 端主动到期，已加载消息正文随授权失效立即清空并遮蔽。
- 聊天监听配置、消息搜索、工作流编辑和执行详情。
- 管理首页展示最近入站事件的安全元数据和自动化判定，不暴露消息正文或原始 Payload。
- 审计日志和按权限限制的导出。

完成标准：管理员可以从 Web 完成一条消息监听到工作流发布的闭环。

## M5：运行可靠性与发布

状态：实现已完成，环境演练待封板。

范围：

- Compose 升级、备份恢复和诊断命令。
- 失败队列、限流、超时、死信和告警。
- 可选的独立 Worker 运行模式验证。

完成标准：故障恢复、回滚和数据备份均有演练记录；正式版本可固定镜像和数据库迁移升级。

已实现人工死信恢复与关闭、逾期 Retry 安全接管、等待期关闭保护、未知出站禁止重发、运行状态摘要、API/Webhook 限流、有界执行容量、进程内 Dispatcher 边界、有界消息内容保留与原子审计、诊断与备份校验脚本。当前开发机没有 Docker 或 PostgreSQL 客户端，自动化恢复和保留策略测试、脚本语法检查已通过，真实 Compose 备份恢复与版本回滚仍需按[可靠性演练记录](可靠性演练记录.md)在目标环境执行后才能把 M5 标记为完成。

## M6：扩展生态（后续）

- 更多消息来源适配器。
- 外部队列和多节点执行器。
- 可复用工作流模板和版本仓库。
- 更细粒度的多用户、角色和租户隔离。

这些能力只有在 M1-M5 的数据、合同和观测基础稳定后才进入实现。
