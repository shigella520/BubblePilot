# BubblePilot 产品路线图

路线图按可验证的垂直切片推进，不预先创建没有实现入口的模块。

## M0：文档与工程规范

完成标准：

- 需求、架构、数据、工作流、BlueBubbles 集成、安全、开发、部署和发布文档建立。
- `main` 分支保护、短期功能分支、英文提交规范和 PR 模板确定。
- 明确消息数据边界、节点合同和幂等原则。

## M1：消息接入与归档闭环

范围：

- BlueBubbles Webhook 适配器。
- 消息信封、外部事件去重和监听范围配置。
- 聊天、群聊和消息的持久化。
- 最小查询接口和健康检查。

完成标准：同一事件重复投递不会重复入库，监听范围外的消息不会进入业务归档。

## M2：事件匹配与基础动作

范围：

- 关键词、正则、聊天、发送者和消息类型匹配。
- 工作流版本和激活状态。
- 条件、日志、回复等基础节点。
- 执行记录与失败重试。

完成标准：可以配置一个事件，把匹配到的消息回复到原聊天，并能查看完整执行轨迹。

## M3：可编排工作流与 AI

范围：

- 节点注册表和配置 Schema。
- 分支、变量映射、上下文窗口和超时策略。
- OpenAI 兼容 AI Provider。
- AI 输出安全检查和回复策略。

完成标准：新增一个节点只需实现节点合同、配置校验和测试，不修改核心调度器。

## M4：Web 管理与搜索

范围：

- 登录、会话和敏感操作二次验证。
- 聊天监听配置、消息搜索、工作流编辑和执行详情。
- 审计日志和按权限限制的导出。

完成标准：管理员可以从 Web 完成一条消息监听到工作流发布的闭环。

## M5：运行可靠性与发布

范围：

- Compose 升级、备份恢复和诊断命令。
- 失败队列、限流、超时、死信和告警。
- 可选的独立 Worker 运行模式验证。

完成标准：故障恢复、回滚和数据备份均有演练记录；正式版本可固定镜像和数据库迁移升级。

## M6：扩展生态（后续）

- 更多消息来源适配器。
- 外部队列和多节点执行器。
- 可复用工作流模板和版本仓库。
- 更细粒度的多用户、角色和租户隔离。

这些能力只有在 M1-M5 的数据、合同和观测基础稳定后才进入实现。
