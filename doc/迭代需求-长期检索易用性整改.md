# 迭代需求：长期检索易用性整改

> 状态：方案已确认（2026-11-27），待实施。整理日期：2026-11-27。目标：让管理员只需要“开 / 关”和“看状态、点修复”，索引补建、模型切换、旧数据清理由系统自动完成。

## 1. 现状问题

| 问题 | 现状 |
| --- | --- |
| 概念多 | 页面同时出现“授权”“补建”“代次”“覆盖”“增量 / 补建 / 重建任务”等术语，管理员需要理解索引内部机制 |
| 操作分散 | 列表里有授权开关、配置按钮和“重建索引”按钮；补建、检索测试、任务列表在弹窗里，模型切换与任务在 AI 服务 |
| 授权后无历史 | 授权只索引之后的新消息，历史需要另外建补建任务，且要理解时间范围 |
| 补建全量重跑 | 已修复为只补缺口（`1f0f62c`），但仍需从头扫描整段聊天 |
| 健康状态不可见 | 缺口、失败、上游故障只能进弹窗或任务列表才能发现；失败任务停在 failed，需要人工逐个重试 |
| 模型切换繁琐 | 改模型 → 新建构建中代次 → 人工补建每个聊天 → 人工“验证覆盖并启用” → 旧代次数据永久保留 |
| 覆盖率统计慢 | 大聊天上统计超时导致弹窗报错、检索失败（已修复，`e75cb69`） |

## 2. 方案总览

| 编号 | 改动 | 来源 |
| --- | --- | --- |
| R1 | 列表改为“长期检索”状态图标，不再有开关；启用 / 停用统一放在配置弹窗；去掉“授权”字样 | 你的第 1 点 |
| R2 | 配置弹窗重做：关键数据 + 少量操作；补建、检索测试都不填时间 | 你的第 2 点 |
| R3 | 模型切换自动化：自动建新代次、自动补建、覆盖完成自动切换、旧代次停用 3 天后自动清理 | 你的第 3 点 |
| R4 | 健康图标提供一键修复：缺失 → 自动建只补缺口的补建任务 | 你的第 4 点 |
| R5 | 启用聊天时自动补建全部历史 | 补充 |
| R6 | 上游恢复后自动重试失败的索引任务 | 补充 |
| R7 | 补建只扫描未索引的消息（直接跳过已索引区段） | 补充，R4/R5 的前提 |
| R8 | 健康状态由服务端统一计算，列表一次查询拿到全部聊天 | 补充，性能前提 |
| R9 | 设置页精简：维度由测试连接自动填写，问题前缀、模型版本标识收进“高级” | 补充 |

## 3. 健康状态定义（R8，所有界面共用）

服务端为每个聊天计算一个状态，列表图标、配置弹窗、AI 服务总览都使用同一结果：

| 状态 | 判断 | 图标 / 颜色 | 一键操作 |
| --- | --- | --- | --- |
| 未启用 | 该聊天未开启长期检索 | 灰色空心 | 无（去配置启用） |
| 全局已关闭 | 全局开关关闭 | 灰色斜线 | 无（去 AI 服务开启） |
| 索引中 | 有进行中的补建 / 重建任务 | 蓝色进度环，悬停显示百分比和预计完成 | 无 |
| 正常 | 已启用，未索引消息为 0（或仅剩刚到、排队中的新消息） | 绿色 | 无 |
| 有缺失 | 存在未索引且无进行中任务覆盖的消息 | 橙色，显示缺失条数 | **修复**：建只补缺口的补建任务 |
| 服务异常 | 最近索引失败原因为上游错误（HTTP 5xx / 超时 / 连接失败），且最近一次测试或索引仍失败 | 红色，悬停显示最近错误与上游请求 ID | **重试**：先测连接，成功后重试失败任务；失败则提示去检查服务 |
| 需重建 | 角色归属变化导致需要重建（现有 `bot_memory_rebuild_required`） | 橙色 | **修复**：启动现有重建流程（替代列表里的“重建索引”按钮） |

“缺失条数”只统计保留期内、未清理的消息。状态在列表接口里一次算出（按聊天分组聚合，沿用 `e75cb69` 的快速写法），不再逐个聊天调用覆盖率接口。

## 4. 详细设计

### R1 消息页列表

- 列名“长期检索授权”改为“长期检索”，单元格只放健康图标 + 简短文字（如“正常”“缺失 128 条”“索引中 42%”）。
- 去掉列表里的开关和“重建索引”按钮；点击图标或行内“配置”打开配置弹窗。
- 有可修复状态时，图标旁显示“修复”按钮（需敏感操作授权，未授权时就地解锁）。
- 页面说明文字里的“授权”统一改为“启用”。接口字段 `memoryAuthorized` 保持不变，只改界面文案。

### R2 配置弹窗

自上而下只保留：

1. **状态卡**：健康图标、已索引 / 总数、缺失、进行中任务进度、最近错误（如有，含上游请求 ID）。
2. **主操作**：启用 / 停用开关；状态需要时出现“修复”。停用时说明“已建立的索引保留，可随时重新启用”。
3. **检索测试**：只填问题，不填时间；结果显示命中来源、检索方式（向量 + 关键词 / 仅关键词）及降级原因的中文说明。
4. **最近任务**（折叠）：只列补建 / 重建 / 失败任务；“新增消息索引”默认隐藏，可展开查看。

去掉“新建历史补建任务”弹窗和时间范围；补建由启用（R5）和修复（R4）自动触发。时间范围补建仍保留在接口中，供高级场景使用，界面不再暴露。

### R3 模型切换自动化

```text
修改模型并保存
  └─ 测试连接（必须通过，自动回填维度）
  └─ 确认框：将为 N 个已启用聊天、约 M 条消息重建索引，期间检索继续使用当前模型
       ├─ 取消 → 不保存
       └─ 确认 → 新代次“切换中”；为所有已启用聊天自动建只补缺口的补建任务
            └─ 后台：新消息只写入新代次（旧代次继续服务检索，切换期间的新消息暂不在旧代次中）
            └─ 所有已启用聊天覆盖完成 → 自动切换为当前代次，旧代次标记“已停用”（记录时间）
            └─ 停用满 3 天 → 自动清理旧代次的向量、分块、索引标记和任务；保留代次记录本身
```

- 设置页在切换期间显示进度条：“正在切换到 xxx：已完成 a / b 个聊天，预计 hh:mm 完成”，并提供“放弃切换”（新代次直接清理，继续使用旧模型）。
- 自动切换条件沿用现有覆盖校验（新代次覆盖所有已启用聊天，且旧代次已索引的消息新代次都有）；校验不通过时不切换，健康状态显示具体缺口，可一键修复。
- 清理只删除数据量大的部分：`memory_embeddings`、`memory_chunks`（及来源）、`memory_indexed_messages`、该代次的任务与任务项。代次记录保留（状态改为“已清理”），以免影响历史检索记录与执行详情中的引用。
- 仅改超时 / 凭据不触发切换（已实现）。同一模型重复保存不新建代次（已实现）。
- 需要迁移：代次增加停用时间与“已清理”状态；新增定时清理任务（复用记忆后台工作循环，每小时检查一次）。

### R4 一键修复

- 接口：`POST /api/v1/chats/:chatId/memory/repair`（敏感操作授权、审计）。
- 根据健康状态决定动作：有缺失 → 建只补缺口的补建任务；服务异常 → 测连接后重试该聊天失败任务；需重建 → 启动重建。
- 幂等：同一聊天已有进行中的修复 / 补建任务时直接返回该任务，不重复创建。
- AI 服务的长期检索总览提供“修复全部”，对所有可修复聊天依次执行。

### R5 启用即补建

- 启用聊天时自动建一个只补缺口的全量补建任务；确认框提示消息条数与大致耗时（向量调用量按缺口条数估算）。
- 重新启用之前停用过的聊天时，已有索引直接复用，只补停用期间的缺口。

### R6 自动重试

- 索引失败为上游错误（HTTP 5xx、429、超时、连接失败）时，不再在 3 次后永久停住：转入“等待重试”，按 5 → 15 → 60 分钟退避自动重试，直到成功或 24 小时后停止并标为失败（可一键修复）。
- 非上游错误（数据变化、配置错误）保持现有行为。
- 全局在测试连接成功或任一索引请求成功后，提前唤醒等待中的任务，加快恢复。

### R7 补建只扫未索引消息

- 补建批次直接查询“范围内、未清理、当前代次未索引”的消息，已索引区段不再逐批读取；缺口少时整段聊天几十秒内完成。
- 进度改为以“缺口条数”为分母，避免 45,000 条里补 300 条时进度条长时间停在高位。

### R9 设置页精简

- 主区域保留：启用开关、服务协议、服务地址、模型、凭据、请求超时、测试连接、保存。
- 维度由测试连接返回值自动填写（仍可在高级里手动改）；问题编码前缀、模型版本标识收进“高级设置”。
- 显示全局健康总览：已启用聊天数、正常 / 有缺失 / 异常数量、“修复全部”。

### R10 索引任务页

- 默认只显示补建、重建、失败、等待重试和进行中的任务；“新增消息索引”默认折叠为一行汇总（如“今日 132 条，失败 0”）。
- 任务名称改为面向用户的说法：“补全历史”“归属重建”“新消息”。

## 5. 接口与数据变更

| 项 | 内容 |
| --- | --- |
| 列表接口 | 聊天列表增加 `memoryHealth`：状态、已索引、总数、缺失、进行中任务进度、最近错误摘要 |
| 修复接口 | `POST /api/v1/chats/:chatId/memory/repair`，返回创建或复用的任务 |
| 补建 | 不传时间即为只补缺口的全量补建（行为已在 `1f0f62c` 实现），R7 优化扫描 |
| 启用聊天 | `PUT /api/v1/chats/:chatId/memory` 启用时自动建补建任务（可在响应中返回任务） |
| 代次 | 迁移：`retired_at`、状态增加“已清理”；放弃切换的代次直接清理 |
| 任务 | 迁移：任务状态增加“等待重试”（或复用 queued + 退避时间），记录自动重试次数 |
| 文案 | 界面“授权”统一为“启用”；API 字段名不变 |

## 6. 分阶段

1. **后端基础**：R7 扫描优化、R8 健康状态计算、R4 修复接口、R6 自动重试。上线后即可解决“失败堆积、需逐个重试”的问题。
2. **界面**：R1 列表图标、R2 配置弹窗、R5 启用即补建、R10 任务页、R9 设置页精简。
3. **模型切换**：R3 自动切换与 3 天清理（含迁移），设置页切换进度与放弃切换。
4. **文档与验收**：更新部署与运维、接口契约、验收用例；用虚构数据覆盖缺失修复、上游故障自动恢复、模型切换与清理。

## 7. 已确认决定（2026-11-27）

| 编号 | 决定 |
| --- | --- |
| Q1 | 启用聊天时自动补建全部历史（确认框显示条数） |
| Q2 | 上游错误自动重试 24 小时 |
| Q3 | 旧代次保留天数可配置（默认 3 天） |
| Q4 | 停用聊天只停用，保留索引 |
| Q5 | 切换期间新消息只写入新模型代次；清理期内切回旧模型时旧代次恢复为当前，期间缺口由用户一键修复补齐 |

R3 据此调整：切换期间不再双写；“放弃切换”或在清理期内改回旧模型时，旧代次直接恢复为当前代次，健康状态显示切换期间产生的缺口，由一键修复补齐。
