# BubblePilot 验收与演练

本文固定 Web 异步交互和可靠性演练的有限范围。产品功能是否存在以[产品与范围](产品与范围.md)为准；HTTP 和工作流字段以机器契约为准。

## 严重级别

| 级别 | 判定 | 发布规则 |
| --- | --- | --- |
| P0 | 认证绕过、敏感数据泄漏、重复外部回复、破坏持久化幂等、错误处置未知发送 | 必须立即修复，阻止发布 |
| P1 | 重复提交写操作、显示错误状态、成功后保留失效入口、失败后错误改写本地状态 | 发布候选必须修复 |
| P2 | 不改变业务结果的加载提示、视觉或可访问性增强 | 记录但不阻塞 |

新增问题只有能映射到产品需求、接口契约或下方通用合同时，才能提升为 P0/P1。不要在一次修复中无限扩大 UI 审查范围。

## Web 通用合同

所有 P0/P1 写操作必须满足：

1. 认证、二次验证、版本检查、审计和幂等由服务端执行；前端禁用按钮不是安全边界。
2. 请求开始前清除旧反馈，只锁定会冲突的目标操作。
3. 同一目标的重复点击不能产生并发写请求。
4. 成功优先用接口返回值更新目标；刷新失败不能掩盖已经成功的写入。
5. 业务失败、网络失败、`401` 和 `409` 保留可解释结果，不能错误改写原状态。
6. 取消确认不发请求、不改变状态。
7. 会话或二次授权到期时，正文、搜索结果、导出预览和敏感操作状态立即清理。

读取操作必须避免旧响应覆盖新选择，失败后可恢复，并且不泄露敏感数据。

## Web 停止条件

一次 Web 发布审查在以下条件同时满足时结束：

1. 受影响路径没有未处理 P0/P1；
2. 针对性测试、Web 类型检查、生产构建和仓库质量门禁通过；
3. 受影响页面完成桌面与 390px 移动视口验收，无意外横向溢出；
4. P2 单独记录，不继续扩大当前变更范围。

## 死信与恢复演练

自动化基线：

```bash
pnpm vitest run tests/workflow-application.test.ts tests/reliability-guards.test.ts
```

目标环境步骤：

1. 用虚构测试聊天触发一个明确失败、且没有未知出站的工作流。
2. 在恢复队列记录源执行 ID、状态和错误码。
3. 在正常等待期尝试人工重试，应返回 `EXECUTION_RETRY_STILL_ACTIVE`。
4. 超过 `STALE_RETRY_SECONDS` 后重试，确认新执行通过 `retryOfExecutionId` 关联源执行，且最多产生一次预期回复。
5. 制造回复结果未知场景，确认人工重试被拒绝；核对 BlueBubbles 后人工关闭。
6. 检查 `execution.retry` 和 `execution.close` 审计只包含 ID、结果和关联 ID。

通过标准：重复点击不创建第二个直接恢复子执行；旧等待执行器不能覆盖人工关闭或逾期接管；`unknown` 禁止重发；限流、并发和队列上限返回稳定错误。

## 备份恢复演练

```bash
BACKUP_PATH=$(scripts/backup-postgres.sh)
scripts/verify-postgres-backup.sh "$BACKUP_PATH"
```

通过标准：

- `.dump` 非空且 SHA-256 匹配；
- custom-format 备份可恢复到脚本创建的随机临时数据库；
- `schema_migrations` 和消息、执行、Provider、会话、导出关键表可查询；
- 临时数据库在成功或失败后都被删除；
- 生产数据库名称、大小和连接状态未改变；
- 备份复制到受控异机位置，演练记录不包含数据内容。

## 升级与回滚演练

1. 当前和目标镜像都固定为 `X.Y.Z` 或 `sha-<commit>`，不用 `dev` 或 `latest` 作为回滚锚点。
2. 创建备份并运行：

```bash
scripts/preflight-upgrade.sh "$BACKUP_PATH"
```

3. 启动目标镜像：

```bash
docker compose pull app
docker compose up -d --no-build
scripts/diagnose.sh
```

4. 验证登录、二次授权、聊天监听、虚构测试消息、工作流回复、AI Fallback、执行详情、搜索（若启用）和导出预览。
5. 应用回滚时切回上一精确镜像。数据库不反向迁移；若旧应用不兼容新 Schema，恢复演练备份和对应旧应用版本。
