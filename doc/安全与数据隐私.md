# BubblePilot 安全与数据隐私

## 1. 数据敏感性

BubblePilot 处理的聊天正文、联系人标识、附件元数据、AI 输入输出、工作流配置和执行记录均按敏感数据处理。日志、测试 Fixture、截图和 Issue 中不得出现真实内容。

## 2. 认证与授权

首期采用单实例管理员模型：

- 登录密码用于建立管理会话。
- 敏感操作密码用于查看消息正文和审计事件、修改监听范围、人工重试或关闭死信、导出或删除数据及系统设置等操作；脱敏执行记录的列表和详情登录后即可查看；自动化与 AI Provider 配置仅要求登录。
- 二次验证应有短时效、明确的会话绑定和审计记录。
- 人工重试和人工关闭必须由服务端重新检查执行状态与出站记录；前端按钮禁用不是授权或防重复发送边界。
- 两套密码只以独立 scrypt 哈希注入；服务端会话使用 256 位随机 Token，数据库只保存 SHA-256，Cookie 使用 `HttpOnly`、`SameSite=Strict`，生产环境增加 `Secure`。
- 会话撤销、到期或不存在时，其二次验证授权不可继续使用；登录失败和二次验证失败使用通用错误，不能回显哈希、输入或内部差异。
- 浏览器按服务端返回的绝对到期时间建立一次性刷新边界，并在页面重新可见时复核当前时间。二次授权到期后必须立即清空已加载的消息结果并重新遮蔽正文；管理会话到期后退出管理界面。浏览器计时只用于及时收起界面，服务端校验仍是唯一授权边界。
- 所有服务端管理 API 都必须验证认证状态和操作权限；前端隐藏按钮不构成权限控制。

未来增加多用户时，应把用户、角色、资源范围和审计主体纳入数据模型，而不是在控制器中散落判断。

## 3. Secret 管理

- BlueBubbles URL、访问令牌、登录密码、敏感操作密码和 AI Key 不提交到 Git。
- 环境变量示例只保留占位符，例如 `CHANGE_ME`，不使用真实默认密码。
- Secret 不回显到 API、Web 页面、日志、错误堆栈或执行上下文。
- 怀疑泄漏时立即轮换，并检查历史日志和镜像层。

## 4. 消息保护

- 只有启用监听的聊天才保存正文。
- 搜索、导出和详情接口按授权范围过滤，不允许通过 ID 枚举越权读取。
- 默认对手机号、联系人名称、令牌和消息正文进行日志脱敏。
- 默认在消息归档入库 90 天后清理正文与附件元数据，保留幂等和执行追踪所需元数据；有效导出和仍可恢复的执行会延期清理。清理批次与系统审计在同一数据库事务完成。
- `MESSAGE_RETENTION_DAYS=0` 会关闭自动清理，属于管理员显式接受的无限期保留决策；删除、清理和导出必须审计。
- 备份文件与生产数据库具有相同敏感等级。
- 导出任务按管理会话或 API Token 所有者隔离；会话所有者不能读取其他会话创建的任务，下载时仍要求聊天处于启用监听状态。
- 导出必须先冻结范围预览，再完成服务端二次验证和显式确认；单次仅限一个聊天、最长 31 天、最多 10,000 条且预估不超过 25 MB。
- 导出使用短时 JSON Lines 动态响应，不生成临时正文文件；结果不包含 Secret、`secretRef`、完整 Prompt、原始 Webhook Payload、节点输入输出或内部错误详情。

## 5. AI 安全

- AI Provider 使用服务端 Secret，浏览器不能直接调用 Provider。
- Provider 列表、详情、测试和执行轨迹只返回 Secret 是否已配置或其服务端引用，不返回 Secret 内容。
- 发送给 AI 的上下文按工作流配置限制范围和数量。
- AI 输出不能直接获得管理权限、修改配置或绕过二次验证。
- 回复前执行长度、格式、敏感信息和循环触发检查。
- Provider 超时、限流和错误信息不得泄露 Secret 或完整 Prompt。
- AI Provider Attempt 诊断只记录请求/响应哈希、请求 ID、HTTP 状态、消息/字符/字节计数、`finish_reason`、可见输出/推理字符数和 Token/缓存计数；哈希不可反推出正文，日志与执行详情均不得写入完整 Prompt、聊天正文、AI 输出或原始响应体。
- 诊断中的 `clientRequestId` 使用执行 ID、节点、重试轮次和序号串联调用链；排查问题时应结合执行版本、Provider 版本和供应商请求 ID 定位，不通过复制生产 Prompt 到普通日志重现。
- Provider 排序、启停、路由策略、降级阈值、健康重置和凭据轮换要求登录并审计；消息、审计和系统设置仍需二次验证。
- 连通性测试使用固定虚构内容，不读取归档消息，且不得改变生产健康计数。

## 6. Webhook 与网络

- Webhook 入口验证来源、请求签名或访问令牌，并限制请求大小和处理时间。
- 管理 API 与 Webhook 入口分离权限；Webhook 不得调用管理配置接口。
- 生产环境使用 HTTPS 或受控私有网络。
- 数据库不直接暴露到公网。

## 7. 审计事件

至少审计以下行为：登录失败、二次验证、监听范围变更、工作流发布/停用、Provider 变更、导出预览/确认/下载/撤销、消息删除或自动内容清理、凭据轮换、人工重试和死信关闭。

审计记录包含操作者、时间、目标、结果、关联 ID 和脱敏原因，不保存不必要的消息正文。

## 8. 滥用与容量保护

- 管理 API 与 Webhook 使用独立固定窗口限流，限流键只保存不可逆客户端指纹，不保存 Token、Cookie 或完整 User-Agent。
- 工作流同时执行数、等待队列长度和等待时间均由环境变量设置硬上限；容量不足返回稳定的 `429` 或 `503` 错误，不通过扩大日志内容帮助调试。
- `/api/v1/operations/status` 只返回计数、容量和稳定告警码，不返回消息正文、错误详情、Prompt、Secret 引用值或凭据状态明细。
- 对 `sending`、`unknown` 和 `confirmed` 出站状态禁止人工恢复重发；运维者只能确认外部事实后关闭处理，不能通过数据库改写状态绕过保护。
