# BubblePilot 目标需求

## 1. 文档目的

本文是 BubblePilot 的产品需求基线，定义系统解决的问题、首期范围、核心概念和验收原则。具体架构见[概要设计](概要设计.md)，流程合同见[事件与工作流设计](事件与工作流设计.md)，面向用户的端到端场景见[典型用户交互故事](典型用户交互故事.md)。

## 2. 产品定位

BubblePilot 是面向 BlueBubbles 的自托管消息自动化、归档与 AI Bot 平台。它把 BlueBubbles 的消息事件转换为标准化事件，按配置匹配 Bot 触发器，执行可编排的处理流程，并将结果回复到聊天中。

产品不试图替代 BlueBubbles，也不把每个业务需求实现成一次性代码。核心价值是：

- 用统一消息模型隔离 BlueBubbles 供应商细节；
- 用可复用节点和配置化工作流降低定制成本；
- 保存可搜索、可审计的消息与执行记录；
- 通过 OpenAI 兼容接口接入不同 AI 服务；
- 在单机部署简单的前提下，为未来队列和多节点执行保留边界。

## 3. 目标用户与场景

- 个人用户：监听指定的一对一聊天或群聊，保存消息并进行搜索。
- 自动化维护者：配置关键词、正则、发送者、聊天范围和时间条件，触发 Bot 事件。
- AI 应用维护者：把消息、上下文和配置提示词交给 AI 服务，再将结果回复到原聊天。
- 运维者：通过 Docker Compose 部署、升级、备份和恢复实例。

## 4. 首期范围

### 4.1 消息接入与归档

- 接收 BlueBubbles Webhook 事件。
- 校验来源、记录原始事件摘要，并转换为统一消息信封。
- 仅对配置启用监听的聊天和群聊归档。
- 保存消息唯一标识、聊天标识、发送者、时间、文本、附件元数据和来源事件标识。
- 对重复 Webhook 做幂等处理，不产生重复消息或重复执行。

### 4.2 Bot 事件与工作流

- 支持按聊天、群聊、发送者、文本关键词、正则和消息类型匹配事件。
- 一个事件可以绑定一个已发布的工作流版本。
- 工作流由触发、条件、转换、AI、回复和结束等节点组成。
- 节点通过稳定合同输入和输出，不允许业务控制器写死节点类型分支。
- 工作流执行结果、节点耗时、错误和回复状态可查询。

### 4.3 AI 交互

- 支持管理多个 OpenAI 兼容 AI Provider，配置名称、接口类型、服务地址、模型、参数、单请求超时、启停状态和人工优先级。
- 支持对单个 Provider 进行无副作用的连通性测试，并通过稳定路由配置为 AI 节点选择有序候选列表。
- Provider 路由必须区分单次调用、候选 Fallback 和节点级 Retry；所有候选耗尽后才能按节点策略退避重试。
- 支持按连续超时或可配置故障阈值自动降级 Provider，并在冷却探测成功后恢复；运行时健康状态不得覆盖管理员设置的固定顺序。
- API Key 只在服务端使用，不返回 Web 页面。
- AI 节点明确输入上下文、提示词模板、超时、最大输出和失败策略。
- AI 输出进入后续节点前必须经过长度、格式和安全策略检查。
- 执行轨迹记录实际尝试的 Provider、模型、顺序、耗时、错误类别和降级结果，但不记录 Secret 或不必要的完整 Prompt。

### 4.4 Web 与权限

- 提供登录认证。
- 提供监听聊天配置、消息搜索、事件配置、工作流配置和执行记录查看。
- 查看消息、导出数据、修改监听、激活工作流、修改凭据等敏感操作需要额外密码验证。
- 默认按单实例管理员模型设计，为未来多用户权限保留用户和审计字段。

### 4.5 部署

- 使用 Docker Compose 一键启动应用及其依赖。
- BlueBubbles URL、访问令牌、登录密码、敏感操作密码和 AI Key 均通过环境变量或外部 Secret 注入。
- 提供健康检查、日志、备份和恢复说明。

## 5. 非目标

首期不承诺以下能力：

- 替代 BlueBubbles 的消息同步、联系人或设备管理。
- 任意用户提交并执行服务器端脚本。
- 直接接入所有聊天平台。
- 一开始就拆分微服务或引入 Kafka 等分布式基础设施。
- 对生产消息内容进行无审计的批量删除或导出。
- 把 AI 判断当作权限控制或唯一的业务事实来源。

## 6. 需求编号与验收原则

| 编号 | 需求 | 首期验收重点 |
| --- | --- | --- |
| REQ-MSG-001 | 接收 BlueBubbles 消息事件 | 合法事件能入库，非法来源被拒绝 |
| REQ-MSG-002 | 监听范围配置 | 未启用的聊天不进入业务归档 |
| REQ-MSG-003 | 消息幂等 | 同一外部事件重复发送只产生一条有效记录 |
| REQ-EVT-001 | Bot 事件匹配 | 条件组合可测试、可解释 |
| REQ-FLOW-001 | 工作流编排 | 节点顺序、分支和失败策略可配置 |
| REQ-FLOW-002 | 执行追踪 | 可定位到具体节点、输入摘要和错误 |
| REQ-AI-001 | 多 AI Provider 管理 | 可配置、排序、启停和测试多个 OpenAI 兼容 Provider，Secret 不回显 |
| REQ-AI-002 | AI 回复 | AI 输出经策略校验后才允许发送 |
| REQ-AI-003 | Provider 路由与恢复 | Retry、Fallback、自动降级和恢复有界、可配置、可追踪 |
| REQ-WEB-001 | 消息搜索 | 只能搜索当前授权范围内的聊天 |
| REQ-AUTH-001 | 登录认证 | 未登录不能访问管理 API |
| REQ-AUTH-002 | 敏感操作二次验证 | 二次验证有时效并被审计 |
| REQ-OPS-001 | Compose 部署 | 新实例可按文档启动并完成健康检查 |

## 7. 非功能要求

- **可靠性**：接收、归档、执行和回复均有明确状态；可重试但不能重复回复。
- **可扩展性**：数据源适配器、节点类型、AI Provider 和存储适配器均通过接口扩展。
- **可观测性**：记录关联 ID、执行状态、耗时、重试次数和错误码；默认不记录完整敏感正文。
- **安全性**：密钥不入库、不进日志；消息和执行数据按最小权限访问。
- **可部署性**：默认单机运行；组件边界允许未来将执行器迁移到独立 Worker。
- **可维护性**：配置版本化，已发布工作流不可被静默修改；代码、合同和文档同步演进。

## 8. 产品决策

- 工作流以有向图表达，但首期只实现有限节点类型和有限分支能力。
- 节点配置是数据，不允许通过配置执行任意代码。
- 消息正文、AI 输入和 AI 输出必须区分保存策略，默认只保留业务必需内容。
- 失败回复默认不自动重试无界次数；达到上限后进入可人工处理的失败状态。
