# BubblePilot Web 交互验收矩阵

本文固定 Web 管理端异步交互的有限审查集合、严重级别和停止条件，避免在开发过程中临时扩大验收范围。产品范围仍以[目标需求](目标需求.md)、[典型用户交互故事](典型用户交互故事.md)和[产品路线图](产品路线图.md)为准。

## 1. 审查边界

截至 2026-08-03，`apps/web/src` 中共有 34 个异步函数。按用户可观察行为拆分合并后形成 35 条交互路径：

- 一个函数承载多个独立动作时分别计数，例如 Provider 的测试、启停、重置和删除；
- 拖拽、上下移动和保存顺序等同一交互链路合并计数；
- 页面初始化调用等内部编排与对应刷新操作合并计数；
- 纯同步的表单编辑、展开收起和本地排序不进入本矩阵。

除非需求或接口契约发生变化，后续审查不得在 35 条路径之外临时增加发布阻塞项。

## 2. 严重级别

| 级别 | 判定条件 | 处理规则 |
| --- | --- | --- |
| P0 | 可能绕过认证或二次验证、泄露敏感数据、产生重复外部回复、破坏持久化幂等或错误处置未知发送结果 | 立即修复，阻止发布 |
| P1 | 可能重复提交配置、展示错误对象或状态、在成功后保留失效操作入口，或在失败后错误改写本地状态 | 纳入 Web 发布候选质量门禁；不反向改变 M0-M5 路线图状态 |
| P2 | 只影响读取操作的细粒度加载提示、视觉润色或不改变业务结果的可访问性增强 | 记录但不阻塞当前开发与路线图 |

当前没有未处理的 P0 或 P1；P2 共 5 条且不阻塞。

## 3. 通用验收合同

所有 P0/P1 写操作按同一合同验收：

1. 服务端继续负责认证、二次验证、版本检查、审计和幂等，前端状态不能替代安全边界。
2. 请求开始前清除旧反馈，并只锁定会产生冲突的目标操作。
3. 同一目标的重复点击不能产生并发写请求。
4. 成功时优先使用接口返回值更新目标对象；确需刷新时，不能让刷新失败掩盖已经成功的写操作。
5. 业务失败、网络失败、`401` 和 `409` 均保留可解释结果；失败不得错误改写原状态。
6. 取消确认不得改变状态或发出请求。
7. 会话或二次授权到期时，敏感正文、导出预览和对应操作状态立即清理。

读取操作只要求不泄露敏感数据、不把旧请求结果覆盖到新选择上，并提供可恢复错误。P2 加载动效不单独触发发布阻塞。

## 5. 固定处理顺序

P1 只按以下页面批次处理，不再拆成无限的独立审查任务：

1. 已完成 AI 管理 5 条 P1：`WEB-AI-002`、`WEB-AI-007` 至 `WEB-AI-010`。
2. 已完成工作流与触发器 7 条 P1：`WEB-FLOW-002` 至 `WEB-FLOW-006`、`WEB-TRIGGER-002`、`WEB-TRIGGER-003`。
3. 已完成消息与导出 5 条 P1：`WEB-MSG-002`、`WEB-EXP-002` 至 `WEB-EXP-005`。
4. 已完成执行详情 1 条 P1：`WEB-EXEC-002`。

每个页面批次统一检查成功、业务失败、请求失败、重复操作和状态一致性；桌面与移动端各做一次页面级视觉验收。

## 6. 停止条件

Web 交互审查在以下条件同时满足时结束：

1. 本矩阵没有未处理 P0 或 P1；
2. 针对性检查、Web 类型检查、生产构建和仓库完整质量门禁通过；
3. 每个页面批次完成一次桌面与移动端验收；
4. 未完成 P2 保留在本矩阵，但不继续扩大当前开发范围；
5. 新问题只有在能映射到权威需求、接口契约或本矩阵通用合同时，才允许提升为 P0/P1。

M5 的 PostgreSQL 备份恢复和镜像升级回滚仍按[可靠性演练记录](可靠性演练记录.md)独立封板，不能由 Web 交互检查替代。
