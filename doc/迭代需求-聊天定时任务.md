# 迭代需求：聊天定时任务

本文覆盖单次提醒及其周期扩展；具体 API 以[接口与配置契约](接口与配置契约.md)和 OpenAPI 为准。代码交付不代表已部署，真实模型对自然语言时间的理解需另行验收。

## 改造点清单

1. 统一任务定义、计划实例、执行记录三层存储，迁移已有单次任务。
2. 增加日历与固定间隔计算、结束条件、未来时间预览。
3. 扩展原任务工具，支持周期创建、修改、暂停、恢复、跳过下一次和取消。
4. 调度器按实例领取与恢复，压缩停机错过的周期，保留发送幂等边界。
5. 管理页沿用弹窗编辑，展示规则、状态、已消费次数和实例历史。
6. 回归旧任务、数据库迁移、权限、时区、并发及备份恢复；不自动部署。

## 目标与边界

用户在原聊天向角色明确委托提醒，应用持久化任务，到期使用原工作流和届时上下文重新请求模型生成提醒。创建时的确认文案不会直接重放。

单次与周期任务共用聊天、工作流、创建成员归属和执行链，不建立两套业务。任务只能向原聊天发送；一个聊天只能绑定一个启用提醒的工作流。默认不开启，已有工作流行为保持不变。

支持每天、每周指定星期、每月指定日期／月末及固定分钟间隔。不支持 Cron、法定节假日、跨聊天群发、无人回应连续催促、单独改期某一次、自动购买、脚本或其他外部操作。工作日指周一至周五。

## 配置模型

| 层次 | 字段和职责 |
| --- | --- |
| 公共定义 | content（1～2000 字符）、timeZone（IANA）、聊天／工作流／创建成员、version |
| 单次 schedule | kind=once、scheduledAt（含偏移的绝对时间） |
| 周期 schedule | kind=recurring、startsAt、rule、end |
| daily | localTime，HH:mm |
| weekly | weekdays（1～7，周一至周日，去重）、localTime |
| monthly | dayOfMonth（1～31 或 last）、localTime |
| interval | everyMinutes（60～525600），锚定 startsAt |
| end | never；until（截止时刻不包含）；count（1～10000 个计划次数） |

创建或修改周期规则须提供未来且一年内的生效起点；循环本身可持续一年以上。单次也须在未来一年内。输入的偏移必须与声明时区对应。修改提交完整 schedule，任务类型不可变；旧 scheduledAt 写法仅用于单次。

日历按当地时区计算，缺失日期及夏令时不存在的时刻跳过，秋季重复时刻取第一次，仅产生一次提醒。固定间隔按绝对时间推进，不随夏令时漂移。

count 统计受理、失败、过期、手动跳过；不以成功送达计数。暂停期间不消费。规则修改保留已消费次数，不能设置低于已消费的次数；设置为相同次数则结束后续周期。编辑前预览最多三个未来时刻，预览不创建任务，不调用模型。

## 存储与生命周期

- `scheduled_tasks`：唯一任务定义，schedule、lifecycle、当前 scheduled_at、consumed_count、version。active／paused／completed／cancelled 表示整体生命周期，保留 status 兼容旧接口。
- `scheduled_task_occurrences`：每个实际安排的实例，保存任务版本、计划时间、必要快照、结果。唯一 task_id＋occurrence_number；同一任务最多一个 pending／running 实例。
- `scheduled_task_runs`：实例执行与租约，一实例对应一个逻辑执行；恢复不创建新执行。
- `scheduled_task_events`：只追加变更、受理、结果及错过周期的区间／数量。
- `scheduled_task_operations`：成员工具变更幂等结果，防止相同工具调用重复跳过或消费。

不会预生成无限实例。错过的大量周期压缩成区间审计，不逐条建执行；每批最多处理 512 个时间槽，后续扫描继续推进。实例序号不等于已消费总数。

暂停／取消使未提交发送的旧执行失效。恢复只安排恢复时刻之后的周期，不补暂停期间的提醒。暂停任务仍占活动任务额度，防止通过暂停绕过上限。单次不支持暂停、恢复或跳过。

已经提交网关的发送不能撤回。周期任务此时允许暂停／取消未来周期，返回 sendingAlreadyStarted=true；本次结果仍归原实例。单次维持原有发送后拒绝修改／取消的规则。

## 调度与模型执行

每 10 秒轮询 PostgreSQL，复用进程内队列及聊天串行门控，不新增 Redis 或容器。队列拒绝不消费次数；任务行锁、实例唯一约束和租约代次防止并发重复受理。同一任务不重叠运行。

停机恢复只尝试最近且仍在补发窗口内的一次，较旧周期消费并记录错过；超出窗口不调用模型。补发配置 0 保持既有一分钟正常调度容差。结果未知不重发该实例，不阻止后续独立周期。

实例受理时固定工作流版本、任务内容、历史边界和上下文快照。新版 `scheduled-task-v2` 增加 occurrenceId／occurrenceNumber；旧 v1 执行原样恢复，保留原事件键与执行 ID。

到期不是新用户消息，不伪造正文或消息归档，不移动普通消息窗口。模型只生成提醒文字，失败使用任务内容兜底；不开放写任务、表情、搜索、插件或附件导入。定时委托不构成执行外部行动的授权。

有效工作流重新发布后，待执行实例使用新版本；旧版本未提交的运行停止，该周期记录取消，后续周期继续。关闭聊天、工作流或提醒配置会撤销整项任务，重新启用不会复活。

## 工具与管理端

仅可确认的真人当前消息可调用任务工具，成员只能读写自己在当前聊天、工作流中的任务。历史、网页、空闲事件、到期事件及身份不明消息不能创建任务。

保留 create/list/update/cancel_scheduled_task，新增 pause/resume/skip_next_scheduled_task。修改均要求 expectedVersion；结果完整可容纳且事务提交后才能确认成功。歧义应追问，不猜测时间、任务 ID 或版本。

管理端“定时任务”沿用工作流、聊天、状态筛选。列表显示规则摘要和消费次数，弹窗编辑规则并预览；详情分页显示实例与执行关联。编辑、取消、暂停、恢复、跳过和原始请求详情需要敏感解锁并审计。浏览列表及只读规则预览需要管理员登录。

## 持久化与恢复

迁移 0063 将旧任务变为 once，回填实例并关联历史 runs，不重写历史 event 或 execution。数据库仍是权威来源，不增加挂载目录和环境变量。

升级前停止写入并备份完整数据库；恢复时维持 restore guard 机制自动暂停。管理员检查后恢复，跳过暂停区间。旧镜像不能直接使用新结构，回滚须恢复配套数据库。

必要任务正文保留至任务结束后的既有清理期限；实例、运行和变更正文分别按自身完成／创建时间 90 天清理，长期活跃周期不会永久保留旧正文。普通日志只记录元数据。

## 验收

- 单次旧字段、旧任务迁移、v1 恢复，事件键与出站幂等不变。
- 日／周／月／月末、固定间隔、截止和次数；跨月、闰年、夏令时跳跃／重复。
- 群聊成员隔离、跨聊天／工作流越权、配置撤销、敏感解锁和并发版本冲突。
- 重复工具调用、队列拒绝、并发调度、进程中断、暂停恢复、全局暂停、停机积压。
- 未提交发送的取消与迟到结果；已提交发送的暂停／取消未来周期；失败／未知不重复投递。
- 管理弹窗、失效预览、移动布局、实例分页和历史内容清理。
- `pnpm verify`、依赖安全检查、Compose 校验、独立 PostgreSQL 迁移及恢复演练。

自动化只使用虚构数据及模拟模型；真实聊天创建、周期送达、自然语言理解和角色质量另行验收。本轮不发布镜像、不更新 NAS、不启用生产聊天。
