# BubblePilot 接口与配置契约

## 权威来源

本文解释接口边界，不重复抄写每个请求字段。机器可校验合同是：

| 文件                                                                                        | 权威内容                          |
| ------------------------------------------------------------------------------------------- | --------------------------------- |
| [`contracts/openapi.yaml`](../contracts/openapi.yaml)                                       | HTTP 路径、认证、参数、请求和响应 |
| [`contracts/bluebubbles-webhook.schema.json`](../contracts/bluebubbles-webhook.schema.json) | BlueBubbles 原始 Webhook          |
| [`contracts/message-envelope.schema.json`](../contracts/message-envelope.schema.json)       | 统一消息信封                      |
| [`contracts/workflow.schema.json`](../contracts/workflow.schema.json)                       | 可发布工作流图                    |

`GET /api/v1/workflows/schema` 另外提供面向 AI 和跨实例传输的 `BubblePilotWorkflow bubblepilot.io/v1` 清单 Schema；它包装运行时工作流图并用逻辑 Binding 隔离实例资源。运行时 Zod/图语义校验仍是最终发布权威，合同测试负责防止公开 Schema、节点注册表和运行时实现漂移。

运行时路由、OpenAPI、环境变量和 Schema 由 `pnpm contracts:check` 交叉检查。

## API 分区与认证

| 分区                    | 入口示例                                                                                                                                             | 认证                                                            |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 健康检查                | `/health/live`、`/health/ready`                                                                                                                      | 无                                                              |
| Web 登录                | `/api/v1/auth/session`、`/api/v1/auth/sensitive`                                                                                                     | 登录密码或当前管理会话                                          |
| BlueBubbles Webhook     | `/api/v1/webhooks/bluebubbles`                                                                                                                       | 查询参数 Token 或 `X-BubblePilot-Webhook-Secret`                |
| 消息与监听              | `/api/v1/chats`、`/api/v1/chats/{chatId}/participants`、`/api/v1/messages/search`、`/api/v1/chat-monitoring` | 管理会话或 Bearer；正文、索引重建和监听变更需二次验证，成员映射无需二次验证 |
| 工作流与触发器          | `/api/v1/workflows`、`/api/v1/triggers`                                                                                                              | 管理会话或 Bearer                                               |
| AI Provider、路由与工具 | `/api/v1/ai/providers`、`/api/v1/ai/routes`、`/api/v1/ai/usage`、`/api/v1/ai/search/settings`、`/api/v1/ai/image-input/settings`                     | 管理会话或 Bearer                                               |
| 执行与运行状态          | `/api/v1/executions`、`/api/v1/operations/status`                                                                                                    | 管理会话或 Bearer；人工恢复需二次验证                           |
| 审计与导出              | `/api/v1/audit-events`、`/api/v1/exports`                                                                                                            | 管理会话或 Bearer；敏感读取、确认和下载需二次验证               |
| BlueBubbles 设置        | `/api/v1/integrations/bluebubbles`                                                                                                                   | 查询需登录，修改和测试需二次验证                                |

浏览器使用服务端管理会话。Cookie 为 `HttpOnly`、`SameSite=Strict`，`SESSION_COOKIE_SECURE=auto` 时按 HTTPS/反向代理协议决定 `Secure`；数据库只保存随机会话 Token 的 SHA-256。二次授权绑定当前会话并短时有效，前端到期收起内容不能替代服务端逐请求校验。

`API_ACCESS_TOKEN` 是兼容受控自动化的高熵 Bearer Token，视为已经具备实例管理权限，应像管理员凭据一样保护。新用户操作优先使用 Web 会话，不把 Bearer Token 暴露给浏览器脚本或不可信客户端。

分页列表使用不透明 `cursor` 和 `limit`，`limit` 为 1-100。错误响应包含稳定 `code`、可读 `message` 和 UUID `correlationId`。调用方不得解析错误文案决定重试。

管理 API 与 Webhook 分别限流，超过上限返回 `429 RATE_LIMITED`。执行容量不足返回 `503 WORKFLOW_QUEUE_FULL` 或 `503 WORKFLOW_QUEUE_WAIT_TIMEOUT`；只能退避重试，不能通过并发重放绕过上限。同一工作流与聊天的后续消息属于有序串行工作，不使用容量等待超时丢弃，但仍计入有界队列容量。

## Webhook 合同

- URL：`/api/v1/webhooks/bluebubbles?token=<secret>`；Secret 至少 32 字符并使用常量时间比较。
- 当前处理 `new-message`；其他合法事件以 `ignored` 进入幂等事件表。
- 稳定事件键为 `new-message:<message-guid>`。
- 成功返回 `202`，接入状态为 `archived`、`ignored` 或 `duplicate`。
- `automationOutcome` 区分 `unsupported-event`、`chat-not-monitored`、`evaluation-pending`、`not-evaluated`、`no-active-triggers`、`no-trigger-match` 和 `matched`。
- 只有 `evaluation-pending` 允许同键重投继续调度；其他最终判定不按当前配置补跑。
- 未监听聊天只保存发现所需元数据，不保存正文。
- 入站事件查询不返回消息正文、原始 Webhook、Payload 哈希、Prompt 或凭据。

详细字段映射和供应商行为见 [BlueBubbles 集成说明](BlueBubbles集成说明.md)。

统一消息信封当前为 `schemaVersion=3`，必填 `message.linkPreview`。状态为 `not-requested|pending|available|unavailable|failed|redacted`，最多保存 4 条规范化预览；单条只包含来源、HTTP(S) URL、有限标题/摘要/站点名、图片/图标存在标志，以及可用时的公开卡片主图 URL 和来源。原始 BlueBubbles `payloadData`、网页 HTML 和媒体二进制不进入该合同。

`GET/PUT /api/v1/integrations/bluebubbles` 除连接与发送配置外，还返回或更新 `linkPreviewEnabled`、`openGraphFallbackEnabled` 和 `openGraphTimeoutMs`（1000-15000 毫秒）。它们保存在 `bluebubbles_settings`，修改仍需要二次验证和乐观版本。消息列表返回规范化 `linkPreview`、有限 `linkPreviewDiagnostics` 和 `linkPreviewFetchedAt`，便于排障；诊断不包含 URL、网页正文、聊天正文、凭据或原始响应。

聊天列表（`GET /api/v1/chats`、`GET /api/v1/chat-monitoring`）及监听更新结果包含 `memoryAuthorized`，直接读取 `memory_chats.enabled`，无授权记录时为 false。此字段独立于监听、全局记忆开关和索引完成状态；聊天列表展示“长期记忆授权”，通过对应聊天的长期记忆配置弹窗修改授权后同步更新。

## 对话成员身份合同

`GET /api/v1/chats/{chatId}/participants` 聚合该聊天历史中实际出现的非本人 sender ID，返回消息数量、最后出现时间、本名、昵称和独立映射版本。`PUT` 使用 `expectedVersion` 全量替换映射；最多 100 项，同一 sender ID 不能重复，本名或昵称至少填写一项，空数组用于清除全部映射。提交不在该聊天历史中的 ID 返回 `CHAT_PARTICIPANT_NOT_DISCOVERED`，版本过期返回 `CHAT_PARTICIPANT_IDENTITIES_CONFLICT`。

BlueBubbles direct 聊天的管理端显示名称按“本名 → 昵称 → 原始号码（或邮箱）”选择，空白视为未配置。只用该聊天 ID 与私聊 GUID 中的对端原始标识精确匹配成员映射，不跨聊天查找、不取第一位成员、不归一化号码猜测身份。无法解析对端时保留网关名称／聊天 ID 兜底。群聊及其他来源名称不变。此规则应用于聊天监听与选择器、消息搜索、执行列表／详情、历史索引、定时任务和空闲交流管理展示；映射保存后当前聊天列表自动刷新。读取时计算，不修改 chats.display_name、不改变消息信封、历史执行快照或已生成导出；无需迁移与回填。

两个接口需要管理员身份，无需二次验证，并写入 `chat.participants.view` 或 `chat.participants.update` 审计。审计只保存动作、聊天 ID、结果和 HTTP 状态，不保存本名、昵称或请求正文。映射按聊天隔离；运行时读取当前聊天全部已配置成员映射，不受历史窗口限制，不读取其他聊天映射；不为未配置成员推断姓名。完整映射计入请求预算，硬上限拒绝不静默截断。

## 聊天软删除

`DELETE /api/v1/chats/{chatId}?expectedVersion=<version>` 软删除一个已停用监听的聊天。只有 `enabled=false` 的聊天可删除；已启用返回 `409 CHAT_STILL_ENABLED`，版本过期返回 `409 CHAT_DELETE_CONFLICT`，不存在或已删除返回 `404 CHAT_NOT_FOUND`。删除只写入 `deleted_at`，聊天行、消息、执行、导出和成员映射保持不变，历史引用仍能显示聊天名称；`/api/v1/chat-monitoring` 和 `/api/v1/chats` 不再返回已删除聊天。已删除聊天重新收到消息会清除删除标记，恢复同一聊天记录（ID、名称、历史保持不变），但仍保持停用状态且不自动归档正文，管理员可重新启用。删除需二次验证并写入 `chat.delete` 审计。

## 工作流与 AI 合同

已发布工作流版本不可原地修改。编辑会创建新的已校验候选版本；发布和切换在事务中完成，已开始执行继续引用原版本。直接创建／编辑触发器的接口只接受 `includeFromMe=false`；画布节点可配置 `true`，普通匹配按配置处理本人消息，新增引用入口始终拒绝本人消息。冲突提示只表示潜在重叠，不阻止启用。

引用本工作流的已确认 Bot 消息时，默认放宽文本匹配，其余条件不变，关键词、前缀和正则均适用。`POST /api/v1/triggers/preview` 的虚构样本可选 `replyTarget=none|same-workflow|other-workflow|participant|unknown`；提供该字段时结果可含 `matchSource=ordinary|reply|null`，仅做条件判断，不查询真实消息或产生执行。`GET /api/v1/inbound-events` 对已评估引用可选返回脱敏 `replyWake.status` 和 `decision`；执行详情可选 `messageMatchSource=ordinary|reply|null`，旧记录为未知。两者不返回引用正文或其他聊天信息。省略新字段的旧预览请求保持原响应语义。

工作流创建、编辑、发布、启停、删除、导入导出及触发器管理均需管理员身份，不要求敏感密码；包括开启空闲主动交流、定时提醒及实例绑定导出。写操作和导出记录审计，发布仍校验节点、目标聊天监听授权和能力绑定。画布启用主动发言时保留目标聊天确认。定时任务详情与管理、插件连接和聊天正文等其他模块的敏感验证不变。

管理端共用表单弹窗的 `sensitiveRequired` 必须由调用处显式声明，没有默认值。Provider、路由和成员映射弹窗不展示敏感密码表单；插件管理、历史补建、定时任务设置及删除任务保留敏感解锁入口。该属性仅控制界面提示，不能替代服务端授权，也不改变现有接口权限；Provider 和路由仍为管理员认证加变更审计。新增弹窗遗漏声明应由 Web 类型检查阻断。

### AI Friendly 清单与导入导出

工作流列表可复制 JSON Schema、AI 编写指南、Binding Catalog 和标准提示词，也可上传或粘贴 `*.bubblepilot-workflow.json`。清单的 `spec` 只描述图逻辑，`bindings` 以 `providerRouteRef` 和 `chatRefs` 描述外部依赖；摘要 Provider 由全局 AI 设置管理，不进入工作流绑定；不得包含 Secret、执行记录或消息正文。

`GET /api/v1/workflows/{workflowId}/versions/{version}/export` 默认生成 portable 清单并移除 AI Route 与 Chat 实例 ID；`mode=instance-bound` 保留绑定 ID 用于同实例备份，两种模式均只需管理员认证，不导出凭据并记录审计。`GET /api/v1/workflows/binding-catalog` 只返回逻辑名称、资源 ID 和已验证能力，不返回 Provider 地址或 Secret。

自动化列表导出与画布默认打开使用同一版本规则：优先已发布版本，其次最新 validated 候选，最后最新存储版本；画布显式指定版本时导出该版本。画布有未保存修改、正在保存或保存失败时，先保存再导出，不能静默导出旧数据。数据连线存储在节点 `inputs` 的 `kind=output` 引用中，而非独立的 `edges` 数组；导出、导入和画布恢复保留该引用、控制流与节点位置，修改名称或提示词不改变引用。已丢失引用的旧文件无法凭空还原，应从正确的原工作流版本重新导出。

导入固定分两步：`POST /api/v1/workflows/import/preview` 执行结构、图语义、模板与能力绑定校验，错误使用 RFC 6901 JSON Pointer，并签发五分钟令牌；`POST /api/v1/workflows/import` 重传 Manifest、最终绑定和令牌，服务端再次校验资源快照。提交支持 `create` 或带 `targetWorkflowId` 的 `new-version`，始终只创建 `validated` 候选版本，不自动发布或启用。预览和提交仅要求管理员登录，提交不要求敏感操作二次验证，仍写审计，日志和审计只保存结果与哈希，不保存 Manifest 正文。

动作目录只返回具备运行时实现的节点。`load-context@1` 提供 messages、count 和当前聊天全部已配置的 participants，读取双窗口内且严格早于触发消息的原文。字符保护只约束历史提取，不约束整个 AI 请求。`render-text@1` 使用允许的 Context Token 提供 text；未知路径、未知动作输出和不完整模板在候选版本校验时拒绝。`set-variable@1` 已移除，导入及版本校验拒绝该节点；`schema/guide` 保留 `deprecatedNodes` 字段并返回空数组。

AI Provider 的 `reasoningEffort` 可设为 `default|none|minimal|low|medium|high|xhigh|max`。`default` 不发送协议字段；其他值在 Responses 中映射为 `reasoning.effort`，在 Chat Completions 中映射为 `reasoning_effort`。可用等级取决于具体模型和兼容网关。该默认值适用于普通请求、Agent 工具轮次、Retry 和能力探测。图片能力探测使用全局图片输入配置的细节等级，与真实图片请求保持一致；无法读取配置时回退为 `high`，不再固定使用 `low`。

AI Provider 支持 Chat Completions 或 Responses 接口类型、Base URL、模型、参数、超时、启停、排序、Function Calling、托管搜索、原生图片输入、会话亲和、工具参数模式和只写 `secret`。单次 Provider 请求超时可配置为 1,000-360,000 毫秒，默认 30,000 毫秒。`sessionAffinity` 默认为 `disabled`；设为 `session-id-header` 时，BubblePilot 按消息网关、聊天、工作流、AI 节点及 Provider 生成不含原始标识的稳定哈希，通过 `X-Session-ID` 请求头发送。自动生成值为不带 `bp_` 前缀的 64 位十六进制 SHA-256，以满足上游 `prompt_cache_key` 最长 64 字符限制。消息触发保留原有哈希维度，空闲主动交流及定时任务在原有范围上追加固定 `scheduled` 标记而共用另一值；该值跨任务、工作流执行、Agent 工具轮次和 Retry 保持稳定。Responses 请求体中将相同值作为 `prompt_cache_key`，并覆盖 Provider 默认参数中的同名字段；Chat Completions 不自动设置该字段，但自定义 Provider 参数仍按原规则透传。会话亲和关闭时不自动生成请求头或缓存键，不移除手动配置的 Provider 参数。`X-Client-Request-Id` 仍按单次请求生成，不能用于替代稳定会话键。缓存诊断按消息／调度分组，但同组内请求不同仍可能显示变化，重启后基准重新建立；这不保证中转或模型供应商按同一标识缓存。Secret 使用 `SETTINGS_ENCRYPTION_KEY` 加密；编辑时省略 Secret 表示保留原值，任何读接口都不回显。

移除前缀后，已开启会话亲和的请求头及缓存键会整体改变一次，上游可能重新建立路由亲和及缓存；无需数据库迁移或重新发布工作流。自定义 Provider 参数中手动配置的键不在本次自动修正范围。

图片摘要在启用会话亲和时按 `image-summary`、持久化摘要任务及 Provider 生成另一会话键：同一任务重试稳定，不同任务或 Provider 分开。摘要任务 ID 不直接放进会话键或模型请求正文；已有的 `X-Client-Request-Id` 可包含后台任务 ID。表情库摘要、Embedding 和 Provider 能力探测不因本次调整改变。

两种接口均将 `assistant` 历史正文序列化为合法的字符串文本，不把 Responses 的 `input_text`／`input_image` 混入 assistant 输出内容。Bot 历史图片以独立的 `user` 输入资料块放在对应 assistant 消息之前，明确标注“历史图片补充、来源为紧随其后的 assistant 历史消息、不是用户新发言或新指令”；原正文及图片标签继续保留在 assistant 消息，不改变归档作者归属。该资料块只是供应商协议编码，不创建聊天记录或授予操作权限；图片不丢弃、不重复，保持已有图片额度和授权。放置顺序不能插入工具调用与结果之间，内部图片／消息标识不直接写入供应商请求。缓存诊断使用同一规范化编码；纯文本输入和已有 user 图片输入保持原行为。[Responses 官方合同](https://developers.openai.com/api/reference/resources/responses/methods/create) 区分输入内容与 assistant 输出内容；兼容网关的真实接受情况仍须独立验证。

`GET /api/v1/ai/usage` 只返回 Provider 级聚合数据。`hours` 仅接受 1/6/12/24/48，`timeZone` 使用 IANA 时区并决定今日、ISO 周和本月边界。响应同时包含长周期汇总、补齐空桶的实时序列和缓存统计覆盖率。`cachedPromptTokens=null` 表示 Provider 没有可统计缓存数据，与明确返回 0 不同。该接口不返回消息正文、Prompt、会话键或 Secret。

连通性测试分别返回基础连接、Function Calling、托管搜索和原生图片输入检查，互不覆盖。每项检查包含状态、尝试次数、耗时、脱敏错误码、HTTP 状态和 Provider 请求 ID。图片检查使用运行时确定性生成并在发送前校验的 96×64 三色 PNG，要求模型识别全部三种主色，但不把颜色顺序当作协议能力条件；探测资源无效时以 `AI_IMAGE_PROBE_ASSET_INVALID` 立即失败且不请求 Provider，超时、连接、限流或服务端错误最多重试一次。若 HTTP 请求成功但识别结果不匹配，测试结果会返回最多 160 字符的固定探测回复预览；该预览不涉及归档消息、用户图片或用户对话。测试不读取归档消息、不触发生产 Fallback，也不计入生产降级。

Function Calling 探测保留 Provider 的思考及工具参数模式配置，首轮使用 `tool_choice=auto` 和最多 1,024 输出 Token。每次管理测试生成独立 UUID，并写入连接、工具、搜索、图片各阶段的提示词，避免固定提示词被上游当作旧请求；每次模型请求带独立 `X-Client-Request-Id`。会话亲和开启时，各阶段使用独立的 64 位哈希测试会话，同一次工具探测的两轮保持相同会话；关闭时不自动发送会话 ID，不改动聊天的会话键。

工具探测要求一次无副作用的 `capability_probe` 调用，`acknowledgement=bubblepilot-probe`，未使用的可选 `note` 在严格模式传 null、兼容模式省略。首轮只有单个真实工具调用、非空 ID、正确函数名和精确参数结构才进入第二轮；无调用返回 `unknown` + `AI_FUNCTION_PROBE_NOT_OBSERVED`，结构错误返回 `failed` + `AI_FUNCTION_PROBE_MISMATCH`。第二轮保留原始 assistant 调用和 call ID，回传包含新生成随机回执的模拟工具结果，不再提供工具；只有模型无新工具调用且准确返回回执才记为 `verified`。回执只出现在工具结果中，普通 OK 或正文声称成功不算闭环通过。第二轮不匹配返回 `AI_FUNCTION_PROBE_ROUNDTRIP_MISMATCH`；HTTP 错误及超时保留原错误码，不自动重试、不无限循环、不执行任何业务工具。工具检查的 attempts 为实际模型请求数（正常闭环 2），durationMs 计两轮总和。

未验证或失败的 Provider 不能进入工具路由；升级不自动改写以前的探测状态，管理员需重新测试。管理页区分“测试通过”和“连接正常，但部分能力未通过”；接口 success 仍保持基础连接成功的既有含义。

AI 节点联网开关继续以 `webSearch=disabled|auto` 存储，缺省关闭；兼容接受旧 `required`，其含义等同 `auto`，不再发送强制搜索指令。工作流导入导出保持旧字段兼容，已发布版本无需重建。托管搜索同样使用自动工具选择。

`GET/PUT /api/v1/ai/search/settings` 读取和更新实例级联网搜索参数。参数包括 HTTP 尝试次数、单次请求超时、重试退避、最大结果数和失败策略；PUT 必须携带 `expectedVersion` 防止旧页面覆盖新配置。未保存时 GET 返回系统默认值和 `version=0`，首次保存后以数据库配置为准，并对新的 Agent 执行立即生效。工作流节点不保存这些参数，也不存在独立的工具总时间预算。

`GET/PUT /api/v1/ai/image-input/settings` 管理所有 AI 节点共享的原生图片输入。配置包括总开关、附件和链接卡片主图来源、当前/历史/总图片数量、单图/总字节、获取超时和 Provider 图片细节等级；PUT 使用 `expectedVersion`。`trustedLinkPreviewHosts` 已迁移为共享外部网络配置的只读兼容别名，域名在 `/api/v1/settings/network` 维护，用于允许部署代理的 `198.18.0.0/15` Fake-IP，不能豁免其他私网地址。系统默认关闭，启用后无需修改工作流节点。图片只在请求期间转为 Data URL，不持久化原图或 Base64。图片摘要没有节点级或新增全局配置：新图片自动创建后台任务，未命中有效内容复用时，仅在存在已验证视觉 Provider 时调用模型生成。

路由响应同时区分：

- `configuredProviderIds`：管理员保存的固定顺序；
- `effectiveProviderIds`：当前运行时可选择的候选；
- `unavailableProviderIds`：停用、缺少 Secret 或仍在冷却的候选。

执行列表返回匹配聊天的显示名称和 Provider Chat ID，并按单次执行聚合 `ai-chat` 节点所有可统计 Provider Attempt 的缓存命中输入 Token、可统计输入 Token 与命中率；Retry、Fallback 和 Agent 多轮均计入，图片摘要等辅助 AI 请求不计入。Provider 总用量仍包含 `purpose=image-summary` 的真实请求。没有可统计的对话回复请求或 Provider 未返回缓存统计时命中率为 `null`。执行详情返回每条脱敏节点、Provider Attempt、工具调用、图片输入和出站轨迹；图片摘要不在执行详情展示。消息搜索的敏感“图片与 AI 摘要”弹窗通过 `/api/v1/messages/{messageId}/media` 返回摘要状态和有限诊断，并通过受保护的 `/api/v1/messages/{messageId}/image` 代理原图。图片摘要诊断只包含来源、状态、稳定引用、Hash、Provider、模型、尝试次数、耗时和错误码；其他图片轨迹不包含附件 GUID、完整图片 URL、原图或 Base64。其他轨迹可以包含实际搜索词、规范化有限结果、请求 ID、HTTP 状态、哈希、大小和 Token 计数，但不得包含完整 Prompt、聊天正文、AI 输出、Secret 或原始外部响应。

图片媒体接口 `/api/v1/messages/{messageId}/media` 在每个 item 增加 `resultOrigin: model|cache|legacy|null`、`reusedAt: string|null`（ISO 时间）和 `providerAttemptCount: number`。未成功任务的来源为 null；旧成功记录为 legacy；model 表示本任务生成，cache 表示同聊天内容复用。`generatedAt` 始终为原摘要生成时间，缓存条目的 Provider／模型也是原摘要来源，`durationMs` 是本任务处理耗时。`attemptCount` 表示任务尝试，内容租约竞争等待不占次数；`providerAttemptCount` 按当前任务实际 Provider Attempt 记录计数，包含失败／重试／Fallback，首次缓存命中为 0，不能用任务尝试数代替。路由轨迹只显示当前任务已有的真实调用过程，不复制缓存来源任务的轨迹。Web 弹窗分别标记模型生成、缓存复用和历史记录，显示任务尝试、模型调用及生成／复用时间。敏感认证、审计要求不变，不返回复用来源消息标识。

内容复用无需新开关或环境变量：下载校验成功后，以同聊天、内容 Hash、完整生成策略指纹匹配仍有效的成功摘要；只复用 0076 上线后的新策略结果。命中不调用 Provider，未命中沿用现有视觉路由和失败重试；链接封面与收发双方归档图片的自动摘要规则不变。不能依据 URL、附件标识或旧指纹为空的记录直接跳过下载校验。

列表和详情接口的 `providerAttempts` 按实际调用顺序返回完整 AI 调用路径，包含同一 Provider 重试和跨 Provider fallback；新增的 `routeTraces` 固定执行时的路由名称、ID、版本、请求是否带图、候选顺序及过滤或跳过原因，并明确区分原生图片调用和纯文本降级。执行详情及敏感图片摘要诊断使用同一数据合同；迁移前的历史记录返回空数组，不根据当前配置反推。

完整执行语义见[事件与工作流设计](事件与工作流设计.md)。

## 受控导出

导出使用“冻结预览 → 二次验证 → 显式确认 → 短时下载”：

1. 单个任务只允许一个当前监听聊天、明确时间范围，以及消息或执行摘要中的至少一种。
2. 时间最长 31 天，最多 10,000 条，预计不超过 25 MB；预览 5 分钟有效。
3. 确认必须回传预览的 `expectedRecordCount` 和 `expectedSnapshotAt`。
4. 确认后下载窗口 10 分钟；服务端按冻结快照流式生成 JSON Lines，不写临时正文文件。
5. 任务按当前管理会话或 Bearer 所有者隔离，下载时再次检查监听状态和有效期。

第一行为 `manifest`，之后为 `message` 或 `execution`。导出不包含 AI Key、Secret、`secretRef`、完整 Prompt、节点输入输出、原始 Webhook 或内部错误详情。预览、确认、下载和取消分别审计。

消息中的 `contentRedactedAt` 区分“原本没有正文”和“已按保留策略清理”；清理后 `body=null`、`attachments=[]`、链接预览状态为 `redacted` 且条目清空，必要元数据与执行关联仍可查询。消息导出包含同一规范化预览，不包含原始卡片或网页内容。

主要状态错误包括 `MEMORY_VERSION_CONFLICT`、`MEMORY_DISABLED`、`MEMORY_DATABASE_NOT_READY`、`MEMORY_COVERAGE_INCOMPLETE`、`MEMORY_SOURCE_UNAVAILABLE`。Embedding 服务异常不会把原始服务响应写入错误或日志；只提取标识形态的上游请求 ID（响应头 `x-request-id`／`x-oneapi-request-id`／`request-id` 或错误消息中的 `request id`）和错误码／类型令牌。超时使用 `MEMORY_EMBEDDING_TIMEOUT`，连接失败仍为 `MEMORY_EMBEDDING_UNAVAILABLE`。测试连接失败时错误信息附带 HTTP 状态、上游错误码与请求 ID。任务列表只返回状态和计数，不包含源文本；0080 起 `error_detail` 记录最近一次失败的 `kind`（timeout／network／http／response）、`httpStatus`、`upstreamRequestId`、`upstreamCode`、`elapsedMs`、`timeoutMs` 和 `at`，任务之后成功也保留供参考。模型、配置、数据库能力探测不自动授权聊天或重建历史。

### 补建进度返回值

`GET /api/v1/memory/jobs` 与聊天下的 `/memory/jobs` 保留原字段，追加聊天名称、模型、范围、request_key 和 progress。progress 包含 scope（full/remaining/null）、total、processed、removed、remaining、percent、lastProgressAt、generatedAt 和 estimate。百分比为 `(processed + removed) / total`，removed 不计为索引成功。scope=null 不显示百分比。

estimate 包含 status、messagesPerMinute、remainingSeconds、estimatedCompletionAt；不可预估时三个数值/时间字段为 null。状态包括 available、warming、waiting、stalled 和任务终态。日期使用 ISO 时间，客户端以本地时区展示。普通进度接口仅含元数据，操作仍需敏感二次验证、版本检查和审计。接口 schema 以 OpenAPI 为准。

任务列表采用 `limit`（默认 50，上限 100）与不透明 `cursor`，返回 `{ data, page: { nextCursor } }`；按创建时间与 ID 倒序稳定分页。Web 索引任务每页 10 条（AI 服务页与聊天面板一致），详情单独读取，不受当前列表页限制。

Provider 路由列表按创建时间倒序、ID 升序稳定排列；修改策略或启停不改变排序。AI 页面以列表展示路由名称、状态、候选顺序、运行策略、创建时间与操作。

Provider Attempt 响应诊断与原始请求共用最近 20 个执行的内存生命周期，不落库、不进入普通日志。响应按 clientRequestId 独立关联，重试不会覆盖相同请求哈希的其他响应；仅敏感验证后通过 `/api/v1/executions/{executionId}/ai-attempts/{attemptId}/raw-response` 查看和复制。正文最多保留 64 KiB（UTF-8 安全截断），同时返回原始字节数和截断标记。只提取 error 的 message/code/type/param 及请求关联 ID（x-request-id、request-id、openai-request-id、cf-ray、x-amzn-requestid、x-ms-request-id），不保存认证或 Cookie 响应头。错误字段仍属于敏感正文，不进入普通执行列表。未收到完整响应不伪造正文；空响应、HTML 和文本可区分。弹窗分为结果摘要、响应与错误详情、原始请求及缓存诊断；敏感会话失效清空正文并拒绝过期响应。


### 近期发言与上下文覆盖

历史归档工具已扩展为 5 个：原文查询、语义搜索、来源展开、精确计数、首末消息。工具合同见[接口与配置契约](接口与配置契约.md#聊天归档工具合同)。新运行仅注册新名称，旧 `get_latest_chat_messages` 的参数 Schema、执行分支和专用查询已移除；旧执行中的工具名称及原有来源仍可查看。

最后发言与时间段查询使用上述工具，主题查询仍使用相关度搜索；相关度排序不能证明最近一次。身份不明时不能猜发言人，相对日期依据当前消息时间及聊天时区解释。连续追问沿用可见上下文已确定的绝对日期、成员、每日时段、关键词与分组；仅要求查看原文时不得扩大范围或重新解释相对日期。缺少必要条件时简短澄清；跨运行引用不可用时在相同范围重新查询。不增加回答事实审核。

执行上下文新增可选 `historyCoverage`：`windowEvicted`、`retained`、`omitted`；三项为 null 或包含 `count`、`firstMessageIndex`、`lastMessageIndex`、`earliestSentAt`、`latestSentAt` 的范围。条数来自实际候选消息，时间为发送时间极值，不用索引差推算。`contextIncompleteReasons` 包含 `window-evicted`、`history-trimmed` 或 `character-overflow`；任一原因使 `contextIncomplete=true`。该信息进入模型输入及执行快照，不含遗漏正文；旧执行不回填，显示“未记录覆盖范围”。范围区分消息窗口移出和字符裁剪，不代表被授权过滤或已清理内容的覆盖情况。

## Agent 执行配置

`GET /api/v1/ai/agent/settings` 返回 `{data}`，包含三个运行参数、`source=defaults|database`、`version`、`updatedAt`。`PUT` 接受三个参数和 `expectedVersion`，返回已保存配置。管理员权限与现有 AI 设置相同，更新写入 `ai.agent.settings.update` 审计；不另加敏感操作解锁。参数非法返回 400，未授权 401，并发版本冲突 409 `AI_AGENT_SETTINGS_CONFLICT`，配置服务不可用 503 `AI_AGENT_SETTINGS_UNAVAILABLE`。

| 参数 | 默认 | 范围 | 语义 |
| --- | --- | --- | --- |
| `maxToolCalls` | 10 | 整数 1–30 | 单次运行全部应用侧工具共享调用次数 |
| `maxToolOutputCharacters` | 64000 | 整数 4000–100000 | 累计模型可见工具结果字符，含来源元数据 |
| `maxToolDurationMs` | 90000 | 整数 5000–180000 | 累计工具执行及内部重试时间，不含模型生成 |

配置保存在迁移 0048 的 `ai_agent_settings` 单例表，无行时使用新默认值，版本为 0。保存后从版本 1 开始；运行开始时读取一次，运行中不切换版本。恢复默认值只修改页面表单，保存后才生效。不新增环境变量或工作流节点字段。供应商内部托管搜索无法作为应用侧工具逐次计数，不宣称该配置控制供应商内部搜索次数。

执行节点 JSON 摘要新增可选 `agentBudget`；合同与字段说明见[Agent 统一预算](事件与工作流设计.md#agent-统一预算)。它只记录元数据，不包含查询、消息正文或凭据。

## 内部 XML 请求协议 v2

公共 HTTP API、工作流配置 Schema 和工具参数 Schema 不变。模型输入的 `chat_history`／`current_message` 改为包含独立 `message` 节点：id、sender_id、sent_at 属性来自数据库／信封，author 保存作者类型及独立 Bot workflow 身份，text 为正文，reply_to、revision_notice、message_state、history_attachments、link_previews 分区各自序列化。外部文本不成为 XML 结构，非法 XML 1.0 字符仅在请求投影中替换，归档原文不改写。

`systemPrompt` 配置仍接受既有模板语法，但 system 角色只包含管理员模板原文和占位符。实际使用的变量按名称排序进入历史之后、本轮输入之前的 user `system_template_data/variable`，name 为变量名，缺失为空，不递归替换。动态变量不再具有 system 优先级。普通任务模板、上游输入仍是 user 任务数据。请求的原生角色、工具关联及图片协议不变；内部区域／链接预览元数据不出现在 Provider 请求中。

历史检索外层 JSON、Evidence.text 的 string 类型、`M1` 引用、分页、附件引用和权限不变；text 内容改为完整 XML 消息片段，而非时间／发言人行拼接。仅改变新请求的运行时展示，不改索引、Embedding、历史执行记录或数据库证据来源。历史字符预算包含序列化结构与转义；工具预算按最终 JSON 长度核算，均不截断 XML。

### 历史工具紧凑投影与统一模型时间

公共 HTTP API、工作流配置 Schema 和工具参数 Schema 不变，无数据库迁移。仅调整发给模型的内容：

- `query_chat_messages`、`search_chat_history`、`read_chat_excerpt` 的每条证据只保留 `ref`、`text` 与非空的 `attachments`／`images`；移除与 XML 重复的 `authors`、`participants`、`messageIds`、`dates`、`senderIds`，以及查询结果外层的 `messageId`、`sentAt`、`senderId`。成员名称改为每次结果一份 `participants`（`sender_id → 名称`）。
- 历史工具 XML 中普通成员作者与消息 `sender_id` 相同时只输出 `<author kind="participant">`；Bot、unknown-self 及不一致身份仍输出完整作者字段。

**模型可见时间统一为一种格式**：带聊天（或任务）时区偏移的 ISO 8601，例如 `2026-11-17T00:00:00+08:00`，毫秒非零时保留；与历史工具 `from`／`to` 参数和计数工具时间桶一致，可直接复用。覆盖范围：

| 位置 | 字段 |
| --- | --- |
| 注入历史与当前消息 | `chat_history`／`current_message` 的 `sent_at`（原为 `YYYY-MM-DD HH:mm:ss GMT+08:00 [时区]`） |
| 覆盖范围 | `history_coverage` 各区间的 `earliestSentAt`／`latestSentAt` |
| 附件目录 | `file_attachments` 当前及历史条目的 `sentAt` |
| 上下文路径 | `context.event.message.sentAt`、`context.history.messages[].sentAt` |
| 运行状态 | `agent_budget_status.currentTime` |
| 定时任务 | 触发投影 `scheduled_task.scheduledAt`／`triggeredAt`；任务工具结果的 `scheduledAt`、`nextScheduledAt`、`upcoming` |
| 历史工具 | XML `sent_at`、`queriedAt`、首末消息 `sentAt`、展开 `coverage.from/to` |

存储、事件信封（`scheduled-task-v2`）、执行记录与诊断、来源登记、引用校验、分页游标、附件目录提交、管理 HTTP API 和审计事件继续使用 UTC 及原结构。上下文提取节点的 `messages` 数据端口保留原始 UTC，由 AI 节点渲染时转换。面向用户的延迟提醒文案保持易读格式，不属于模型输入。网页搜索返回的 `publishedAt` 为外部原值，不做转换。

单条短消息证据由约 636 字符降至约 243 字符（虚构 6 字正文实测）；同一工具字符预算可覆盖约 2.6 倍原文。

## 聊天归档工具合同

仅在现有长期检索全局开关、聊天授权和活动索引代际条件满足时，通过 Agent 工具注册表提供以下 5 个工具；不新增 HTTP 接口、工作流节点或单独配置。直接数据库查询不要求向量覆盖，不调用 embedding。

| 工具 | 参数及默认值 | 返回与排序 |
| --- | --- | --- |
| query_chat_messages | 共用筛选；order=asc/desc 默认 desc；limit 默认 20、1–50；可选 cursor | 每条证据仅含 `ref`、XML `text`（消息 ID、聊天本地 sent_at、发言人、作者、正文）及可选附件/图片引用，结果级 `participants` 映射发言人名称；按 sent_at、message_index 同方向排序 |
| search_chat_history | query、senderId 或 botWorkflowId、from、to、limit（默认 8，上限 20） | 保留关键词/向量混合召回与相关度排序；相关度不能证明最新 |
| read_chat_excerpt | 已返回的 ref，before/after（默认各 8，范围 0～20） | 按实际可读行展开，保留源正文；可接受查询和首末消息返回的引用 |
| count_chat_messages | 共用筛选及附件/作者类别；groupBy 默认 none，可选 hour/day/week/month/sender/hourOfDay/weekday；可选 breakdownBy、orderBy；limit 默认 31、1–100；可选 cursor | 完整匹配集 SQL COUNT 后分页分组；返回 totalCount、totalGroups、returnedGroupCount；none 兼容 count；不返回正文或伪造引用 |
| get_chat_message_extrema | 共用筛选；groupBy=none/day/sender；limit 默认 31、1–100；可选 cursor；必填 pick=first/last | 整体或每组按发送时间、消息索引选首/末条；仅返回消息元数据及 ref，正文由展开工具获取 |

模型工具默认严格模式：未使用的可选字段传 `null`，服务端按原合同还原为省略；Provider 配置 `toolSchemaMode=compatible` 时改为省略未使用项，不接受原业务合同未允许的 null。严格模式下，语义搜索的 `senderId` 和 `botWorkflowId` 都为 `null` 表示不按发言者筛选，空字符串不作为省略。`query` 必须为 1–500 字符，时间含秒与时区，Bot ID 为纯 UUID；明确指定的身份无法确定时应澄清，不能静默删除限制。空值不改变服务端固定的聊天、历史授权和触发边界。`0`、`false`、有意义的空字符串或原本就有语义的 `null` 保持各工具原有含义。

参数解析和校验失败向模型返回 `unavailable/invalid-arguments`、安全的 `issues` 字段及修正指引；字段名只来自工具合同，错误不回显参数值、未知字段名或原始异常。可识别的条件规则、游标失效及历史检索失败分别提供原因，后端失败提供受控的阶段、类别和错误码；语义或关键词检索降级通过 `warnings` 提醒模型不要将不完整结果解释为不存在。插件 MCP 优先直接声明原始参数，由 Provider 模式决定可选字段的传法；仅复杂 Schema 的 `arguments_json` 内仍遵守原始 Schema：通常省略未使用的字段，只有原 Schema 允许时才能传 `null`；调用前参数校验失败可以修正，远端结果未知的调用不自动重放。

执行详情的历史工具 `responseDetails` 可包含 `kind=memory`、`version=1`、`status`、`mode`、`reason`，以及可选的 `failure`、`embeddingFallback`、`keywordFailure`。失败信息只含受控的阶段与类别、白名单字段名及校验代码、已知向量错误码与 HTTP 状态、失败类型、上游请求 ID／错误码令牌及耗时，或数据库 SQLSTATE；不保存参数值、聊天内容、原始异常或外部响应。每次调用独立记录，`mode=hybrid` 配合 `keywordFailure` 表示关键词分支失败而向量分支仍可用；`keyword-only` 配合 `embeddingFallback` 表示向量分支降级。模型收到单独构造的安全错误信息，不直接接收持久化诊断；旧记录不回填。沿用现有执行详情权限和 JSON 字段，无数据库迁移。

三个 SQL 工具共用以下筛选：

- senderId 为准确标识，不做姓名解析；chatId、触发消息上界、时区只能从服务端本次执行取得，模型不能覆盖。时区缺失的旧调用使用 UTC。
- from/to 为带时区 ISO 时间，包含端点，精度最多微秒；拒绝倒置。每日时段 dailyTime={from,to} 使用聊天时区，格式 HH:mm，起点包含、终点不包含；仅终点允许 24:00。23:00–02:00 表示跨午夜；分组日期仍是消息实际本地日期。拒绝相同时刻。
- keywords 接受 1–10 个非空词，每词最多 100 字符；提供时必须同时指定 keywordMode=all/any。对原始正文做大小写不敏感的字面子串匹配；%、_、正则字符无特殊含义。单位为消息条数，重复出现不重复计数。无关键词时附件消息也参与；附件衍生摘要不作为关键词正文。
- 仅当前授权聊天、message_index 严格小于触发消息且正文未清理的归档记录。与上下文裁剪、向量候选条数无关；没有读取到的记录不能据此推断不存在。

计数工具的时间维度必须提供 from/to，最多覆盖 366 个本地自然日；none/sender 继续允许不指定时间范围。维度含义：

| 分组 | 语义 |
| --- | --- |
| hour / day | 带日期的小时／自然日；hour 含 UTC 偏移，夏令时重复小时分开、缺失小时不生成 |
| week / month | 周一开始的 ISO 周／自然月；按本地日历而非固定秒数 |
| hourOfDay / weekday | 跨日期合并钟点 0–23／ISO 星期 1–7；返回累计条数，不是日均值 |
| sender | 按稳定成员／Bot 工作流标识；不同角色同名仍分组，NULL 和未知本账号独立保留 |
| none | 全部匹配归档计数 |

只允许两类组合：任意时间维度 + breakdownBy=sender；weekday + breakdownBy=hourOfDay。单时间维度与星期×钟点补齐零桶，星期×钟点固定 168 组；成员组合只返回存在的组，成员信息通过当前页 members 字典和 senderKey 关联。orderBy 默认 group 按稳定键升序，countDesc 按数量降序并以同一键打破平局。超过 10,000 组整体返回 unavailable/group-limit，不能把截断分组冒充完整统计。

桶边界起点包含、终点不包含；整体 from/to 仍包含端点。hour/week/month 返回 bucketStart/bucketEnd；日分组保留 date。日历桶被请求时间边界切开时标记 partialBucket，不能当作完整周期比较。空桶只表示“没有匹配的可读归档”，不证明聊天没有活动或归档完整。首末工具仍只支持 none/day/sender，其中 day 最多 366 日并补齐 message=null；未扩展其维度。

计数支持 hasAttachments、attachmentName、attachmentType，和原文查询共用同附件匹配谓词；每条消息最多计一次，不是文件数。authorKind=participant 表示入站且 senderId 非空的归档身份，不保证是真人；bot 表示有确认归属的本账号 Bot 消息；unknown 包含无发言人和来源不明的本账号消息。这是筛选分类，保留旧返回 author.kind 的身份合同。所有筛选取交集，不扩大聊天授权。

整体计数 0 是成功，整体首末查询无匹配为 no-results。超出 JavaScript 安全整数范围的计数返回 unavailable，不近似处理。

SQL 返回 queriedAt 表示该条查询的数据库快照时间。totalCount、totalGroups 和本页组来自同一条 SQL 快照，totalCount 始终是完整匹配集数量，不是本页或排行前 N 项之和。每次调用重新查询，不跨模型轮次维持事务；补录和清理可能改变后续页面。cursor 是会话内不透明 UUID，绑定工具、规范化筛选、排序、分组、取值和授权范围；允许调整 limit，不可跨会话使用，不接收客户端时间/索引位置。原文使用包含微秒的时间与索引进行 keyset 分页，不使用 OFFSET。

返回包含 filters、timeZone、hasMore、nextCursor、complete、truncated；仅第一页已覆盖全部匹配时 complete=true。分组计数即使分页，每个已返回组仍是精确值（countsExact=true）；不能将部分分组的和称为总数。字符预算只丢弃完整项目，cursor 始终绑定实际返回的最后一项；不足以容纳一项时返回 unavailable/tool-output。计数页另有 12,000 字符软分页上限，达到时 hasMore=true、truncated=false，提供续页 cursor，不触发统一预算收尾；只有实际剩余工具预算不足时才标记 truncated/tool-output 并收尾。若单项连软页也无法容纳则明确 unavailable/tool-output，不静默截断。其他原文工具仍沿用字符裁剪收尾规则。重复查询复用来源，但照常计次、计字符。无结果不等于权限失效，查询失败或预算不足绝不返回伪造的零。

查询、统计和联网继续共享单次运行 10 次 / 64,000 字符 / 90 秒默认预算，不按天发额度。数据库单次操作仍受 5 秒和当前剩余工具时长较小值约束；取消后销毁连接，迟到结果不登记来源。普通轨迹仅保留工具名、结果条数、状态和预算元数据；统计诊断额外白名单记录 groupBy/breakdownBy/orderBy、返回组数、输出字符量、hasMore/truncated 和受控失败原因，不写日期、关键词、成员标识、各组计数或正文。


## Bot 角色配置与归属维护

GET/PUT `/api/v1/workflows/:workflowId/bot-identity` 管理昵称。PUT 输入 nickname（去除首尾空白，1–120 字符，无控制字符）与 expectedVersion；未配置版本为 0，冲突返回 409。首次保存后只能改名不能清空。管理权限及审计与 AI 全局设置一致，不激活或发布工作流；保存只影响后续执行。workflowId 是稳定角色 ID，同名允许。

GET `/api/v1/bot-attributions` 返回精确匹配预览、最近任务和派生历史状态；POST `/api/v1/bot-attributions/backfill` 启动只读原文的元数据回填；POST `/api/v1/bot-attributions/:jobId/retry` 重试失败任务。POST `/api/v1/chats/:chatId/bot-identity/rebuild` 需要管理员敏感解锁并记录审计，仅启动索引重建，不处理聊天摘要。

原文查询、计数、首末和语义搜索新增可选 botWorkflowId（UUID），与 senderId 互斥，不能扩大聊天权限。senderId 仍表示网关成员，不接受角色昵称。返回作者 kind 为 participant、bot 或 unknown-self；Bot 包含 workflowId、nickname、version、basis、revision。按 sender 分组分别统计各 Bot 工作流和未知本账号来源，不混成一个发送账号。游标绑定角色筛选，证据哈希包含作者元数据。

工作流 Manifest metadata.botNickname 是可选昵称建议；导出不带身份 ID 或历史关联。导入预览与结果返回建议昵称，角色区保存后生效；新建工作流产生新身份，已有工作流导入不覆盖身份配置。

角色归属状态新增 `workflows`：每项含 `workflowId/name/nickname/total/bound/unbound/nicknamePending`。统计单位为可精确匹配发送记录的归档消息，`total = bound + unbound`；来源未知和多重匹配单独保留在账号级预览，不猜测其所属自动化。已绑定但尚待首次昵称补充的消息计入 `nicknamePending`，不算未绑定。无消息的未删除工作流仍返回零计数。

角色弹窗通过 GET `/api/v1/bot-attributions?workflowId=<uuid>` 仅查询当前工作流统计、归属任务和有发送记录的聊天；不返回全局未知/冲突预览。回填接口可选请求体 `{workflowId}` 限定工作流，省略仍为全局回填。两者校验工作流存在。聊天重建范围仍为整段聊天共享历史，索引记录在「AI 服务 → 索引任务」查看。

角色历史索引重建使用 reason=rebuild 标识，分批、重试及暂停恢复保留该类型；不能用 request_key 是否为空判断是否为增量任务。重建任务首次领取时初始化固定范围进度，之前显示“等待初始化进度统计”。旧的未完成无统计补建任务下次领取时仅统计剩余范围并重置旧采样；已完成任务不回填。补建与重试只为当前代次尚未索引的消息生成向量：已在 `memory_indexed_messages` 中的消息计为已处理但不再调用 Embedding；编辑、撤回、清理及角色归属重建会先清除该标记，因此仍会重新索引。若跳过的消息在提交前失去标记，该批回滚重试。

## 聊天上下文配置与摘要退休（迁移 0052）

`GET/PUT /api/v1/ai/context/settings` 使用管理员权限。PUT 写入 `ai.context.settings.update` 审计，通过 `expectedVersion` 检查冲突（409），不要求敏感操作二次解锁。字段为 `includeFromMe`（默认 true）、`baseMessageWindow`（1～50）、`redundancyMessageWindow`（1～50）、`characterLimit`（100～60000）；默认值分别为 true、10、10、6000。返回增加 source、version、updatedAt。未保存使用默认值；保存只影响之后创建的触发快照。

聊天摘要设置、压缩列表／详情／正文／重新生成、聊天摘要清空／重置接口全部删除（404）。Bot 归属重建仅接受 `target=memory`，缺省为 memory，summary/both 返回参数错误；归属状态不再返回 summaries 或 bot_summary_* 字段。模型调用用途只保留 workflow-reply 与 image-summary。

`load-context` 输出 messages、count、participants，不再输出 summary 或 summaryCoveredThroughIndex。已有工作流显式引用这些输出时，校验报告节点及缺失端口，不静默渲染空值。

`historyCoverage` 包含 retained（最终原文）、omitted（字符裁剪）、windowEvicted（消息窗口移出）。范围为空或包含 count、firstMessageIndex、lastMessageIndex、earliestSentAt、latestSentAt；计数和时间均来自实际允许读取的记录。contextIncompleteReasons 分别使用 window-evicted、history-trimmed、character-overflow，模型输入与执行快照一致，不包含移出正文。旧快照缺少覆盖信息不回填。

### 生成与检索统一策略

共享常量位于 modules/ai/execution-policy.ts，由前后端共同使用；运行时通过 resolveGenerationPolicy 解析新旧配置。ai-chat 新字段 targetOutputCharacters 为 1～4000 整数，派生保护值为 3 倍，不能与旧 maxOutputCharacters 同时设置；maxOutputTokens 仍允许 1～8192。新建模板显式使用 2000/8192，旧配置省略值维持 4000/1024。无新增全局接口、环境变量或数据库迁移。

图片摘要新请求使用 500 字符提示目标、1500 字符保护和 2048 Token；不自动重建已有摘要。

search_chat_history 返回 returnedCount（实际片段数）、candidateLimitReached（任一路触及候选上限，不能证明没有更多）、selectionLimited（已知融合候选超过 limit）、exhaustive=false，以及原有 coverage/truncated。未索引补充依然仅检视有限的最近 100 条记录；本轮不增加语义分页。内容预算裁剪按完整证据项移除并更新数量。

read_chat_excerpt 返回 returnedMessageCount、beforeCount/afterCount、hasEarlier/hasLater、coverage（实际索引和最早/最晚时间）及 truncated。预算不足时逐条移除最外围消息并更新覆盖和可用性，源消息不截断；源本身放不下则 unavailable/tool-output。权限撤销、正文清理或无效引用均 unavailable。共享 Agent 配额不变，不能用有限语义结果证明完整时间线或完整计数。

发送层渲染结果使用同源最大保护值 12000 字符，避免固定 4000 字符阻断已通过 AI 节点校验的完整结果；超出时失败、不切片。reply 文本模板自身仍限制 4000 字符，AI 节点仍按本次配置硬上限校验。


执行列表支持 `attention=unknown-outbound`，按未知出站且执行未关闭筛选，再应用游标分页；与 `status` 取交集。运行状态的未知出站数量排除所属执行已关闭的发送记录，原始发送状态不变。


### 历史引用格式与回答交付

`[M数字]` 是本次历史聊天工具返回的内部来源标记，不能用于网页、图片或当前上下文消息编号。网页来源遵循联网来源展示策略。引用有效性只核对标记，不等于事实审核。

未登记引用最多触发一次格式纠正，不开放新工具、不突破既有轮数；纠正保留用户原任务及可用网页、图片和上下文，不强制转为历史问答。仍有无效引用时，仅移除内部引用标记并保留回答内容，不将未知标记登记为来源；JSON 按结构处理字符串。无效 JSON 或清理后空文本以 `AI_OUTPUT_FORMAT_INVALID` 失败，不再发送“未找到历史线索”的固定兜底。权限复核与正文清理检查不变。

执行快照中的 `agentBudget.citationHandling` 为可选元数据，包含 `invalidResponses`、`correctionAttempts` 和 `finalAction`（`corrected`、`markers-removed`、`failed`）。执行详情以普通说明展示，旧快照不回填，普通日志不新增回答正文。原始模型响应沿用已有受保护诊断。

### 恢复队列批量关闭

`POST /api/v1/executions/recovery/close` 需要管理员敏感操作授权，审计动作为 `execution.bulk-close`。返回 `{ data: { closedCount: number } }`。一次数据库语句关闭执行时可见的全部 `retrying`、`failed`、`dead-lettered` 记录，不受列表分页限制；并发更新后已不符合条件的记录不会关闭。清空重试时间和当前节点，保留完成时间、错误码、出站状态及轨迹。空队列或重复操作返回 0；不发送消息，不修改运行中和已完成任务。


### 表情库与独立投递

### Agent 每轮额度提示与收尾

工具定义在一次 Agent 循环内保持可见；公共接口、配置及预算快照结构不变。模型每轮收到当前调用次数、工具结果字符数和累计执行时间的已用／上限／剩余值，以及模型轮次和执行可用状态。预算截断、轮数预留或引用修正进入收尾后使用 `toolChoice=auto`，调用只返回 `unavailable`，不执行实际操作。预算拒绝沿用 `AI_AGENT_TOOL_LIMIT_REACHED`；引用修正或轮次收尾拒绝使用 `AI_AGENT_FINAL_ANSWER_REQUIRED`。超过 N＋2 轮仍未完成回答返回 `AI_AGENT_TURN_LIMIT_EXCEEDED`。这不增加正文格式识别或额外模型审核。

### Provider 工具参数模式

Provider 新增 `toolSchemaMode: strict | compatible`，默认 `strict`。创建、编辑、查询及列表共用现有 Provider 接口；旧请求省略该字段时使用严格模式，完整编辑请求须回传当前选择，版本冲突仍返回 409。管理页在 Provider 弹窗中提供「工具参数模式」下拉框，编辑回填已存值；工作流不新增开关。

| 模式 | 模型侧声明 | 未使用的业务可选项 |
| --- | --- | --- |
| strict（默认） | `strict: true`，递归全部属性 required、`additionalProperties=false`，可选字段增加 nullable 分支 | 传 null，执行前按原合同还原为省略 |
| compatible | `strict: false`，递归保留业务 required，不额外注入 nullable，`additionalProperties=false` | 直接省略；不删除模型错误传入的 null，由原业务校验拒绝 |

两种 API 均显式传递 strict 标志。原本有业务意义的 null（如选择表情的跳过值）、嵌套结构、互斥约束、默认值及授权保持不变；默认值仍由业务校验器应用。公共提示词及校验错误不固定要求 null，由当前 Provider 的工具声明附加对应模式说明；原始 assistant 调用及配对 ID 保持不变。Provider 降级或切换时，每次请求按实际候选重新构建 Schema，执行参数处理按本轮成功 Provider 的模式进行。

能力探测沿用 auto，通过提示词引导调用无副作用工具，并验证可选 note 在严格模式下为 null、兼容模式下省略，再回传模拟结果验证闭环；每次管理测试使用独立标识，纯文字声称调用不算通过。它不保证所有工具或上游长期稳定。迁移 0072 增加 `ai_providers.tool_schema_mode`，既有记录默认 strict；无新环境变量。

本地不可转换的工具定义返回 `AI_TOOL_SCHEMA_INVALID`（configuration，retryable=false，fallbackAllowed=false，countsForDegrade=false），不会向供应商发送请求。它与模型生成参数错误、供应商 502/503 区分；参数错误继续沿用工具原有结果和计额。

| `web_search` | `query` | 无 |

归档共同筛选中，`senderId` 与 `botWorkflowId` 互斥；`keywords` 与 `keywordMode` 必须同时出现或同时省略；`from` 不晚于 `to`；`dailyTime.from` 与 `dailyTime.to` 不相同。`hasAttachments=false` 不能与 `attachmentName` 或 `attachmentType` 合用；文件名与类型同时使用时必须匹配同一附件。游标需来自本次工具结果并绑定原查询条件。各参数的取值范围和默认值仍以相应工具 Schema 与上文归档合同为准。

应用先校验外部 MCP 的原始参数，再连接或发现远端服务；校验错误可修正后重新调用，权限检查和远端未知结果不得绕过。OpenSandbox 的原始工具分别要求：`prepare_sandbox` 无参数；`run_command` 必填 `command`、可选 `timeout_seconds`；`read_file` 必填 `path`、可选 `offset`/`length`；`write_file` 必填 `path`、`text`。其他 MCP 工具的字段由其获批 Schema 定义，不能预设为固定参数集。

connection 字段为 `{url,allowPrivate,auth,header,secret?}`；auth 为 none / bearer / header。留空省略 secret 仅在地址、认证方式和请求头不变时保留已有凭据。只支持明确配置的凭据，不向包提供任意环境变量。header 认证禁止 Host、Cookie 等传输控制头。错误使用 PLUGIN_* 受控码，不将供应商异常或凭据写入普通日志。

执行工具 JSON 诊断可包含插件 ID、不可变 revision、服务、工具、Skill／参考 ID、轮次和结果状态；不新增参数正文、工具正文持久化。旧诊断不回填。

插件 MCP 首版每个服务支持至多一个认证请求头占位符；多认证头整包拒绝。`Authorization` 默认由向导映射为 Bearer，其余头映射为 API Key Header；不读取宿主环境变量。插件列表的 `pending_review` 保存受影响工具标识，重新发现并确认授权后清除；详情 `references` 提供阻止卸载的工作流 ID 与版本。运行前后复核当前及固定版本的凭据和权限，定义变化不会自动获得批准。

插件列表 `GET /api/v1/plugins` 增加只读 `summary`：`toolsEnabled` / `toolsApproved` 为未停用／已批准工具数，`skillsEnabled` / `skillsTotal` 为开启／总 Skill 数，`servers` 为包声明的 MCP 服务数，`activeWorkflows` 只统计未删除、启用中且当前发布版本 AI 节点明确配置该插件 ID 的工作流（同工作流多节点只计一次，不计草稿、旧版本或提示词中出现的 ID）。这些是配置统计，不代表实时可调用或服务健康；待复核工具另外提示。`autoSyncTools`、`lastCheckAt`、`lastSyncStatus` 表示自动同步配置、最后检查时间和最近状态，无记录返回 null。停用插件的自动同步显示暂停；同步失败仍保留原配置。列表保留原 `metadata.description` 简介，不返回加密配置、凭据或完整连接。无需数据库迁移或新增权限。

MCP 工具失败结果提供程序生成的 `contentAvailable=false`、`retryInThisAnswer=false` 和后续处理指引；这些字段是模型指引，不代表程序自动重试或切换供应商。仅 `isError` 结果中的明确结构化错误码 `QUOTA_EXCEEDED`／`INSUFFICIENT_CREDITS`／`CREDITS_EXHAUSTED` 归为 `PLUGIN_QUOTA_EXHAUSTED`，`RATE_LIMIT_EXCEEDED` 归为 `PLUGIN_RATE_LIMITED`；未知错误保留通用工具错误，不从任意文本推断额度。工具调用 HTTP 402 表示计费受限，429 表示限流，401／403 表示远端认证拒绝，均不把正文标为已读取。具体供应商错误映射须在接入时核对。

插件导入任务的 `error_code` 仅保存受控原因：缺少清单、Git 读取失败/超时、包超限、不安全路径或网络目标等；未知异常仍为 `IMPORT_FAILED`，不保存 Git stderr、凭据或任意异常正文。旧任务的统一错误码不能反推具体原因。`SENSITIVE_AUTH_REQUIRED` 是请求级授权错误，与已受理导入任务失败分开解释；导入权限要求保持不变。

### 外部网络配置

`GET /api/v1/settings/network` 要求管理员登录，返回 `trustedFakeIpHosts`、`version`、`updatedAt`。`PUT` 要求管理员登录、敏感解锁并记录 `network.settings.update` 审计，提交 `trustedFakeIpHosts` 与 `expectedVersion`；版本过期返回 `NETWORK_SETTINGS_CONFLICT`（409）。最多 32 个精确 DNS 域名，去空白、转小写和去重，拒绝 IP、URL、端口、路径与通配符。列表仅允许 Fake-IP，不配置代理服务器或代理出口。

图片 `trustedLinkPreviewHosts` 为弃用的只读兼容别名，更新请求可以省略；传入不同于当前共享配置的内容返回 `NETWORK_SETTINGS_MOVED`（409）。前端统一通过系统设置维护，图片、链接预览、Git 与 MCP 使用同一来源。

### Git 插件目录链接

POST /api/v1/plugins/imports 的 Git JSON 接受 url、可选 ref、可选 directory。url 支持 GitHub /tree/<ref>/<directory> 和 /blob/<ref>/<directory>；后者同样必须指向目录。普通仓库未传 ref 时用 HEAD，未传 directory 时按根目录发现插件。目录链接自动识别，ref 可用于消歧；同时指定 directory 返回 GIT_SOURCE_AMBIGUOUS，建议改用仓库根地址。任务 source 返回规范化 url、ref、directory、sha，staged 文件路径相对所选目录。权限及 ZIP 合同不变。

### MCP 连接测试与参数兼容诊断

插件已批准工具增加可选 `outputSchema` 字段，输出契约变化同样需要重新批准。`POST /api/v1/plugins/connections/test` 不调用业务工具；发现阶段按 MCP JSON Schema 校验，不能把模型严格模式不支持误报为 MCP 连接失败。

受控错误包括 `PLUGIN_SCHEMA_UNSUPPORTED`、`PLUGIN_SCHEMA_DIALECT_UNSUPPORTED`、`PLUGIN_REMOTE_AUTH_DENIED`、`PLUGIN_RATE_LIMITED`、`PLUGIN_BILLING_REQUIRED`、`PLUGIN_MCP_TIMEOUT`、`PLUGIN_MCP_CANCELLED`、`PLUGIN_MCP_TRANSPORT_ERROR`、`PLUGIN_MCP_PROTOCOL_ERROR`、`PLUGIN_MCP_OUTPUT_INVALID` 及 `PLUGIN_MCP_TASK_REQUIRED`。界面显示中文原因；不包含凭据、调用参数或远端原始错误。模型侧外部工具优先直接声明参数，仅转换器不能表达的复杂 Schema 封装为 `{ "arguments_json": "{...}" }`。编码方式按本次注册合同固定，不猜测、自动兼容旧包装或修补参数。封装内 JSON 非法时返回 `issues=[{field:"arguments_json",code:"invalid_json_object"}]` 与转义/闭合修正指引，不回显内容或原始解析异常；两条路径均按批准的原始契约校验后才发送。管理 API 的工具原始定义、批准哈希和授权范围保持不变。

### 插件目录预算设置

`GET /api/v1/settings/plugins` 要求管理员登录，返回 `catalogueCharacters`、`version`、`updatedAt` 及 `usage`（全部已启用插件的 `characters`、`toolCount`、逐插件占用和 `sharedCharacters`）。这是全部启用插件同时使用的参考值，工作流按所选插件单独计算。

`PUT /api/v1/settings/plugins` 要求敏感验证并审计，提交整数 `catalogueCharacters`（8,000–256,000，默认 64,000）及 `expectedVersion`；版本冲突返回 409。仅影响后续工作流校验及新执行。超限错误显示当前字符数、配置上限与设置入口，工具数量上限独立校验。

插件调用审计在已有 `requestDetails` / `responseDetails` 中增加可选 `pluginName`，与 `pluginId`、`revision`、`server`、`tool` 一起记录运行时身份，不增加接口或迁移。执行详情以 MCP 服务标识和原始工具名为标题，模型使用的 `ext_…` 名称保留在诊断区。旧记录仅在同节点、同插件 ID 和同版本的执行预算快照可唯一匹配时展示插件名称，否则明确显示未记录；不查询当前安装名称替换历史名称。普通远端工具错误不推断为余额或认证失败，不持久化原始错误正文。

### MCP 大结果诊断（可选字段）

不增加管理 API 或迁移。现有 aiToolExecutions.responseDetails 可包含 diagnosticVersion=1、delivery（complete/partial/read/search）、resultRef、parentToolCallId、responseBytes（tools/call HTTP 响应已读取字节，包含传输封装）、responsePayloadBytes（已校验结果的 JSON 字节）、normalizedCharacters、totalCharacters（正文码点数）、storedBytes、deliveredCharacters、outputLimit、remainingBefore/remainingAfter、offset/nextOffset 和 matchCount。值只描述实际接受的结果，缺失项不推测；不记录正文、查询词或完整参数。

PLUGIN_RESPONSE_TOO_LARGE 表示网络响应超过 30 MiB；PLUGIN_RESULT_STORAGE_LIMIT 表示运行内暂存超过 30 MiB；PLUGIN_RESULT_BUDGET 表示剩余文字不足；PLUGIN_MCP_TIMEOUT 表示 MCP 超时，Agent 总时间耗尽继续使用 AI_AGENT_TOOL_TIMEOUT。工具读取复用现有敏感详情保护，结果引用不是下载地址。旧记录无需回填，前端显示未记录详细交付信息。

## OpenSandbox 适配服务配置

主应用 API、数据库和工作流配置没有新增字段。独立服务通过 Bearer 认证的 `/mcp` 提供 Streamable HTTP；敏感解锁、逐工具审批和内网地址显式批准继续适用。服务凭据只读 secret 文件，插件包只含凭据占位符。

并发配置 `MAX_CONCURRENT_SANDBOXES`（默认 1，1–8）位于独立 Compose 环境，不能由模型参数修改。其余限额、镜像 digest、实例标识和网络配置见 [OpenSandbox 配置合同](../plugins/opensandbox/README.md)。命令返回状态、退出码、stdout/stderr、耗时和截断标识；非零退出不是成功，未知结果不重放。文件只支持 UTF-8，按字节 offset/length 和 nextOffset 分段读取。

## OpenSandbox 轻量运行环境

`SANDBOX_IMAGE` 支持固定 digest 的旧 Python 3.12 镜像或 `ghcr.io/shigella520/bubblepilot-sandbox-python`（可带标签）；其他仓库及可变标签拒绝。仅部署管理员配置，模型不能传镜像。`prepare_sandbox` 的 created/reused 结果增加 `runtime`，含版本化能力清单；缺失、超限或非法清单返回 `{ "id": "unknown" }`。在初始化时读取一次，后续复用同一快照，不新增公共 API 或迁移。

### 搜索来源展示与任务链接

`webSearchSources=full|compact|hidden` 是模型展示偏好，不是 URL 过滤器。full 引导按需附来源；compact 引导末尾最多两个附带来源，不限制任务所需链接；hidden 引导不主动附来源，但保留用户明确索要（含上下文追问）、任务必需、代码、配置及 JSON 中的 URL。模型不得编造地址，应区分拼接地址与实际访问验证。隐藏或精简由模型遵循，不保证绝对无引用或严格数量。

后端不删除最终回答的 URL、来源行，不递归清理 JSON 字符串；iMessage Markdown 链接仍转换为“标题：URL”。历史聊天引用标记处理、预算、权限、路由和发送规则不变。旧工作流无需重新发布，无 API、配置枚举或数据库迁移。

## 空闲主动交流合同

工作流 `message-trigger.config.idle` 为可选对象，旧定义缺省关闭；完整参数见工作流文档与生成的 `contracts/workflow.schema.json`。可移植清单将嵌套 `idle.chatIds` 转为 `idle.chatRefs`，导入需显式解析目标聊天，不携带原实例授权。

- `GET /api/v1/settings/idle`：仅返回实例 `timeZone`，用于新配置的时区默认值。
- `GET /api/v1/workflows/:workflowId/idle-preview`：只读当前启用版本，返回选定聊天的活动、资格、预计时间、免打扰、本工作流每聊天剩余额度与阻止原因；不调用模型、不创建执行。

发布或重新启用含空闲能力的工作流要求管理员认证并记录审计；发布时校验目标聊天归档授权，画布操作保留目标聊天确认。执行响应增加可空 `triggerEvent`，旧记录为 null；空闲执行没有 `source_message_id`，聊天通过 `target_chat_id` 关联。图片来源诊断的 scope 可使用 `idleExecutionId`，由服务端读取执行上界，不接受任意地址或扩大图片访问范围。

实例每日限额修改接口 `PATCH /api/v1/settings/idle` 已移除；预览不再返回 `instanceRemaining`。工作流限额按受理时的触发器时区计日，各工作流独立统计。资格检查与额度预约在受理事务完成，发送阶段不再复核活动、免打扰、配置、聊天权限或次数；无需新增配置或数据库字段。已受理执行及配套表情沿用该结果，手动关闭执行仍有效。


### 主动交流状态与历史

自动化页的「空闲主动交流」栏目展示当前状态和历史触发记录；状态基于已发布版本，不具备资格时不显示旧预计触发时间。`GET /api/v1/workflows/:workflowId/idle-history` 要求管理员登录，支持 chatId/status、offset（0～100000）和 limit（1～50）筛选分页，返回 items/hasMore；只含执行元数据，原始请求响应仍需敏感解锁且仅内存保留。模型主动交流优先自然开启轻松话题，跳过可返回受控 reason：user-unavailable/repetitive/no-suitable-topic。旧无 reason 响应仍兼容，历史不补猜理由。已有自定义说明不改写；程序决策指引每轮注入。测试覆盖决策枚举、历史查询隔离与分页、无资格隐藏预计时间。无数据库迁移，不自动启用生产工作流。


空闲配置继续使用 `idle.taskInstruction`（非空、最多 4000 字），默认第一版中性交流说明。节点提供恢复默认，程序决策协议不可配置。状态预览新增 `last-message-bot`、`last-message-unknown` 阻止原因；无资格时预计触发时间为空。

## 定时提醒

管理接口：`GET /api/v1/scheduled-tasks`（workflowId、chatId、status、offset、limit=1～50），`GET/PATCH /api/v1/scheduled-tasks/:taskId`，`POST /api/v1/scheduled-tasks/:taskId/cancel`，`GET/PUT /api/v1/settings/scheduled-tasks`。全部要求管理员认证；详情及修改要求敏感解锁并审计。详情含任务、变更历史和关联执行，不提供直接新建或重放已发送任务的管理接口。

PATCH 接收 expectedVersion 及 summary、content 或完整 schedule 变更；修改时区必须同时给出 schedule。取消需 expectedVersion。任务内容 1～2000 字符，时间必须含偏移量并与 IANA 时区一致。工具中的聊天、工作流和成员来自可信运行上下文，不是模型参数。无效时间、额度不足、归属不符、版本冲突及已经开始发送返回明确 TASK_* 错误码。

实例设置 PUT 为 paused、pendingLimit、catchupMinutes、expectedVersion，以及可选 retentionDays（整数 7～180，省略保留当前值）；GET 返回 paused、pending_limit、catchup_minutes、retention_days、version。retention_days 升级默认 30；用于已结束任务删除及历史周期／运行／事件正文保留，下一次清理检查读取新值。缩短期限可能永久删除已有历史；延长不恢复已清理数据。去重操作记录继续按内部 90 天规则保留，删除防重放标记不随此设置过期。配置写入沿用敏感授权、审计和 expectedVersion 冲突校验。补发窗口只影响新建／改期任务，0 表示保留计划时刻起一分钟的正常调度容差，超过该分钟不补发。消息确认应明确日期、时刻、时区。

工作流启用提醒需具备工具调用能力的文本模型路由；不新增环境变量。机器合同参见 `contracts/openapi.yaml` 与 `contracts/workflow.schema.json`。

## 聊天附件沙箱合同

AI 节点可选 `attachmentHandling={enabled,pluginId,server,limits}`，缺省关闭。启用要求文本输出、支持工具调用的路由、所选插件已启用及目标服务四工具均已批准。`GET /api/v1/plugins/attachment-targets` 要求管理员认证，仅列举已批准的协议 v1 服务，不创建沙箱；发布时重新握手、发现并检查绑定。唯一目标由节点界面预选，多个必须明确选定；既有绑定失效不重选。工作流导入移除该授权并返回 `ATTACHMENT_REBIND_REQUIRED` 警告，须重新绑定发布。

`limits`：`fileMiB=10`（1～20）、`files=3`（1～5）、`totalMiB=20`（1～50且不小于单文件）、`timeoutSeconds=30`（5～180并受剩余工具时间约束）、`expandedMiB=50`（1～100）、`expandedFiles=200`（1～500）。使用现有工作流版本控制和经管理员认证的发布，不新增数据库字段。

`query_chat_messages` 新增可选 `hasAttachments`、`attachmentName`（大小写不敏感的字面文件名子串）、`attachmentType`（规范化的精确 MIME 或 `.扩展名`）、`attachmentOffset`。文件名与类型由同一附件满足；其他筛选保持 AND、原分页单位仍是消息。不扩展计数／最早最晚工具的附件条件。原文结果及 `read_chat_excerpt` 的 `attachments` 含每条消息最多20项、总数、未展示数及 `nextOffset`，后者可传入 `read_chat_excerpt.attachmentOffset`；不声称元数据证明文件仍可下载。

内置 `import_chat_attachment({attachment_ref})` 仅在人类入站消息的获授权文本任务中提供，不能指定 URL、网关 ID 或目标路径。当前附件目录最多100项；历史查询按需发放引用，整次运行最多100个且不静默淘汰。返回任务内路径、SHA-256、实际大小、沙箱代次、运行环境、剩余额度；压缩包额外返回受控展开路径。成功重复调用复用文件，不重复占文件额度、不覆盖修改；每次调用仍消耗工具预算。二进制从不进入模型文本或 MCP JSON。

历史工具仅为成功返回的附件目录提交 `attachment_ref`；被裁剪的结果或取消、失败查询不授予导入权限。`ATTACHMENT_REFERENCE_UNAVAILABLE` 表示引用未在本次运行中发放，下载／导入尚未开始；可重新调用 `query_chat_messages` 或 `read_chat_excerpt` 获取引用，不得用上下文显示标识、消息 ID 或其他运行的引用替代。该错误不代表 XLSX 等格式不受支持，也不应直接要求用户重发文件。

MCP 初始化使用 `experimental["io.bubblepilot/attachments"]={version:1,...}` 显式协商；扩展不会改变原四工具的 Schema 哈希。已认证 MCP 会话通过 `POST /mcp/attachments/tickets` 申请默认45秒、一次性的上传票据（适配器 `ATTACHMENT_IMPORT_TIMEOUT_SECONDS` 可设5～180秒，响应 `expiresInSeconds` 返回实际值），再向 `POST /mcp/attachments` 发送二进制；两者都要求原服务凭据及 `mcp-session-id`，上传额外要求 `X-BP-Transfer-Token`，票据不放 URL。同一导入 ID 可核对已完成结果；会话失效不重建、不重放。原 MCP JSON 上限保持512 KiB，元数据入口上限8 KiB，文件硬上限20 MiB。该路径不是新的模型工具。


### 可配置的沙箱等待时间

插件安装、连接测试和配置接口的 `connections[server].callTimeoutSeconds` 为可选整数，范围5～180秒，缺省45秒。插件页每个 MCP 服务显示独立输入框，保存沿用敏感解锁和 `expectedVersion`；不会通过模型参数选择时限。该值只控制 `tools/call`，不改变初始化／发现的30秒时限，也不控制独立附件二进制上传。附件上传使用 AI 节点 `attachmentHandling.limits.timeoutSeconds`。两类调用均受 Agent 本轮剩余工具时间约束；连接测试不会调用业务工具或验证冷启动耗时。

重新测试连接只刷新工具目录：名称与定义哈希未变的工具保持勾选，变化或新增的工具须重新确认，不会因修改时限等连接设置而清空授权。原有授权的插件保存为 0 个工具时界面要求二次确认；若仍有未删除工作流（含停用）的已发布版本在 AI 节点引用该插件，`PUT /api/v1/plugins/:id/config` 返回 409 `PLUGIN_TOOLS_IN_USE`，需先解除引用或至少保留一个工具。运行中的执行在收尾时复核授权，授权被撤销会使本次执行失败，不发送已准备的附件。

独立 OpenSandbox MCP 适配器的环境变量（非 BubblePilot 主应用变量）：

| 变量 | 默认 | 范围 | 含义 |
| --- | --- | --- | --- |
| `SANDBOX_CREATE_TIMEOUT_SECONDS` | 40 | 5～180秒整数 | 沙箱创建及初始化截止时间，含缺失镜像的拉取等待 |
| `ATTACHMENT_IMPORT_TIMEOUT_SECONDS` | 45 | 5～180秒整数 | 附件上传请求、票据有效期、传输阶段和接收辅助命令的时限 |

变量缺省保持旧值，非法值阻止适配器启动；修改后重建适配服务容器生效。模型不能覆盖这些变量。会话TTL与普通命令执行时限不会随之增加。


### OpenSandbox 命令时限

适配器新增 `SANDBOX_COMMAND_TIMEOUT_SECONDS`（默认60）与 `SANDBOX_COMMAND_MAX_TIMEOUT_SECONDS`（默认120），单位秒，均为1～180整数，默认值不得大于上限，非法配置阻止启动。`run_command.timeout_seconds` 的缺省值及 maximum 从这两项生成；修改后重建适配器并重新发现／批准工具，旧批准的 Schema 不自动扩大。命令参数省略时使用默认时限。应用 MCP 时限及本轮剩余工具预算继续优先约束。

命令超时／取消／不确定错误分别返回 `command_timeout_session_invalidated_do_not_replay`、`command_cancelled_session_invalidated_do_not_replay`、`command_result_unknown_session_invalidated_do_not_replay`，均为 MCP `isError=true` 的工具结果。会话立即失效，不允许继续执行或自动重放；不能将超时解释为“没有副作用”。

`SANDBOX_WORKSPACE_CHECK_TIMEOUT_SECONDS` 单独控制沙箱磁盘用量检查，默认 10 秒，整数范围 1～30 秒。它不改变 256 MiB 用量阈值、20,000 个条目扫描边界或每秒检查调度，不接受模型参数。检查超时、用量越界或结果不确定仍立即使会话失效并进入清理；底层忽略取消也不能无限阻塞清理轮询。


## 周期提醒合同（迁移 0063）

单次及周期共用 `/api/v1/scheduled-tasks`。模型工具创建必填 summary、content、timeZone、schedule；模型工具和管理 API 更新均只通过 schedule 修改时间，不再接受顶层 scheduledAt。已有外部调用方须改用完整 schedule，旧写法返回参数错误。schedule.kind=once 含 scheduledAt；recurring 含 startsAt、rule、end。rule 支持 daily(localTime)、weekly(weekdays:1～7,localTime)、monthly(dayOfMonth:1～31|last,localTime)、interval(everyMinutes:60～525600)。end 为 never、until（不含截止时刻）或 count（1～10000，含失败／过期／跳过）。完整 Schema 见 OpenAPI 的 TaskSchedule。

每个 `schedule`、`rule` 和 `end` 只能选择一种类型，不能混合其他类型专属字段；`weekly.weekdays` 不得重复。模型工具出现非法组合时返回 `TASK_ARGUMENTS_INVALID` 和修正指引，不自动选择或更改时间。

PATCH 替换整个 schedule，保留已消费计数且不改变 kind；expectedVersion 必填。列表响应中的 scheduledAt 表示当前计划执行时间，并非更新入参。POST `/{taskId}/pause|resume|skip-next|cancel` 需要敏感认证、expectedVersion 和审计；暂停任务计入活动额度，恢复从当前时刻之后安排。周期提交发送后的暂停／取消返回 sendingAlreadyStarted=true，不能承诺当前发送撤回。单次发送后保持拒绝修改。

POST `/api/v1/scheduled-tasks/preview` 需要管理员登录，接收 schedule、timeZone、可选 consumedCount（默认 0），返回规则摘要与最多三个未来 UTC 时刻；无写入或模型调用。输入错误为 400，任务规则／时间冲突为 409。预览中的消费数只是计算输入，保存始终以数据库为准。列表新增 lifecycle 筛选，返回 schedule、lifecycle、consumedCount、nextScheduledAt、scheduleSummary、upcoming。详情的 offset/limit 分页用于实例／执行，events 最多返回最近 100 项；旧字段保留。

成员工具新增 pause_scheduled_task、resume_scheduled_task、skip_next_scheduled_task，复用取消工具的 id/expectedVersion 合同。写权限仍只属于真人当前消息，按聊天＋工作流＋创建者隔离；到期事件不可再登记任务。新 scheduled-task-v2 事件增加 occurrenceId/occurrenceNumber，旧 v1 继续恢复。不新增环境变量、MCP 或数据库外存储。

## 消息修订合同（0064）

无新增环境变量或工作流开关。`contracts/bluebubbles-webhook.schema.json` 接受新消息和更新通知；内部修订使用 `message-revision-v1`，普通消息信封保持 v3 并增加可选引用字段。修订通知通过现有 Webhook Secret 校验，响应仍为 202，自动化结果为 `not-evaluated`、不返回执行；重复更新返回 duplicate。队列容量不足请求失败供调用方识别，不能静默丢弃后宣称成功。

归档列表、搜索、详情和新导出增加 `revisionState`（active/retracted/partial/unresolved）、`editedAt` 与可选 `replyTo`。`replyTo` 包含 status，授权可知时包含 message_id、archive_id、message_index、sender_id、author、part_id；available 可包含 sent_at（UTC）、text_preview／truncated（仅引用文本部分 0 时），目标含附件时还包含 attachments（前 10 个，index／file_name≤200 字符／mime_type，不含网关标识）与 attachment_count。状态为 unavailable 时不披露边界外作者或撤回信息。`GET /api/v1/messages/:messageId` 需管理员认证及敏感解锁，且目标聊天仍允许访问，用于引用定位；不存在／不可访问返回 404。

`GET /api/v1/inbound-events` 中修订事件可带 `archiveUpdate`，展示异步任务 status、reason 和 attempts；它不是工作流执行状态。状态包括 pending/running/applied/ignored/failed，失败原因仅白名单元数据。模型结构与提示词规范见[迭代需求第 3.4 节](迭代需求-聊天消息修订与引用.md#34-传递给模型的引用结构)。

### 修订展示合同（0066）

敏感解锁后的归档列表、搜索、详情响应增加可选 retractedBody（字符串或 null），仅全部／部分撤回且未按保留策略清理时返回。普通 body 仍为空，引用 preview 不包含留存正文；未保存时返回 null。管理页关键词搜索仍只匹配当前正文，不扩展到留存正文。模型历史及工具证据使用不含原文的撤回／部分撤回／状态待确认占位，已编辑记录标注当前正文；不增加工具参数或新工作流事件。

### 本轮通用附件目录

模型输入中的 `file_attachments` 目录覆盖实际纳入本轮上下文的当前及历史消息附件，不按文件类型过滤。目录携带所属消息标识、`sentAt`、`senderId`、附件序号、有限文件名、MIME 和大小；未知字段使用 null。`archived=true` 只表示归档元数据存在，`availability=not-verified` 不保证仍能下载，`contentRead=false` 表示尚未进行文件解析，不覆盖独立图片输入或图片摘要的状态。文件名最长512字符并标记截断，MIME最长256字符；目录通过安全 JSON 编码，不携带网关附件 ID、下载 URL 或凭据。

开启附件处理后，内部 `AttachmentRunInput.history` 只接受已选入本轮上下文的消息快照。初始目录先为当前附件，再为最近历史附件分配本轮引用；历史引用必须通过现有聊天历史授权及触发消息时间边界检查。目录最多展示100项，历史每消息最多20项，复用整个运行100个引用的上限。初始目录与历史工具共用引用表，只提交最终提供给模型的目录项；没有权限、未开启处理、引用耗尽时不授予引用。省略消息数量、附件数量、每条目录的 omitted/nextOffset 明确显示，允许通过既有授权历史工具继续查找。

上下文提取计入附件序列化元数据和引用的字符开销；目录最终按剩余输入载荷空间删除完整条目，不截断 JSON 或必要说明，连最小目录都容不下时返回 `AI_INPUT_TOO_LARGE`。原64 MiB输入硬上限不变，最终组装再次校验。目录不是工具返回，不另消耗工具调用额度；后续导入及沙箱命令继续共用现有工具预算。

关闭附件处理时仍展示可见附件元数据，并明确 `attachment-processing-disabled`，不提供导入工具或引用。初始历史引用未授权时标记 `history-not-authorized`，引用耗尽沿用 `referenceLimitReached`。当前附件为空不能推断历史没有文件；模型必须匹配文件名、发送者和时间，存在有效引用时直接导入，缺失或省略时先检索历史，不以旧截图替代所请求的文档。本次不修改公共 API、数据库、配置开关或导入格式白名单。


## 定时任务概要

创建工具 create_scheduled_task 必填 summary（trim 后 1～40 字符、单行）、content、requestSnapshot（trim 后 1～8000 字符）、timeZone 和 schedule。列表、详情和工具结果返回可空 summary，旧记录为 null。update_scheduled_task／PATCH /api/v1/scheduled-tasks/:taskId 接收可选 summary，仍要求 id／expectedVersion（HTTP id 在路径中）；不传时保留。仅传概要可修改正文尚保留的已结束任务；正文已清理返回 TASK_CONTENT_CLEARED。仍按当前成员、聊天、工作流限制工具权限，管理员修改仍需敏感解锁。

仅更新概要递增管理 version、记录 summary-updated 事件，不改变执行版本、任务时间、状态、次数、逐次记录或在途运行。content／schedule 等执行性修改保留原状态校验并递增 execution_version。程序生成的 scheduleSummary 仍是时间规则说明，与模型提交的 summary 不同。


### 删除定时任务

DELETE /api/v1/scheduled-tasks/:taskId 要求管理员认证、敏感解锁，body 为 { expectedVersion }，成功返回 { data: { id, deleted: true } }。仅已结束且无在途运行的任务可删除，否则 TASK_DELETE_NOT_FINISHED（409）；版本冲突409、未知任务404。同一删除前版本重试幂等。删除任务及其专属历史，保留独立工作流执行与发送证据；不新增供模型调用的删除工具。

### 定时任务创建成员展示

任务列表返回 `creatorSenderId` 与可空 `creatorRealName`，详情的 `task` 返回原 `creator_sender_id` 与可空 `creator_real_name`。本名按任务 `chat_id`＋创建成员 `sender_id` 关联当前成员映射，不跨聊天匹配，不使用昵称替代本名。映射新增、修改或删除后，下一次读取即可反映；无映射或未配置本名时返回 null，Web 回退展示原成员标识。有本名时列表与详情以本名为主、原标识为辅助，便于区分同名成员。

此字段仅补充展示，不改变任务归属、成员工具授权或已有执行快照；无需数据库迁移和任务重建，旧任务同样生效。

Web 审计事件列表每页请求 10 条，沿用不透明 cursor 分页及敏感读取要求；不改变服务端默认值或最大页容量。调度与容量设置中的“暂停调度”使用拨动开关，仍需敏感解锁并保存后生效，关闭未保存表单不提交。

## 启动关闭元数据

执行列表及详情响应增加可选 `startupClosure`（未自动关闭时为 `null`）：`runId` 为本次扫描 UUID，`reasonCode` 为 `WORKFLOW_PROCESS_INTERRUPTED`，`reason` 为可展示说明，`previousStatus` 为原执行状态，`closedAt` 为带时区的关闭时间。Web 详情展示“启动时自动关闭”，与人工关闭区分；现有状态枚举保持不变。未知投递筛选／运行统计仍包含启动自动关闭但投递未核实的执行。

审计新增系统事件 `execution.startup-close`（逐条记录原状态、扫描边界和原因）及 `execution.startup-scan`（扫描／关闭／移交／中断节点／未知投递数量），使用共同 `correlation_id`，不写聊天正文、模型提示词或凭据。不新增公共操作接口或环境变量。

### Agent 运行状态的消息角色

`AiRouteRequest.executionTime` 为内部任务起始时间快照（聊天时区偏移的 ISO 8601），不作为供应商顶层字段发送。Agent 在每轮请求末尾以 `user` 角色发送一份 `agent_budget_status` JSON，其中 `currentTime` 可选，预算数值和收尾原因反映当前状态；固定解释与权限规则保留在 system。无当前消息的空闲／定时任务不伪造用户请求，运行状态也不提供操作授权。无公共 API、数据库、环境变量或配置迁移，既有预算审计字段及工具调用配对保持兼容。


### 定时任务委托说明与默认列表

创建工具必填 `requestSnapshot`，由模型综合本次委托相关的多轮交流，整理创建者已明确确认的目的、要求、时间及澄清，不只复制最后一句确认，不引入无关聊天、他人请求或推测授权。它是委托说明而非逐字原文；实际执行仍以 `content` 和结构化 `schedule` 为准。缺失、null、空白或超长时返回 `TASK_ARGUMENTS_INVALID` 及字段诊断，不退回截取最后消息。

复用数据库 `request_snapshot`，来源消息、来源执行、聊天、工作流及创建者仍由程序绑定，不由模型传参。创建后该说明保持不变，update 工具和 PATCH 不接受 `requestSnapshot`；旧记录继续显示已有快照，不自动生成或覆盖。字段只在原有敏感保护的详情及受理事件快照中提供，不加入普通列表或日志。无数据库迁移、环境变量或新增接口。

任务列表固定按 `created_at DESC, id DESC` 排序，Web 默认筛选 `pending`，仍可切换全部或其他状态；API 和模型列表工具未传状态时仍查询所有状态，调度器按到期时间领取的顺序不变。

### 已授权插件工具自动同步

`PUT /api/v1/plugins/:id/config` 增加可选布尔值 `autoSyncTools`。旧配置缺省关闭；请求省略时保留当前设置。沿用敏感授权、`expectedVersion` 并发控制及 `plugin.configure` 审计。插件详情返回 `pendingReview`、`toolSyncLastCheck` 和最近十条状态变化 `toolSyncHistory`，记录检查来源、时间、状态、字段路径和新旧合同指纹，不保存凭据、原始响应或聊天内容。后台以 `plugin.tools.sync` 系统审计记录自动更新、待审核和失败状态变化；相同待审核结果不重复生成审计。

每分钟扫描一次已启用插件，到距上次检查一小时才执行远程工具发现；未启用自动同步的插件不发起后台连接。新开启且无检查记录者在下一扫描周期开始。调用前发现变化也检查，但不重放实际工具调用。只同步已有授权且未停用的工具，不批准新工具、不改连接或工作流绑定。支持规范化 JSON 对象字段顺序与工具说明首尾空白；保留数组顺序、Schema 字面值和实质说明。无开关也允许这种无语义格式差异，旧原始 hash 不会单独导致拦截。

自动接收的输入扩展限于封闭、简单 object Schema 新增可选属性，已有字段、required、其余约束和输出合同必须保持一致；`$schema` 必须不变。含组合、引用、条件等复杂约束或原本允许额外字段的 Schema 不推断兼容性。实质描述变更、新增必填、删除/改类型、输出合同和附件传输能力变化均待审核。未能判断的变化不自动批准。

同步使用 PostgreSQL 每插件 advisory lock 和事务内插件版本复核；管理员在发现期间保存、停用或回滚时丢弃旧结果。工具定义、指纹、记录及版本原子更新，新任务使用新快照；进行中任务仍按旧快照校验参数与输出，仅当新合同仍兼容且授权仍有效才继续，撤权仍阻断。发现失败保持既有授权与配置，同步状态提示检查失败；不把发现失败视为自动执行许可。待审核工具不影响其他工具；已记录不兼容差异的工具在新任务中不注册，同一任务遇到不兼容后不反复访问该远端工具。管理员重新发现并授权，或后续同步确认恢复兼容，才能解除。

本次复用加密插件配置与版本 metadata，无数据库迁移、无环境变量。自动同步开关不随插件包升级自动开启，插件更新仍沿用原来的显式授权流程。

### 工具图片合同

新增 OpenSandbox MCP `view_image({path})`，仅接受当前会话 `/workspace` 下普通 PNG/JPEG/WebP/GIF 文件；返回标准 `text` 与 `image` 块，图片数据不放入 `structuredContent`。不新增公共 HTTP API、环境变量、工作流开关或数据库迁移；不改变附件目标原有四个必需工具。

沙箱预览限制为原文件 20 MiB、4000 万像素、长边 2048、编码 512 KiB；只取首帧，必要时 PNG 转 JPEG 并记录白色背景处理。通用命令输出仍限 1 MiB。BP 工具图片继续受现有 `enabled/maxImageBytes/maxTotalImages/maxTotalBytes` 及 Agent 剩余输出/耗时限制，传输响应上限仍为 30 MiB；工具图片候选及后续请求额外按 64 MiB 的序列化消息大小保守预检。全部工具图片标签计入输出字符额度。

工具诊断的 `images[]` 保存块位置、图片引用、`imageInputId`、哈希、MIME、尺寸、字节数、处理时长和 `prepared/committed/already-in-context/omitted` 状态；`omitted` 附带原因。实际携图发送仍以 AI 调用 `diagnostics.imageInputs` 为准。不存在对应图片归档记录的工具图片不提供重读接口，管理页只展示元数据及调用结果关联。

### 沙箱文件附件回复

内置 `prepare_chat_attachment({path})` 只有一个必填字符串参数，仅在普通消息触发、AI文本输出、显式 `imageReply` 绑定和插件授权均满足时提供。`imageReply.allowedTypes`可选，缺省只允许PNG；显式值为不重复的非空数组，可选`png/jpeg/gif/pdf/xlsx/csv/txt/md/zip`。旧字段名和`generatedImage`端口保留以兼容已发布版本，界面显示“附件回复”。

路径限制当前沙箱`/workspace`。图片最多8 MiB、1600万像素、单边8192；其他文件最多20 MiB。ZIP/XLSX最多200项、展开50 MiB，拒绝越界、加密、链接、CRC损坏，XLSX核心XML分别最多1 MiB并检查类型、拒绝宏；PDF检查头尾标记，文本必须UTF-8且无二进制控制字符。文件名取路径末段，限制160字符/240字节且不含控制字符、双向覆盖或分隔符。MIME由服务端决定。详见[文件附件方案](技术方案-沙箱文件附件回复.md)。

成功返回本轮 `attachment_ref`、filename、mime_type、可选尺寸、bytes和`delivery=pending_reply_node`，不返回文件字节或宿主路径/下载URL。准备不自动看图，不增加默认工具预算；同路径新内容重新读取，同运行同哈希/名称/类型复用，跨运行不能复用引用。每轮只选择一个附件，失败清除旧选择；最终Reply才发送。

OpenSandbox适配器0.4.0新增`io.bubblepilot/file-export` v1，与已认证MCP会话绑定的`/mcp/file-exports/tickets`和`/mcp/file-exports`使用单次30秒票据导出；原PNG协议和路径继续服务旧能力。保存授权含`fileExportVersion`才可配置其他类型，并复核实时能力。`GET /api/v1/plugins/image-export-targets`保留路径，返回已批准目标及`fileTypes`，不会自动启用工作流。

`GET /api/v1/executions/{executionId}/generated-images`保留路径，返回filename、mimeType、fileType、可空宽高、大小和投递状态；内容接口需要敏感解锁并审计、复核归属/期限/哈希，按真实MIME和安全文件名返回`Content-Disposition: attachment`、`private, no-store`与`nosniff`。文档不在页面执行或内联渲染，图片可通过受保护下载结果预览；不存在或过期返回404。存储、清理沿用`GENERATED_IMAGE_*`配置，目录包括新`.file`与历史`.png`。

纯附件收尾由可信Agent产物选择开启内部空文字许可，不向Provider发送新参数。Chat Completions需要明确stop且存在字符串content，Responses需要completed且存在明确文字输出项；空对象、缺少消息、过滤/失败状态不能借此成为成功结果。普通文字回复空输出保护不变。

### 传输能力锚定与生图插件（多目标）

MCP 服务在 `experimental` 中声明 `io.bubblepilot/attachments`、`io.bubblepilot/image-export`、`io.bubblepilot/file-export` v1 时，可附加 `anchorTool` 与 `workspacePrefix`（附件协议另可附加 `mimeTypes`）：

| 字段 | 规则 |
| --- | --- |
| 未声明 `anchorTool` | 沙箱：锚定 `prepare_sandbox`，工作区 `/workspace/`，图片回复仍要求 `prepare_sandbox`＋`run_command`，附件导入要求四个沙箱工具；不得同时声明 `workspacePrefix`／`mimeTypes` |
| `anchorTool` | 生成器：工具名 1～64 字符，不能是 `prepare_sandbox`；能力只挂在该工具上，随其批准持久化 |
| `workspacePrefix` | 生成器必填，形如 `/workspace/<小写名>/`；同一锚定工具的各协议必须一致 |
| `mimeTypes` | 仅附件协议、仅生成器，取值 `image/png`、`image/jpeg`、`image/webp` 的非空不重复子集 |

格式非法的声明按不支持处理（fail closed）。生成器的 `workspacePrefix` 与 `mimeTypes` 纳入工具合同哈希，变化须重新审阅；沙箱的既有哈希不变。目标列表接口（`image-export-targets`、`attachment-targets`）增加 `kind`、`anchorTool`、`workspacePrefix`，附件目标在生成器上另返回 `mimeTypes`。

AI 节点新增可选 `imageGeneration={enabled,pluginId,server}`，缺省关闭。启用要求文本输出、插件在 `pluginIds` 中、目标为同时具备附件导入和 PNG 导出能力的生成器，且不能与已启用的 `imageReply`／`attachmentHandling` 为同一插件服务。`imageReply` 与 `attachmentHandling` 只接受沙箱目标。任一 `imageReply`／`imageGeneration` 启用时，`generatedImage` 端口须恰好连接一个 Reply 节点。发布时校验生成器的实时能力与锚定工具批准状态；工作流导出移除该绑定并给出 `IMAGE_GENERATION_REBIND_REQUIRED` 警告。

- `import_chat_attachment`：同时绑定两类目标时增加可选 `target`（`sandbox` 缺省、`image_generator`）；只有生成器时不暴露该字段。生成器只接受 PNG、JPEG、WebP 原件；HEIC／HEIF 以 `original=false` 下载网关的 JPEG 版本，文件名改为 `.jpeg`，SHA-256 与大小按转换后字节计算，结果带 `converted: "gateway-jpeg"`。其他类型在下载前返回 `ATTACHMENT_TYPE_UNSUPPORTED_FOR_TARGET`。同一附件可分别导入两个目标，共享单次运行的文件数与字节上限；只有生成器时使用附件限额缺省值。沙箱导入下载原件；文件名为 HEIC／HEIF 的照片同样以网关 JPEG 版本导入。两种目标下，名称为 JPEG／PNG／WebP 但网关原件实际是 HEIF 容器（按 `ftyp` 品牌识别，常见于 iPhone 照片）时，丢弃原件并改用 `original=false` 的 JPEG 版本，结果同样带 `converted: "gateway-jpeg"`；真正的 JPEG／PNG／WebP 仍只下载一次原件。
- `prepare_chat_attachment`：按路径最长前缀路由到所属目标；生成器路径只允许 PNG。产物记录实际来源插件与服务。
- 只绑定沙箱时，模型指引与工具定义字节不变；绑定生成器后才追加生成器指引。
- 执行诊断：只有一个目标时，导入调用的请求诊断沿用该目标的插件与服务；绑定多个目标时请求诊断只列出 `targets`，实际去向以每次调用的返回诊断（`target`、`pluginId`、`server`）为准，执行详情按实际目标显示“图片导入（生图）”或“附件导入”。

无数据库迁移、环境变量或公共 API 新路由。

## 执行耗时概览

执行列表 `GET /api/v1/executions` 增量返回 `calledModels: string[]`：使用本执行关联 Provider Attempt 的模型名快照（含失败、重试和降级），按模型名精确去重、首次 Attempt 记录时间升序展示，同时间按模型名稳定排序。同名模型跨 Provider 只显示一次；未产生记录返回空数组，运行中的尚未落库请求在后续刷新时出现。不读取当前 Provider 配置、不推测独立后台摘要的归属。Web 在聊天与回复缓存命中之间增加“调用模型”列，纵向显示，无记录或旧接口缺字段显示“—”，长名称换行，窄屏保持表格横向滚动。仅按当前页执行 ID 批量查询模型字段，沿用管理员权限，无数据库迁移。


`GET /api/v1/executions` 和执行详情增加只读 `timing`：`observedAt` 为统计观察时间，`totalMs` 为开始执行到完成的实际历时；运行／等待重试时计算到观察时间，前端标为“已运行”／“重试中·已历时”，数值随刷新更新，不假装持续实时追踪。`totalState` 为 `finished|running|retrying|unavailable`，`unavailableReason` 为 `closed|missing|null`。人工关闭或启动关闭记录不将关闭时间视为完成时间；时间缺失、倒置时返回 null，不回退到创建时间，不统计执行前串行排队。

`categories` 分为 `model`（本执行直接关联的全部 Provider 尝试，含失败／降级）、`tools`（本执行工具调用）、`delivery`（reply 节点）和 `otherNodes`（排除 ai-chat 与 reply 的其他节点）。每项返回 `durationMs`、`count`、`recordedCount`；无有效耗时返回 null，真实零值保留 0，未结束节点及启动清理给中断节点人工补记的耗时不计入累计值。独立后台图片／表情摘要没有本执行关联，不强行归属；不把路由轨迹或 AI 节点总耗时叠加到模型调用上。分项可能嵌套／重叠，禁止当作互斥占比或用总耗时减分项制造“其他耗时”。总历时可能包含重试等待，回复节点耗时不表示客户端已收到。列表按当前页 ID 批量聚合，不返回参数、正文、原始响应或凭据，沿用原管理员权限，无数据库迁移。

## 沙箱命令失败与工具审计（0.6.1 插件／0.4.1 适配器）

`run_command` 工作目录为 Linux `/workspace`，参数说明要求文件及脚本路径使用 `/workspace/…` 绝对路径；导入附件使用实际返回的 `sandbox_path`。`bp-render-svg` 帮助与 `svg_path_denied` 返回相同的路径规则及短示例，路径边界和 no-follow 检查不放宽。

适配器按 execd 前台执行事件判定：正常完成为 `completed`；`CommandExecError` + 1–255 的明确非零退出码并且流正常结束，可返回 `command_failed`，不因缺少 `execution_complete` 清理沙箱。任意错误、负退出码、断流、取消、超时及超限仍按未知或失效处理，不自动重放。普通 MCP 工具回执增加 `sessionUsable`；只有明确失败且会话仍可用时才建议检查原因后安全修正，非零退出并不保证前序步骤无副作用。

插件审计增加受控 `remoteStatus`、`exitCode`、`failureReason`（固定枚举，如 `svg_path_denied`），不记录命令、路径、stdout/stderr 或任意错误文本。模型继续收到受预算约束的实际工具结果；长结果分段后保留失败状态和修正指引。内置 metadata-only 工具的 `failed/error` 均记录为失败，`prepare_chat_attachment` 只有 `prepared` 才成功，失败无投递选择，`resultCount` 为 null；安全错误码保留，任意字符串不进入错误码。详情显示已知分类和退出码，历史误标记录不反推或批量改写。

通用插件系统指引不绑定网页搜索；文件回复系统指引只描述最终产物与投递合同。场景教程位于沙箱 Skill 的按需参考文件（绘图、附件、网络环境），不每轮自动展开。没有数据库迁移、新增环境变量或权限放宽。

`view_image` 同样返回 `sessionUsable`；已确认的路径、图片格式或尺寸问题，只有会话明确可用时才允许按剩余预算修正后重新预览。依赖缺失、未知结果、超时及失效会话不自动重试。PNG 渲染的 `png_too_large`、`png_dimensions_invalid` 纳入受控审计原因及中文展示。

### 执行触发消息查看

执行列表与详情仅增加可空 `sourceMessageId` 元数据，不自动包含归档正文。`GET /api/v1/executions/:executionId/source-message` 需要管理员登录与敏感授权，按执行的来源消息关联查询（旧记录可通过入站事件关联恢复），不接受调用者指定其他消息。返回当前归档的时间、发送者、正文、修订状态、编辑时间、撤回留存正文和附件文件名/MIME/大小，不含原始 Webhook、附件下载地址或凭据。

归档消息已删除、内容已清理、聊天停用、无来源关联或调度执行时返回 404；慢查询结束后复核敏感授权。响应 `Cache-Control: private, no-store`，沿用 `message.content.view` 审计，目标为执行 ID。此接口不是触发时不可变快照，不新增正文副本或数据库迁移。

详情弹窗顶部默认遮蔽触发消息，解锁后仍需点击眼睛才请求正文；隐藏、关闭、切换执行或授权过期时清空，迟到响应不能重新显示。当前归档可能经过编辑或撤回，界面明确标记；附件仅展示元数据。

### GIF 直接附件回复（0075）

`allowedTypes` 新增 `gif`，缺省和旧显式列表保持不变；需要已批准的 file-export v1，PNG-only 能力不能导出 GIF。GIF 原样保存和发送，服务端推导 `image/gif`，文件名保留 `.gif`；数据库 width/height 表示逻辑画布单帧尺寸，不是多帧拼接高度。

沿用图片 8 MiB、单边 8192、单帧 1600 万像素，另限制最多 200 帧、画布像素×帧数最多 6400 万。先检查 GIF 签名、颜色表、块边界、帧矩形、结束标记，再完整解码所有帧；拒绝截断、伪装和超限，不转码或丢帧。错误 `IMAGE_ANIMATION_LIMIT` 表示帧数/累计像素超限，`IMAGE_PIXELS_EXCEEDED` 表示画布超限，`IMAGE_INVALID` 表示损坏，`FILE_TYPE_NOT_AUTHORIZED` 表示节点未授权；模型可见代码及准备失败反馈。

下载/审计预览沿用敏感授权与 no-store；管理台以原始 GIF 预览动画，模型 `view_image` 依然只得到首帧。无新环境变量或公共 API，0075 仅扩展类型/MIME/尺寸约束；不新增适配器协议。


### 0081 Embedding 请求超时配置

`memory_settings` 新增 `request_timeout_seconds`（整数 5～120，默认 15，即原固定值）。`PUT /api/v1/ai/memory/settings` 与测试连接接受可选 `timeoutSeconds`，省略时保留已保存值；`GET` 返回 `timeoutSeconds`。该值用于索引批量请求、测试连接和查询向量（查询仍取其与工具剩余时间的较小值）；Ollama 模型身份查询沿用原短超时。超时不属于索引代次配置：修改不会新建代次或触发重建。只改超时（模型配置与启用状态不变、未提交新凭据）时保存不探测服务，因此服务故障期间也能调整。无新增环境变量。

### 0080 向量服务失败可观测性

`memory_jobs` 新增可空 `error_detail JSONB`（仅允许对象），字段见上文长期检索状态错误说明及 OpenAPI `MemoryJobStatus`。索引、检索降级和测试连接失败时，应用日志写一条 `Memory embedding failure` 警告，包含 `operation`（index／search／probe）、错误码、模型名、服务主机名、`jobId`（索引时）和同一份脱敏 `detail`；不含基址路径、密钥、输入文本或响应正文。模型收到的检索警告不变。无新增环境变量、API 路由或配置开关。

### 0079 引用读取范围与附件元数据

仅替换数据库函数：新增 `chat_history_authorized(chat)`（全局记忆启用且该聊天已授权）并重写 `message_reply_preview`，无表结构或数据变化。模型侧引用的下界：聊天已授权长期历史时为 0（全部早于触发的已归档消息），否则沿用本次上下文窗口下界；上界不变。触发消息、`raw-context-v2` 与旧上下文三条路径采用同一判断。`reply_to` 新增可选 `sent_at`、`attachments`、`attachment_count`（见 `contracts/message-envelope.schema.json`），模型投影中 `sent_at` 按聊天时区输出。被引用目标含附件时状态为 `available`（此前引用附件部分返回 `unresolved`）；引用非文本部分且目标无附件仍为 `unresolved`。

附件处理节点的初始附件目录在被引用消息满足同聊天、早于触发、未清理、`revision_state='active'` 且含附件时，将其列为历史首项并标记 `quoted=true`；目录条目字段不变，`attachment_ref` 签发仍经历史附件授权。工具参数、HTTP API 路由、工作流 Schema 与环境变量均不变。

### 0077 执行历史范围

新普通消息执行的 `contextSnapshot.contract` 可为 `raw-context-v2`，保留原字段并增加 `historyUpperIndex`（首次读取时已提交归档的独占上界）、`historyBeforeSentAt`（触发消息发送时间，保留数据库精度）和 `messageIds`（有界原文窗口成员 ID，无正文）。`triggerMessageIndex` 仍表示触发消息自身索引，不再同时表示归档可见上界。旧 `raw-context-v1`、空闲和定时任务兼容保留。模型工具参数不变，时间及归档边界只能由服务端确定；同时间消息以入库序号稳定排序，触发消息不重复进入历史。没有新增 API、配置开关或环境变量。

聊天图片方向校正不新增配置或 API 路由。图片诊断 `processingVersion` 新增 `bluebubbles-compatible-exif-v2`；兼容旧值 `bluebubbles-compatible-original-false`。新记录的字节数、内容哈希及宽高均对应 EXIF 校正后实际发送图片，预览继续敏感认证、来源复核和哈希校验。图片处理新增内部错误码 `AI_IMAGE_ORIENTATION_FAILED`（校正失败）和 `AI_IMAGE_ORIENTATION_UNSUPPORTED`（带方向标记的多帧图片）；校正后超限沿用 `AI_IMAGE_TOO_LARGE`，累计体积沿用现有限额，不发送未校正原图作为降级。
