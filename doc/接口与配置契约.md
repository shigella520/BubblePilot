# BubblePilot 接口与配置契约

## 1. 契约分层

机器可校验的契约放在 `contracts/`，解释性约束放在本文档和相关设计文档中：

```text
contracts/
├── openapi.yaml                    # 健康检查、Webhook、配置与查询 API
├── bluebubbles-webhook.schema.json # BlueBubbles new-message 原始 Payload
├── message-envelope.schema.json    # 规范化后的内部消息信封
└── workflow.schema.json            # M3 工作流定义
```

完整请求、响应和参数定义以 `contracts/openapi.yaml` 为准。查询接口使用不透明 `cursor` 和 `limit`，`limit` 范围为 1-100。错误响应包含机器可读 `code`、用户可读 `message` 和 UUID 格式的 `correlationId`。

管理 API 同时支持高熵 `API_ACCESS_TOKEN` 与服务端管理会话。Bearer Token 面向受控自动化，视为已经具备管理权限；浏览器 Cookie 会话访问敏感接口时必须具有当前会话绑定且未过期的二次验证授权。Cookie 使用 `HttpOnly`、`SameSite=Strict` 和根路径，是否增加 `Secure` 由 `SESSION_COOKIE_SECURE` 决定，默认按请求协议自动判断。服务端只保存随机会话 Token 的 SHA-256，不保存 Cookie 原文。Web 管理端使用会话响应中的绝对时间主动刷新授权状态；二次授权到期会清空已加载的消息结果并遮蔽正文，会话到期会返回登录页，但这些界面行为不替代服务端逐请求校验。

管理 API 与 Webhook 分别应用有界固定窗口限流，超过上限返回 `429 RATE_LIMITED`。工作流并发和等待队列达到上限时返回 `503 WORKFLOW_QUEUE_FULL`，等待容量超时返回 `503 WORKFLOW_QUEUE_WAIT_TIMEOUT`；调用方只能按退避策略重试，不能绕过边界并发重放。

消息列表、搜索结果和 JSON Lines 导出中的 `contentRedactedAt` 用于区分“原消息没有正文”和“正文、附件元数据已经按保留策略清理”。内容被清理后 `body` 为 `null`、`attachments` 为空数组，必要元数据与关联执行仍可查询。

## 3. Webhook 约定

- BlueBubbles 配置 URL 使用 `/api/v1/webhooks/bluebubbles?token=<secret>`。
- 支持自定义请求头的调用方可以改用 `X-BubblePilot-Webhook-Secret`。
- 共享密钥至少 32 个字符，使用常量时间比较。
- 当前实现处理 `new-message`；其他合法事件以 `ignored` 状态进入幂等事件表。
- `new-message` 没有独立事件 ID，因此稳定事件键为 `new-message:<message-guid>`。
- Webhook 返回 `202`，接入状态为 `archived`、`ignored` 或 `duplicate`，同时返回 `automationOutcome`。自动化判定可为 `unsupported-event`、`chat-not-monitored`、`evaluation-pending`、`not-evaluated`、`no-active-triggers`、`no-trigger-match` 或 `matched`。
- 消息归档后、工作流最终判定前使用 `evaluation-pending`。调度容量不足返回 `503` 时保留该状态，BlueBubbles 重投同一事件会恢复匹配；执行和回复幂等键阻止重复副作用。
- 除 `evaluation-pending` 外，同一事件重复投递不产生第二条消息或工作流执行，只返回首次处理保存的自动化判定；历史 `not-evaluated` 不会使用当前配置补跑。监听范围之外的聊天只保留必要聊天元数据，不保存消息正文。
- `GET /api/v1/inbound-events` 只返回事件 ID、关联 ID、事件类型、接入状态、自动化判定和接收时间等安全元数据，不返回消息正文、原始 Webhook、Payload 哈希、Prompt 或凭据。
- 默认请求日志关闭，查询密钥、原始 URL 和完整 Payload 不进入普通日志。

## 4. 受控数据导出

导出采用“冻结预览 → 二次验证 → 显式确认 → 短时下载”的服务端流程：

1. 每个任务只允许选择一个当前启用监听的聊天、明确的起止时间以及消息、执行摘要中的至少一种；时间范围最长 31 天。
2. 预览在服务端记录 `snapshotAt`、各类型数量和预估大小，最多 10,000 条且预估不超过 25 MB；预览 5 分钟内有效。
3. 确认请求必须原样提交预览返回的 `expectedRecordCount` 和 `expectedSnapshotAt`，避免用户确认过期或不一致的范围；确认后下载窗口为 10 分钟。
4. 服务端不写入临时正文文件，而是按已冻结的 `snapshotAt` 动态生成 JSON Lines。第一行为 `manifest`，后续每行是一个 `message` 或 `execution` 对象。
5. 任务按当前管理会话或 API Token 所有者隔离；下载时再次检查聊天仍处于监听状态。停用聊天、任务撤销、过期、快照数量不一致都会阻止下载。

导出只包含所选消息字段和执行摘要，不包含 AI Key、Secret 值、`secretRef`、完整 Prompt、节点输入输出、原始 Webhook Payload、错误详情或未选择的数据类型。预览、确认、下载和取消分别写入 `data.export.preview`、`data.export.create`、`data.export.download` 和 `data.export.cancel` 审计事件。失败与拒绝同样保留结果和 `correlationId`，审计元数据不保存正文。

## 5. 工作流契约

工作流定义必须包含：

- `schemaVersion`；
- 唯一节点 ID；
- 节点类型和节点版本；
- 节点配置；
- 合法的边引用和结束节点；
- 超时、重试和资源上限；
- 发布版本和创建来源。

人工恢复继续使用原执行锁定的消息、Trigger 和 Workflow Version。新执行通过 `retryOfExecutionId` 与 `recoveryAttempt` 关联原链路，并获得新的 `correlationId`、节点尝试和出站幂等键。`failed`、`dead-lettered` 和超过 `STALE_RETRY_SECONDS` 的 `retrying` 可以恢复；尚未逾期的计划重试返回 `409 EXECUTION_RETRY_STILL_ACTIVE`。源执行存在 `sending`、`unknown` 或 `confirmed` 出站记录时，恢复接口返回 `409`，防止把结果未知或已经成功的回复再次发送。执行详情、人工恢复成功和人工关闭成功使用同一个完整脱敏详情模型，均包含节点、Provider Attempt 与出站轨迹，避免管理端在状态切换后丢失解释上下文。

已发布定义不可原地修改；编辑通过版本创建接口生成新的已校验候选版本。发布新版本时，绑定旧发布版本的触发器在同一数据库事务中切换到新版本；已经创建的执行继续引用启动时锁定的版本。

工作流紧急停用只把工作流状态切换为 `inactive`，因此所有关联触发器停止创建新执行，但触发器自身的启停配置和已开始执行保持不变。重新启用要求已有发布版本，不追溯处理停用期间收到的消息。工作流和单个触发器启停要求登录并审计，不要求额外二次验证。

当前注册 `condition@1`、`log@1`、`set-variable@1`、`load-context@1`、`ai-chat@1`、`reply@1` 和 `end@1`。工作流发布前会校验节点配置、唯一 ID、边引用、不可达节点、环路、正则、资源上限及 AI 路由可用性。触发器支持聊天、发送者、消息类型、关键词、前缀、正则和时间窗口的 AND 组合。

时间窗口使用 `timeZone`、`daysOfWeek`、`start` 和 `end`；时区必须是有效 IANA 名称，时间为 24 小时制 `HH:mm`，起点包含而终点不包含，起止不能相同。跨午夜时 `daysOfWeek` 表示起始日。运行匹配使用消息的 `sentAt`；预览可以显式提交 `sample.sentAt`，并在 `checks` 中返回 `timeWindow` 结果。

`GET /api/v1/triggers` 为每个触发器返回 `conflictingTriggerIds`。该字段只包含当前工作流和发布版本均活动的启用触发器之间的潜在重叠，用于在配置端提示可能的重复回复；它不是运行时匹配结果，也不会阻止启用。分析会排除可静态证明不相交的条件，对正则和跨时区等无法可靠证明互斥的组合保守提示。

生产触发器固定拒绝 `isFromMe` 消息；只有后续实现可持久化的循环预算后才开放自触发配置，预览接口可单独检查该条件。

AI 节点通过 `providerRouteId` 引用版本化路由。Provider、路由和健康管理 API 已实现以下行为，最终路径和字段以 OpenAPI 与 JSON Schema 为准：

- 新增、编辑、启停、删除、排序和连通性测试多个 AI Provider；
- 配置 Chat Completions 或 Responses 接口类型、服务地址、模型、参数、单请求超时和只写 Secret；
- 配置 `capabilities.functionCalling` 与 `capabilities.hostedWebSearch`；连通性测试在声明托管搜索时额外执行搜索能力探测，并返回 `capabilityProbe`；
- `ai-chat` 节点配置 `webSearch` 为 `disabled`、`auto` 或 `required`；实例 `ENABLE_WEB_SEARCH=false` 时后两者均被拒绝；
- 配置有序候选、Fallback、Node Retry、降级阈值和冷却时间；
- 查询固定配置顺序、当前有效顺序、健康状态和最近一次脱敏结果；
- 人工重置降级状态，并保留健康状态事件；Provider 与路由变更、测试和健康重置均记录操作者审计。

Provider 列表和详情只返回 `secretConfigured` 等元数据，不返回 API Key。Provider 直接提交只写字段 `secret`，服务端使用 `SETTINGS_ENCRYPTION_KEY` 加密保存；编辑时留空 `secret` 表示保留原值。连通性测试使用固定的非敏感测试输入，不发送归档聊天上下文、不触发生产 Fallback，也不计入生产降级统计。生产路由跳过 `secretConfigured=false` 的候选且不写入无意义 Attempt；路由视图的 `effectiveProviderIds` 复用运行时健康选择，`configuredProviderIds` 保留固定顺序，`unavailableProviderIds` 包含停用、缺少 Secret 或仍在冷却的候选。

执行详情的 AI Provider Attempt 只返回脱敏诊断摘要：`clientRequestId`、`providerRequestId`、`httpStatus`、`requestHash`、`requestMessageCount`、`requestCharacters`、`responseBytes`、`responseBodyHash`、`responseFinishReason`、可见输出/推理字符数，以及 `promptTokens`、`completionTokens`、`reasoningTokens`、`totalTokens`、`cachedPromptTokens`、`cacheWritePromptTokens` 和 `cacheMissPromptTokens`。这些字段用于把一次调用与供应商日志、空输出和缓存效果关联起来，不代表返回 Prompt 或正文；服务端不得保存完整 Prompt、历史正文、AI 输出、Secret 或原始响应体。

| `WORKFLOW_MAX_CONCURRENCY` | 否 | 普通 | `4` | 启动 | 当前进程同时运行的工作流上限 |
| `WORKFLOW_QUEUE_CAPACITY` | 否 | 普通 | `64` | 启动 | 当前进程等待执行的工作流上限，允许设为 0 |
| `WORKFLOW_QUEUE_WAIT_MS` | 否 | 普通 | `30000` | 启动 | 等待执行容量的最长时间 |
| `STALE_RETRY_SECONDS` | 否 | 普通 | `300` | 启动 | 运行状态把逾期 Retry 视为卡住并允许人工恢复的阈值 |
| `LOG_LEVEL` | 否 | 普通 | `info` | 启动 | Fastify/Pino 日志级别 |

AI Provider 的服务地址、模型和加密凭据元数据保存在数据库中，API Key 通过受保护管理 API 或 Web 页面提交后仅以密文保存。密码哈希包含 `$`，在 `.env` 中应使用单引号包裹，避免 Compose 将其解释为变量替换。

Compose 另外读取以下部署变量，它们不进入应用进程配置：

| 名称 | 是否必填 | 敏感性 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `BUBBLEPILOT_IMAGE` | 否 | 普通 | `ghcr.io/shigella520/bubblepilot:dev` | 应用镜像；验证部署可用 `dev`/`sha-*`，生产固定 `X.Y.Z` |
| `POSTGRES_DB` | 否 | 普通 | `bubblepilot` | Compose PostgreSQL 数据库名 |
| `POSTGRES_USER` | 否 | 普通 | `bubblepilot` | Compose PostgreSQL 用户 |
| `POSTGRES_PASSWORD` | 是 | Secret | 无 | Compose PostgreSQL 密码，必须与 `DATABASE_URL` 对应 |

所有 Secret 都必须在日志、诊断接口和错误响应中脱敏。`GET /api/v1/operations/status` 返回保留任务是否启用、最近运行时间、最近清理数量和稳定失败/积压告警码，不返回被清理的正文。新增、重命名或废弃环境变量时，需要在同一 PR 更新本表、`.env.example`、Compose 和回归测试。
