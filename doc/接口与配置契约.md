# BubblePilot 接口与配置契约

## 1. 契约分层

机器可校验的契约放在 `contracts/`，解释性约束放在本文档和相关设计文档中：

```text
contracts/
├── openapi.yaml                    # 健康检查、Webhook 与只读查询 API
├── bluebubbles-webhook.schema.json # BlueBubbles new-message 原始 Payload
└── message-envelope.schema.json    # 规范化后的内部消息信封
```

M2 开始实现工作流时再新增 `workflow.schema.json`，不预先维护没有实现入口的合同。

## 2. 已实现 API

| 方法与路径 | 认证 | 用途 |
| --- | --- | --- |
| `GET /health/live` | 无 | 进程存活检查 |
| `GET /health/ready` | 无 | PostgreSQL 就绪检查 |
| `POST /api/v1/webhooks/bluebubbles` | Webhook 共享密钥 | 接收和归档 BlueBubbles 事件 |
| `GET /api/v1/chats` | Bearer Token | 分页查询启用监听的聊天 |
| `GET /api/v1/chats/{chatId}/messages` | Bearer Token | 分页查询指定聊天的消息 |

完整请求、响应和参数定义以 `contracts/openapi.yaml` 为准。查询接口使用不透明 `cursor` 和 `limit`，`limit` 范围为 1-100。错误响应包含机器可读 `code`、用户可读 `message` 和 UUID 格式的 `correlationId`。

M1 的 `API_ACCESS_TOKEN` 是服务端只读 API 防护，不替代 M4 规划的登录会话、敏感操作二次验证和资源授权。

## 3. Webhook 约定

- BlueBubbles 配置 URL 使用 `/api/v1/webhooks/bluebubbles?token=<secret>`。
- 支持自定义请求头的调用方可以改用 `X-BubblePilot-Webhook-Secret`。
- 共享密钥至少 32 个字符，使用常量时间比较。
- 当前实现处理 `new-message`；其他合法事件以 `ignored` 状态进入幂等事件表。
- `new-message` 没有独立事件 ID，因此稳定事件键为 `new-message:<message-guid>`。
- Webhook 返回 `202`，响应状态为 `archived`、`ignored` 或 `duplicate`。
- 同一事件重复投递不产生第二条消息；监听范围之外的聊天只保留必要聊天元数据，不保存消息正文。
- 默认请求日志关闭，查询密钥、原始 URL 和完整 Payload 不进入普通日志。

## 4. 工作流契约

工作流定义必须包含：

- `schemaVersion`；
- 唯一节点 ID；
- 节点类型和节点版本；
- 节点配置；
- 合法的边引用和结束节点；
- 超时、重试和资源上限；
- 发布版本和创建来源。

已发布定义不可原地修改；编辑会生成草稿，发布后创建新的不可变版本。该合同从 M2 开始实现。

AI 节点从 M3 起通过 `providerRouteId` 引用版本化路由。Provider、路由和健康管理 API 必须支持以下行为，但最终路径和字段以实现时新增的 OpenAPI 与 JSON Schema 为准：

- 新增、编辑、启停、删除、排序和连通性测试多个 AI Provider；
- 配置 Chat Completions 或 Responses 接口类型、服务地址、模型、参数、单请求超时和只写 Secret；
- 配置有序候选、Fallback、Node Retry、降级阈值和冷却时间；
- 查询固定配置顺序、当前有效顺序、健康状态和最近一次脱敏结果；
- 人工重置降级状态，并保留审计记录。

Provider 列表和详情只返回 `secretConfigured` 或 `secretRef` 等元数据，不返回 API Key。连通性测试使用固定的非敏感测试输入，不发送归档聊天上下文，也不计入生产降级统计。M3 开始实现时再新增对应机器契约，不预先维护没有实现入口的 Schema。

## 5. 当前环境变量

| 名称 | 必填 | 敏感性 | 默认值 | 生效时机 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `NODE_ENV` | 否 | 普通 | `development` | 启动 | `development`、`test` 或 `production` |
| `APP_HOST` | 否 | 普通 | `0.0.0.0` | 启动 | HTTP 监听地址 |
| `APP_PORT` | 否 | 普通 | `8080` | 启动 | HTTP 监听端口 |
| `DATABASE_URL` | 是 | Secret | 无 | 启动 | PostgreSQL 连接串 |
| `API_ACCESS_TOKEN` | 是 | Secret | 无 | 启动 | M1 只读 API Bearer Token，至少 32 字符 |
| `BLUEBUBBLES_WEBHOOK_SECRET` | 是 | Secret | 无 | 启动 | Webhook 共享密钥，至少 32 字符 |
| `MONITORED_CHAT_IDS` | 否 | 敏感 | 空 | 启动 | 逗号分隔的 BlueBubbles Chat GUID；空值不归档任何消息 |
| `WEBHOOK_BODY_LIMIT_BYTES` | 否 | 普通 | `1048576` | 启动 | Webhook 最大请求体，范围 1 KiB-10 MiB |
| `LOG_LEVEL` | 否 | 普通 | `info` | 启动 | Fastify/Pino 日志级别 |

`.env.example` 中的 BlueBubbles REST、登录密码、二次验证和 AI 配置是后续里程碑的保留项，M1 运行时尚不读取。

Compose 另外读取以下部署变量，它们不进入应用进程配置：

| 名称 | 是否必填 | 敏感性 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `BUBBLEPILOT_IMAGE` | 否 | 普通 | `ghcr.io/shigella520/bubblepilot:dev` | 应用镜像；验证部署可用 `dev`/`sha-*`，生产固定 `X.Y.Z` |
| `POSTGRES_DB` | 否 | 普通 | `bubblepilot` | Compose PostgreSQL 数据库名 |
| `POSTGRES_USER` | 否 | 普通 | `bubblepilot` | Compose PostgreSQL 用户 |
| `POSTGRES_PASSWORD` | 是 | Secret | 无 | Compose PostgreSQL 密码，必须与 `DATABASE_URL` 对应 |

所有 Secret 都必须在日志、诊断接口和错误响应中脱敏。新增、重命名或废弃环境变量时，需要在同一 PR 更新本表、`.env.example`、Compose 和回归测试。
