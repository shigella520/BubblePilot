# BubblePilot 接口与配置契约

## 权威来源

本文解释接口边界，不重复抄写每个请求字段。机器可校验合同是：

| 文件                                                                                        | 权威内容                          |
| ------------------------------------------------------------------------------------------- | --------------------------------- |
| [`contracts/openapi.yaml`](../contracts/openapi.yaml)                                       | HTTP 路径、认证、参数、请求和响应 |
| [`contracts/bluebubbles-webhook.schema.json`](../contracts/bluebubbles-webhook.schema.json) | BlueBubbles 原始 Webhook          |
| [`contracts/message-envelope.schema.json`](../contracts/message-envelope.schema.json)       | 统一消息信封                      |
| [`contracts/workflow.schema.json`](../contracts/workflow.schema.json)                       | 可发布工作流图                    |

`GET /api/v1/workflows/schema` 另外提供面向 AI 和跨实例传输的 `BubblePilotWorkflow bubblepilot.io/v1` 清单 Schema；它包装运行时工作流图并用逻辑 Binding 隔离实例资源。运行时 Zod/图语义校验仍是最终发布权威，合同测试负责防止公开 Schema、节点注册表和运行时实现漂移。

运行时路由、OpenAPI、环境变量和 Schema 由 `pnpm contracts:check` 交叉检查。

## API 分区与认证

| 分区                    | 入口示例                                                                                                                         | 认证                                                  |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 健康检查                | `/health/live`、`/health/ready`                                                                                                  | 无                                                    |
| Web 登录                | `/api/v1/auth/session`、`/api/v1/auth/sensitive`                                                                                 | 登录密码或当前管理会话                                |
| BlueBubbles Webhook     | `/api/v1/webhooks/bluebubbles`                                                                                                   | 查询参数 Token 或 `X-BubblePilot-Webhook-Secret`      |
| 消息与监听              | `/api/v1/chats`、`/api/v1/chats/{chatId}/participants`、`/api/v1/messages/search`、`/api/v1/chat-monitoring`                     | 管理会话或 Bearer；正文、成员映射和监听变更需二次验证 |
| 工作流与触发器          | `/api/v1/workflows`、`/api/v1/triggers`                                                                                          | 管理会话或 Bearer                                     |
| AI Provider、路由与工具 | `/api/v1/ai/providers`、`/api/v1/ai/routes`、`/api/v1/ai/usage`、`/api/v1/ai/search/settings`、`/api/v1/ai/image-input/settings` | 管理会话或 Bearer                                     |
| 执行与运行状态          | `/api/v1/executions`、`/api/v1/operations/status`                                                                                | 管理会话或 Bearer；人工恢复需二次验证                 |
| 审计与导出              | `/api/v1/audit-events`、`/api/v1/exports`                                                                                        | 管理会话或 Bearer；敏感读取、确认和下载需二次验证     |
| BlueBubbles 设置        | `/api/v1/integrations/bluebubbles`                                                                                               | 查询需登录，修改和测试需二次验证                      |

浏览器使用服务端管理会话。Cookie 为 `HttpOnly`、`SameSite=Strict`，`SESSION_COOKIE_SECURE=auto` 时按 HTTPS/反向代理协议决定 `Secure`；数据库只保存随机会话 Token 的 SHA-256。二次授权绑定当前会话并短时有效，前端到期收起内容不能替代服务端逐请求校验。

`API_ACCESS_TOKEN` 是兼容受控自动化的高熵 Bearer Token，视为已经具备实例管理权限，应像管理员凭据一样保护。新用户操作优先使用 Web 会话，不把 Bearer Token 暴露给浏览器脚本或不可信客户端。

分页列表使用不透明 `cursor` 和 `limit`，`limit` 为 1-100。错误响应包含稳定 `code`、可读 `message` 和 UUID `correlationId`。调用方不得解析错误文案决定重试。

管理 API 与 Webhook 分别限流，超过上限返回 `429 RATE_LIMITED`。执行容量不足返回 `503 WORKFLOW_QUEUE_FULL` 或 `503 WORKFLOW_QUEUE_WAIT_TIMEOUT`；只能退避重试，不能通过并发重放绕过上限。同一工作流与聊天的后续消息属于有序串行工作，不使用容量等待超时丢弃，但仍计入有界队列容量。

## Webhook 合同

- URL：`/api/v1/webhooks/bluebubbles?token=<secret>`；Secret 至少 32 字符并使用常量时间比较。
- 当前处理 `new-message`；其他合法事件以 `ignored` 进入幂等事件表。
- 稳定事件键为 `new-message:<message-guid>`。
- 成功返回 `202`，接入状态为 `archived`、`ignored` 或 `duplicate`。
- `automationOutcome` 区分 `unsupported-event`、`chat-not-monitored`、`evaluation-pending`、`not-evaluated`、`no-active-triggers`、`no-trigger-match` 和 `matched`。
- 只有 `evaluation-pending` 允许同键重投继续调度；其他最终判定不按当前配置补跑。
- 未监听聊天只保存发现所需元数据，不保存正文。
- 入站事件查询不返回消息正文、原始 Webhook、Payload 哈希、Prompt 或凭据。

详细字段映射和供应商行为见 [BlueBubbles 集成说明](BlueBubbles集成说明.md)。

统一消息信封当前为 `schemaVersion=3`，必填 `message.linkPreview`。状态为 `not-requested|pending|available|unavailable|failed|redacted`，最多保存 4 条规范化预览；单条只包含来源、HTTP(S) URL、有限标题/摘要/站点名、图片/图标存在标志，以及可用时的公开卡片主图 URL 和来源。原始 BlueBubbles `payloadData`、网页 HTML 和媒体二进制不进入该合同。

`GET/PUT /api/v1/integrations/bluebubbles` 除连接与发送配置外，还返回或更新 `linkPreviewEnabled`、`openGraphFallbackEnabled` 和 `openGraphTimeoutMs`（1000-15000 毫秒）。它们保存在 `bluebubbles_settings`，修改仍需要二次验证和乐观版本。消息列表返回规范化 `linkPreview`、有限 `linkPreviewDiagnostics` 和 `linkPreviewFetchedAt`，便于排障；诊断不包含 URL、网页正文、聊天正文、凭据或原始响应。

## 对话成员身份合同

`GET /api/v1/chats/{chatId}/participants` 聚合该聊天历史中实际出现的非本人 sender ID，返回消息数量、最后出现时间、本名、昵称和独立映射版本。`PUT` 使用 `expectedVersion` 全量替换映射；最多 100 项，同一 sender ID 不能重复，本名或昵称至少填写一项，空数组用于清除全部映射。提交不在该聊天历史中的 ID 返回 `CHAT_PARTICIPANT_NOT_DISCOVERED`，版本过期返回 `CHAT_PARTICIPANT_IDENTITIES_CONFLICT`。

两个接口都需要二次验证并写入 `chat.participants.view` 或 `chat.participants.update` 审计。审计只保存动作、聊天 ID、结果和 HTTP 状态，不保存本名、昵称或请求正文。映射按聊天隔离；运行时只能按本次加载历史和当前消息中的 sender ID 定向解析，不能读取整张成员表注入 AI。

## 工作流与 AI 合同

已发布工作流版本不可原地修改。编辑会创建新的已校验候选版本；发布和切换在事务中完成，已开始执行继续引用原版本。生产触发器拒绝 `isFromMe`，冲突提示只表示潜在重叠，不阻止启用。

### AI Friendly 清单与导入导出

工作流列表可复制 JSON Schema、AI 编写指南、Binding Catalog 和标准提示词，也可上传或粘贴 `*.bubblepilot-workflow.json`。清单的 `spec` 只描述图逻辑，`bindings` 以 `providerRouteRef`、`summaryProviderRouteRef` 和 `chatRefs` 描述外部依赖；不得包含 Secret、执行记录或消息正文。

`GET /api/v1/workflows/{workflowId}/versions/{version}/export` 默认生成 portable 清单并移除 AI Route 与 Chat 实例 ID；`mode=instance-bound` 保留绑定 ID 用于同实例备份，需二次验证，但仍不导出凭据。`GET /api/v1/workflows/binding-catalog` 只返回逻辑名称、资源 ID 和已验证能力，不返回 Provider 地址或 Secret。

导入固定分两步：`POST /api/v1/workflows/import/preview` 执行结构、图语义、模板与能力绑定校验，错误使用 RFC 6901 JSON Pointer，并签发五分钟令牌；`POST /api/v1/workflows/import` 重传 Manifest、最终绑定和令牌，服务端再次校验资源快照。提交支持 `create` 或带 `targetWorkflowId` 的 `new-version`，始终只创建 `validated` 候选版本，不自动发布或启用。提交需要二次验证并写审计，日志和审计只保存结果与哈希，不保存 Manifest 正文。

动作目录只返回可以创建且具备运行时实现的节点。`render-text@1` 使用白名单 Context Token 渲染字符串并提供 `text` 输出；`load-context@1` 提供 `messages`、`count`、当前窗口过滤后的 `participants`、`summary` 和 `summaryCoveredThroughIndex`。历史摘要默认关闭；开启时必须选择摘要 Provider Route，`compressionBatchSize` 为 1-50、默认 10，`messageLimit` 表示压缩后的基础原始窗口。批次内窗口只追加并可临时超过 `characterLimit`，但不得超过固定 32,000 字符安全上限。未知路径、未知动作输出和不完整模板语法在候选版本校验时拒绝。`set-variable@1` 只保留历史版本运行兼容，不再由动作目录返回。

AI Provider 的 `reasoningEffort` 可设为 `default|none|minimal|low|medium|high|xhigh|max`。`default` 不发送协议字段；其他值在 Responses 中映射为 `reasoning.effort`，在 Chat Completions 中映射为 `reasoning_effort`。可用等级取决于具体模型和兼容网关。该默认值适用于普通请求、Agent 工具轮次、Retry 和能力探测。图片能力探测使用全局图片输入配置的细节等级，与真实图片请求保持一致；无法读取配置时回退为 `high`，不再固定使用 `low`。

AI Provider 支持 Chat Completions 或 Responses 接口类型、Base URL、模型、参数、超时、启停、排序、Function Calling、托管搜索、原生图片输入、会话亲和和只写 `secret`。单次 Provider 请求超时可配置为 1,000-360,000 毫秒，默认 30,000 毫秒。`sessionAffinity` 默认为 `disabled`；设为 `session-id-header` 时，BubblePilot 按 Provider、BlueBubbles 聊天、工作流和 AI 节点生成不含原始标识的稳定哈希，通过 `X-Session-ID` 请求头发送，并在 Responses 请求体中把同一个值作为 `prompt_cache_key`。该值跨工作流执行、Agent 工具轮次和 Retry 保持稳定；显式会话亲和会覆盖 Provider 默认参数中的 `prompt_cache_key`。`X-Client-Request-Id` 仍按单次请求生成，不能用于替代稳定会话键。Chat Completions 不发送 Responses 专用的 `prompt_cache_key`。Secret 使用 `SETTINGS_ENCRYPTION_KEY` 加密；编辑时省略 Secret 表示保留原值，任何读接口都不回显。

`GET /api/v1/ai/usage` 只返回 Provider 级聚合数据。`hours` 仅接受 1/6/12/24/48，`timeZone` 使用 IANA 时区并决定今日、ISO 周和本月边界。响应同时包含长周期汇总、补齐空桶的实时序列和缓存统计覆盖率。`cachedPromptTokens=null` 表示 Provider 没有可统计缓存数据，与明确返回 0 不同。该接口不返回消息正文、Prompt、会话键或 Secret。

连通性测试分别返回基础连接、Function Calling、托管搜索和原生图片输入检查，互不覆盖。每项检查包含状态、尝试次数、耗时、脱敏错误码、HTTP 状态和 Provider 请求 ID。图片检查使用运行时确定性生成并在发送前校验的 96×64 三色 PNG，要求模型识别全部三种主色，但不把颜色顺序当作协议能力条件；探测资源无效时以 `AI_IMAGE_PROBE_ASSET_INVALID` 立即失败且不请求 Provider，超时、连接、限流或服务端错误最多重试一次。若 HTTP 请求成功但识别结果不匹配，测试结果会返回最多 160 字符的固定探测回复预览；该预览不涉及归档消息、用户图片或用户对话。测试不读取归档消息、不触发生产 Fallback，也不计入生产降级。

`GET/PUT /api/v1/ai/search/settings` 读取和更新实例级联网搜索参数。参数包括 HTTP 尝试次数、单次请求超时、重试退避、最大结果数和失败策略；PUT 必须携带 `expectedVersion` 防止旧页面覆盖新配置。未保存时 GET 返回系统默认值和 `version=0`，首次保存后以数据库配置为准，并对新的 Agent 执行立即生效。工作流节点不保存这些参数，也不存在独立的工具总时间预算。

`GET/PUT /api/v1/ai/image-input/settings` 管理所有 AI 节点共享的原生图片输入。配置包括总开关、附件和链接卡片主图来源、可信链接图片精确域名、当前/历史/总图片数量、单图/总字节、获取超时和 Provider 图片细节等级；PUT 使用 `expectedVersion`。`trustedLinkPreviewHosts` 最多 32 项，只接受不含协议、端口、路径或通配符的精确 DNS 主机名，用于允许部署代理的 `198.18.0.0/15` Fake-IP，不能豁免其他私网地址。系统默认关闭，启用后无需修改工作流节点。图片只在请求期间转为 Data URL，不持久化原图或 Base64。图片摘要没有节点级或新增全局配置：新图片自动创建后台任务，仅在存在已验证视觉 Provider 时生成。

路由响应同时区分：

- `configuredProviderIds`：管理员保存的固定顺序；
- `effectiveProviderIds`：当前运行时可选择的候选；
- `unavailableProviderIds`：停用、缺少 Secret 或仍在冷却的候选。

执行列表返回匹配聊天的显示名称和 Provider Chat ID，并按单次执行聚合 `ai-chat` 节点所有可统计 Provider Attempt 的缓存命中输入 Token、可统计输入 Token 与命中率；Retry、Fallback 和 Agent 多轮均计入，历史摘要压缩和图片摘要等辅助 AI 请求不计入。Provider 总用量仍包含 `purpose=image-summary` 的真实请求。没有可统计的对话回复请求或 Provider 未返回缓存统计时命中率为 `null`。执行详情返回每条脱敏节点、Provider Attempt、工具调用、图片输入和出站轨迹；图片摘要不在执行详情展示。消息搜索的敏感“图片与 AI 摘要”弹窗通过 `/api/v1/messages/{messageId}/media` 返回摘要状态和有限诊断，并通过受保护的 `/api/v1/messages/{messageId}/image` 代理原图。图片摘要诊断只包含来源、状态、稳定引用、Hash、Provider、模型、尝试次数、耗时和错误码；其他图片轨迹不包含附件 GUID、完整图片 URL、原图或 Base64。其他轨迹可以包含实际搜索词、规范化有限结果、请求 ID、HTTP 状态、哈希、大小和 Token 计数，但不得包含完整 Prompt、聊天正文、AI 输出、Secret 或原始外部响应。

完整执行语义见[事件与工作流设计](事件与工作流设计.md)。

## 受控导出

导出使用“冻结预览 → 二次验证 → 显式确认 → 短时下载”：

1. 单个任务只允许一个当前监听聊天、明确时间范围，以及消息或执行摘要中的至少一种。
2. 时间最长 31 天，最多 10,000 条，预计不超过 25 MB；预览 5 分钟有效。
3. 确认必须回传预览的 `expectedRecordCount` 和 `expectedSnapshotAt`。
4. 确认后下载窗口 10 分钟；服务端按冻结快照流式生成 JSON Lines，不写临时正文文件。
5. 任务按当前管理会话或 Bearer 所有者隔离，下载时再次检查监听状态和有效期。

第一行为 `manifest`，之后为 `message` 或 `execution`。导出不包含 AI Key、Secret、`secretRef`、完整 Prompt、节点输入输出、原始 Webhook 或内部错误详情。预览、确认、下载和取消分别审计。

消息中的 `contentRedactedAt` 区分“原本没有正文”和“已按保留策略清理”；清理后 `body=null`、`attachments=[]`、链接预览状态为 `redacted` 且条目清空，必要元数据与执行关联仍可查询。消息导出包含同一规范化预览，不包含原始卡片或网页内容。

## 必填运行时配置

| 名称                                | 必填 | 敏感性 | 说明                                              |
| ----------------------------------- | ---- | ------ | ------------------------------------------------- |
| `DATABASE_URL`                      | 是   | Secret | PostgreSQL 连接串                                 |
| `API_ACCESS_TOKEN`                  | 是   | Secret | 至少 32 字符的受控自动化 Bearer Token             |
| `APP_LOGIN_PASSWORD_HASH`           | 是   | Secret | Web 登录密码的 BubblePilot scrypt 哈希            |
| `SENSITIVE_OPERATION_PASSWORD_HASH` | 是   | Secret | 不同于登录密码的敏感操作哈希                      |
| `BLUEBUBBLES_WEBHOOK_SECRET`        | 是   | Secret | 至少 32 字符的首次启动/Webhook 回退密钥           |
| `BLUEBUBBLES_SERVER_URL`            | 是   | 敏感   | BlueBubbles 根 URL，数据库未配置时使用            |
| `BLUEBUBBLES_ACCESS_TOKEN`          | 是   | Secret | BlueBubbles REST API Password，数据库未配置时使用 |

正式部署还应显式设置 `SETTINGS_ENCRYPTION_KEY`。代码为兼容旧实例允许回退到 `API_ACCESS_TOKEN`，但新的正式实例不应依赖该回退。

| `WORKFLOW_QUEUE_CAPACITY`         | 否   | `64`                  | 0-10000 条等待执行                                                   |
| `WORKFLOW_QUEUE_WAIT_MS`          | 否   | `30000`               | 100-300000 毫秒                                                      |
| `STALE_RETRY_SECONDS`             | 否   | `300`                 | 30-86400 秒；逾期 Retry 可人工接管                                   |
| `LOG_LEVEL`                       | 否   | `info`                | Pino 日志级别                                                        |
