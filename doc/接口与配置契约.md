# BubblePilot 接口与配置契约

## 权威来源

本文解释接口边界，不重复抄写每个请求字段。机器可校验合同是：

| 文件                                                                                        | 权威内容                          |
| ------------------------------------------------------------------------------------------- | --------------------------------- |
| [`contracts/openapi.yaml`](../contracts/openapi.yaml)                                       | HTTP 路径、认证、参数、请求和响应 |
| [`contracts/bluebubbles-webhook.schema.json`](../contracts/bluebubbles-webhook.schema.json) | BlueBubbles 原始 Webhook          |
| [`contracts/message-envelope.schema.json`](../contracts/message-envelope.schema.json)       | 统一消息信封                      |
| [`contracts/workflow.schema.json`](../contracts/workflow.schema.json)                       | 可发布工作流图                    |

`GET /api/v1/workflows/schema` 另外提供面向 AI 和跨实例传输的 `BubblePilotWorkflow bubblepilot.io/v1` 清单 Schema；它包装运行时工作流图并用逻辑 Binding 隔离实例资源。运行时 Zod/图语义校验仍是最终发布权威，合同测试负责防止公开 Schema、节点注册表和运行时实现漂移。

运行时路由、OpenAPI、环境变量和 Schema 由 `pnpm contracts:check` 交叉检查。

## API 分区与认证

| 分区                    | 入口示例                                                                                                                                             | 认证                                                            |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 健康检查                | `/health/live`、`/health/ready`                                                                                                                      | 无                                                              |
| Web 登录                | `/api/v1/auth/session`、`/api/v1/auth/sensitive`                                                                                                     | 登录密码或当前管理会话                                          |
| BlueBubbles Webhook     | `/api/v1/webhooks/bluebubbles`                                                                                                                       | 查询参数 Token 或 `X-BubblePilot-Webhook-Secret`                |
| 消息与监听              | `/api/v1/chats`、`/api/v1/chats/{chatId}/participants`、`/api/v1/messages/search`、`/api/v1/chat-monitoring` | 管理会话或 Bearer；正文、成员映射、摘要重置和监听变更需二次验证 |
| 工作流与触发器          | `/api/v1/workflows`、`/api/v1/triggers`                                                                                                              | 管理会话或 Bearer                                               |
| AI Provider、路由与工具 | `/api/v1/ai/providers`、`/api/v1/ai/routes`、`/api/v1/ai/usage`、`/api/v1/ai/search/settings`、`/api/v1/ai/image-input/settings`                     | 管理会话或 Bearer                                               |
| 执行与运行状态          | `/api/v1/executions`、`/api/v1/operations/status`                                                                                                    | 管理会话或 Bearer；人工恢复需二次验证                           |
| 审计与导出              | `/api/v1/audit-events`、`/api/v1/exports`                                                                                                            | 管理会话或 Bearer；敏感读取、确认和下载需二次验证               |
| BlueBubbles 设置        | `/api/v1/integrations/bluebubbles`                                                                                                                   | 查询需登录，修改和测试需二次验证                                |

浏览器使用服务端管理会话。Cookie 为 `HttpOnly`、`SameSite=Strict`，`SESSION_COOKIE_SECURE=auto` 时按 HTTPS/反向代理协议决定 `Secure`；数据库只保存随机会话 Token 的 SHA-256。二次授权绑定当前会话并短时有效，前端到期收起内容不能替代服务端逐请求校验。

`API_ACCESS_TOKEN` 是兼容受控自动化的高熵 Bearer Token，视为已经具备实例管理权限，应像管理员凭据一样保护。新用户操作优先使用 Web 会话，不把 Bearer Token 暴露给浏览器脚本或不可信客户端。

分页列表使用不透明 `cursor` 和 `limit`，`limit` 为 1-100。错误响应包含稳定 `code`、可读 `message` 和 UUID `correlationId`。调用方不得解析错误文案决定重试。

管理 API 与 Webhook 分别限流，超过上限返回 `429 RATE_LIMITED`。执行容量不足返回 `503 WORKFLOW_QUEUE_FULL` 或 `503 WORKFLOW_QUEUE_WAIT_TIMEOUT`；只能退避重试，不能通过并发重放绕过上限。同一工作流与聊天的后续消息属于有序串行工作，不使用容量等待超时丢弃，但仍计入有界队列容量。

## Webhook 合同

- URL：`/api/v1/webhooks/bluebubbles?token=<secret>`；Secret 至少 32 字符并使用常量时间比较。
- 当前处理 `new-message`；其他合法事件以 `ignored` 进入幂等事件表。
- 稳定事件键为 `new-message:<message-guid>`。
- 成功返回 `202`，接入状态为 `archived`、`ignored` 或 `duplicate`。
- `automationOutcome` 区分 `unsupported-event`、`chat-not-monitored`、`evaluation-pending`、`not-evaluated`、`no-active-triggers`、`no-trigger-match` 和 `matched`。
- 只有 `evaluation-pending` 允许同键重投继续调度；其他最终判定不按当前配置补跑。
- 未监听聊天只保存发现所需元数据，不保存正文。
- 入站事件查询不返回消息正文、原始 Webhook、Payload 哈希、Prompt 或凭据。

详细字段映射和供应商行为见 [BlueBubbles 集成说明](BlueBubbles集成说明.md)。

统一消息信封当前为 `schemaVersion=3`，必填 `message.linkPreview`。状态为 `not-requested|pending|available|unavailable|failed|redacted`，最多保存 4 条规范化预览；单条只包含来源、HTTP(S) URL、有限标题/摘要/站点名、图片/图标存在标志，以及可用时的公开卡片主图 URL 和来源。原始 BlueBubbles `payloadData`、网页 HTML 和媒体二进制不进入该合同。

`GET/PUT /api/v1/integrations/bluebubbles` 除连接与发送配置外，还返回或更新 `linkPreviewEnabled`、`openGraphFallbackEnabled` 和 `openGraphTimeoutMs`（1000-15000 毫秒）。它们保存在 `bluebubbles_settings`，修改仍需要二次验证和乐观版本。消息列表返回规范化 `linkPreview`、有限 `linkPreviewDiagnostics` 和 `linkPreviewFetchedAt`，便于排障；诊断不包含 URL、网页正文、聊天正文、凭据或原始响应。

聊天列表（`GET /api/v1/chats`、`GET /api/v1/chat-monitoring`）及监听更新结果包含 `memoryAuthorized`，直接读取 `memory_chats.enabled`，无授权记录时为 false。此字段独立于监听、全局记忆开关和索引完成状态；聊天列表展示“长期记忆授权”，通过对应聊天的长期记忆配置弹窗修改授权后同步更新。

## 对话成员身份合同

`GET /api/v1/chats/{chatId}/participants` 聚合该聊天历史中实际出现的非本人 sender ID，返回消息数量、最后出现时间、本名、昵称和独立映射版本。`PUT` 使用 `expectedVersion` 全量替换映射；最多 100 项，同一 sender ID 不能重复，本名或昵称至少填写一项，空数组用于清除全部映射。提交不在该聊天历史中的 ID 返回 `CHAT_PARTICIPANT_NOT_DISCOVERED`，版本过期返回 `CHAT_PARTICIPANT_IDENTITIES_CONFLICT`。

两个接口都需要二次验证并写入 `chat.participants.view` 或 `chat.participants.update` 审计。审计只保存动作、聊天 ID、结果和 HTTP 状态，不保存本名、昵称或请求正文。映射按聊天隔离；运行时只能按本次加载历史和当前消息中的 sender ID 定向解析，不能读取整张成员表注入 AI。

## 聊天软删除

`DELETE /api/v1/chats/{chatId}?expectedVersion=<version>` 软删除一个已停用监听的聊天。只有 `enabled=false` 的聊天可删除；已启用返回 `409 CHAT_STILL_ENABLED`，版本过期返回 `409 CHAT_DELETE_CONFLICT`，不存在或已删除返回 `404 CHAT_NOT_FOUND`。删除只写入 `deleted_at`，聊天行、消息、执行、导出和成员映射保持不变，历史引用仍能显示聊天名称；`/api/v1/chat-monitoring` 和 `/api/v1/chats` 不再返回已删除聊天。已删除聊天重新收到消息会清除删除标记，恢复同一聊天记录（ID、名称、历史保持不变），但仍保持停用状态且不自动归档正文，管理员可重新启用。删除需二次验证并写入 `chat.delete` 审计。

## 工作流与 AI 合同

已发布工作流版本不可原地修改。编辑会创建新的已校验候选版本；发布和切换在事务中完成，已开始执行继续引用原版本。生产触发器拒绝 `isFromMe`，冲突提示只表示潜在重叠，不阻止启用。

### AI Friendly 清单与导入导出

工作流列表可复制 JSON Schema、AI 编写指南、Binding Catalog 和标准提示词，也可上传或粘贴 `*.bubblepilot-workflow.json`。清单的 `spec` 只描述图逻辑，`bindings` 以 `providerRouteRef` 和 `chatRefs` 描述外部依赖；摘要 Provider 由全局 AI 设置管理，不进入工作流绑定；不得包含 Secret、执行记录或消息正文。

`GET /api/v1/workflows/{workflowId}/versions/{version}/export` 默认生成 portable 清单并移除 AI Route 与 Chat 实例 ID；`mode=instance-bound` 保留绑定 ID 用于同实例备份，需二次验证，但仍不导出凭据。`GET /api/v1/workflows/binding-catalog` 只返回逻辑名称、资源 ID 和已验证能力，不返回 Provider 地址或 Secret。

导入固定分两步：`POST /api/v1/workflows/import/preview` 执行结构、图语义、模板与能力绑定校验，错误使用 RFC 6901 JSON Pointer，并签发五分钟令牌；`POST /api/v1/workflows/import` 重传 Manifest、最终绑定和令牌，服务端再次校验资源快照。提交支持 `create` 或带 `targetWorkflowId` 的 `new-version`，始终只创建 `validated` 候选版本，不自动发布或启用。提交需要二次验证并写审计，日志和审计只保存结果与哈希，不保存 Manifest 正文。

动作目录只返回具备运行时实现的节点。`load-context@1` 提供 messages、count 和当前窗口过滤后的 participants，读取双窗口内且严格早于触发消息的原文。字符保护只约束历史提取，不约束整个 AI 请求。`render-text@1` 使用允许的 Context Token 提供 text；未知路径、未知动作输出和不完整模板在候选版本校验时拒绝。`set-variable@1` 只保留历史运行兼容。

AI Provider 的 `reasoningEffort` 可设为 `default|none|minimal|low|medium|high|xhigh|max`。`default` 不发送协议字段；其他值在 Responses 中映射为 `reasoning.effort`，在 Chat Completions 中映射为 `reasoning_effort`。可用等级取决于具体模型和兼容网关。该默认值适用于普通请求、Agent 工具轮次、Retry 和能力探测。图片能力探测使用全局图片输入配置的细节等级，与真实图片请求保持一致；无法读取配置时回退为 `high`，不再固定使用 `low`。

AI Provider 支持 Chat Completions 或 Responses 接口类型、Base URL、模型、参数、超时、启停、排序、Function Calling、托管搜索、原生图片输入、会话亲和和只写 `secret`。单次 Provider 请求超时可配置为 1,000-360,000 毫秒，默认 30,000 毫秒。`sessionAffinity` 默认为 `disabled`；设为 `session-id-header` 时，BubblePilot 按 Provider、BlueBubbles 聊天、工作流和 AI 节点生成不含原始标识的稳定哈希，通过 `X-Session-ID` 请求头发送，并在 Responses 请求体中把同一个值作为 `prompt_cache_key`。该值跨工作流执行、Agent 工具轮次和 Retry 保持稳定；显式会话亲和会覆盖 Provider 默认参数中的 `prompt_cache_key`。`X-Client-Request-Id` 仍按单次请求生成，不能用于替代稳定会话键。Chat Completions 不发送 Responses 专用的 `prompt_cache_key`。Secret 使用 `SETTINGS_ENCRYPTION_KEY` 加密；编辑时省略 Secret 表示保留原值，任何读接口都不回显。

`GET /api/v1/ai/usage` 只返回 Provider 级聚合数据。`hours` 仅接受 1/6/12/24/48，`timeZone` 使用 IANA 时区并决定今日、ISO 周和本月边界。响应同时包含长周期汇总、补齐空桶的实时序列和缓存统计覆盖率。`cachedPromptTokens=null` 表示 Provider 没有可统计缓存数据，与明确返回 0 不同。该接口不返回消息正文、Prompt、会话键或 Secret。

连通性测试分别返回基础连接、Function Calling、托管搜索和原生图片输入检查，互不覆盖。每项检查包含状态、尝试次数、耗时、脱敏错误码、HTTP 状态和 Provider 请求 ID。图片检查使用运行时确定性生成并在发送前校验的 96×64 三色 PNG，要求模型识别全部三种主色，但不把颜色顺序当作协议能力条件；探测资源无效时以 `AI_IMAGE_PROBE_ASSET_INVALID` 立即失败且不请求 Provider，超时、连接、限流或服务端错误最多重试一次。若 HTTP 请求成功但识别结果不匹配，测试结果会返回最多 160 字符的固定探测回复预览；该预览不涉及归档消息、用户图片或用户对话。测试不读取归档消息、不触发生产 Fallback，也不计入生产降级。

`GET/PUT /api/v1/ai/search/settings` 读取和更新实例级联网搜索参数。参数包括 HTTP 尝试次数、单次请求超时、重试退避、最大结果数和失败策略；PUT 必须携带 `expectedVersion` 防止旧页面覆盖新配置。未保存时 GET 返回系统默认值和 `version=0`，首次保存后以数据库配置为准，并对新的 Agent 执行立即生效。工作流节点不保存这些参数，也不存在独立的工具总时间预算。

`GET/PUT /api/v1/ai/image-input/settings` 管理所有 AI 节点共享的原生图片输入。配置包括总开关、附件和链接卡片主图来源、可信链接图片精确域名、当前/历史/总图片数量、单图/总字节、获取超时和 Provider 图片细节等级；PUT 使用 `expectedVersion`。`trustedLinkPreviewHosts` 最多 32 项，只接受不含协议、端口、路径或通配符的精确 DNS 主机名，用于允许部署代理的 `198.18.0.0/15` Fake-IP，不能豁免其他私网地址。系统默认关闭，启用后无需修改工作流节点。图片只在请求期间转为 Data URL，不持久化原图或 Base64。图片摘要没有节点级或新增全局配置：新图片自动创建后台任务，仅在存在已验证视觉 Provider 时生成。

路由响应同时区分：

- `configuredProviderIds`：管理员保存的固定顺序；
- `effectiveProviderIds`：当前运行时可选择的候选；
- `unavailableProviderIds`：停用、缺少 Secret 或仍在冷却的候选。

执行列表返回匹配聊天的显示名称和 Provider Chat ID，并按单次执行聚合 `ai-chat` 节点所有可统计 Provider Attempt 的缓存命中输入 Token、可统计输入 Token 与命中率；Retry、Fallback 和 Agent 多轮均计入，图片摘要等辅助 AI 请求不计入。Provider 总用量仍包含 `purpose=image-summary` 的真实请求。没有可统计的对话回复请求或 Provider 未返回缓存统计时命中率为 `null`。执行详情返回每条脱敏节点、Provider Attempt、工具调用、图片输入和出站轨迹；图片摘要不在执行详情展示。消息搜索的敏感“图片与 AI 摘要”弹窗通过 `/api/v1/messages/{messageId}/media` 返回摘要状态和有限诊断，并通过受保护的 `/api/v1/messages/{messageId}/image` 代理原图。图片摘要诊断只包含来源、状态、稳定引用、Hash、Provider、模型、尝试次数、耗时和错误码；其他图片轨迹不包含附件 GUID、完整图片 URL、原图或 Base64。其他轨迹可以包含实际搜索词、规范化有限结果、请求 ID、HTTP 状态、哈希、大小和 Token 计数，但不得包含完整 Prompt、聊天正文、AI 输出、Secret 或原始外部响应。

列表和详情接口的 `providerAttempts` 按实际调用顺序返回完整 AI 调用路径，包含同一 Provider 重试和跨 Provider fallback；新增的 `routeTraces` 固定执行时的路由名称、ID、版本、请求是否带图、候选顺序及过滤或跳过原因，并明确区分原生图片调用和纯文本降级。执行详情及敏感图片摘要诊断使用同一数据合同；迁移前的历史记录返回空数组，不根据当前配置反推。

完整执行语义见[事件与工作流设计](事件与工作流设计.md)。

## 受控导出

导出使用“冻结预览 → 二次验证 → 显式确认 → 短时下载”：

1. 单个任务只允许一个当前监听聊天、明确时间范围，以及消息或执行摘要中的至少一种。
2. 时间最长 31 天，最多 10,000 条，预计不超过 25 MB；预览 5 分钟有效。
3. 确认必须回传预览的 `expectedRecordCount` 和 `expectedSnapshotAt`。
4. 确认后下载窗口 10 分钟；服务端按冻结快照流式生成 JSON Lines，不写临时正文文件。
5. 任务按当前管理会话或 Bearer 所有者隔离，下载时再次检查监听状态和有效期。

第一行为 `manifest`，之后为 `message` 或 `execution`。导出不包含 AI Key、Secret、`secretRef`、完整 Prompt、节点输入输出、原始 Webhook 或内部错误详情。预览、确认、下载和取消分别审计。

消息中的 `contentRedactedAt` 区分“原本没有正文”和“已按保留策略清理”；清理后 `body=null`、`attachments=[]`、链接预览状态为 `redacted` 且条目清空，必要元数据与执行关联仍可查询。消息导出包含同一规范化预览，不包含原始卡片或网页内容。

## 必填运行时配置

| 名称                                | 必填 | 敏感性 | 说明                                              |
| ----------------------------------- | ---- | ------ | ------------------------------------------------- |
| `MEME_STORAGE_PATH` | 否 | `./data/memes`；原文件与预览的本地持久化目录，Compose 固定挂载 `/app/data/memes`。 |
| `DATABASE_URL`                      | 是   | Secret | PostgreSQL 连接串                                 |
| `API_ACCESS_TOKEN`                  | 是   | Secret | 至少 32 字符的受控自动化 Bearer Token             |
| `APP_LOGIN_PASSWORD_HASH`           | 是   | Secret | Web 登录密码的 BubblePilot scrypt 哈希            |
| `SENSITIVE_OPERATION_PASSWORD_HASH` | 是   | Secret | 不同于登录密码的敏感操作哈希                      |
| `BLUEBUBBLES_WEBHOOK_SECRET`        | 是   | Secret | 至少 32 字符的首次启动/Webhook 回退密钥           |
| `BLUEBUBBLES_SERVER_URL`            | 是   | 敏感   | BlueBubbles 根 URL，数据库未配置时使用            |
| `BLUEBUBBLES_ACCESS_TOKEN`          | 是   | Secret | BlueBubbles REST API Password，数据库未配置时使用 |

### 补建进度返回值

`GET /api/v1/memory/jobs` 与聊天下的 `/memory/jobs` 保留原字段，追加聊天名称、模型、范围、request_key 和 progress。progress 包含 scope（full/remaining/null）、total、processed、removed、remaining、percent、lastProgressAt、generatedAt 和 estimate。百分比为 `(processed + removed) / total`，removed 不计为索引成功。scope=null 不显示百分比。

estimate 包含 status、messagesPerMinute、remainingSeconds、estimatedCompletionAt；不可预估时三个数值/时间字段为 null。状态包括 available、warming、waiting、stalled 和任务终态。日期使用 ISO 时间，客户端以本地时区展示。普通进度接口仅含元数据，操作仍需敏感二次验证、版本检查和审计。接口 schema 以 OpenAPI 为准。

任务列表采用 `limit`（默认 50，上限 100）与不透明 `cursor`，返回 `{ data, page: { nextCursor } }`；按创建时间与 ID 倒序稳定分页。Web 每页 25 条，详情单独读取，不受当前列表页限制。

Provider 路由列表按创建时间倒序、ID 升序稳定排列；修改策略或启停不改变排序。AI 页面以列表展示路由名称、状态、候选顺序、运行策略、创建时间与操作。

Provider Attempt 响应诊断与原始请求共用最近 20 个执行的内存生命周期，不落库、不进入普通日志。响应按 clientRequestId 独立关联，重试不会覆盖相同请求哈希的其他响应；仅敏感验证后通过 `/api/v1/executions/{executionId}/ai-attempts/{attemptId}/raw-response` 查看和复制。正文最多保留 64 KiB（UTF-8 安全截断），同时返回原始字节数和截断标记。只提取 error 的 message/code/type/param 及请求关联 ID（x-request-id、request-id、openai-request-id、cf-ray、x-amzn-requestid、x-ms-request-id），不保存认证或 Cookie 响应头。错误字段仍属于敏感正文，不进入普通执行列表。未收到完整响应不伪造正文；空响应、HTML 和文本可区分。弹窗分为结果摘要、响应与错误详情、原始请求及缓存诊断；敏感会话失效清空正文并拒绝过期响应。


### 近期发言与上下文覆盖

历史归档工具已扩展为 5 个：原文查询、语义搜索、来源展开、精确计数、首末消息。工具合同见[接口与配置契约](接口与配置契约.md#聊天归档工具合同)。新运行仅注册新名称；旧执行中的 get_latest_chat_messages 名称及原有来源仍可查看。

最后发言与时间段查询使用上述工具，主题查询仍使用相关度搜索；相关度排序不能证明最近一次。身份不明时不能猜发言人，相对日期依据当前消息时间及聊天时区解释。连续追问沿用可见上下文已确定的绝对日期、成员、每日时段、关键词与分组；仅要求查看原文时不得扩大范围或重新解释相对日期。缺少必要条件时简短澄清；跨运行引用不可用时在相同范围重新查询。不增加回答事实审核。

执行上下文新增可选 `historyCoverage`：`windowEvicted`、`retained`、`omitted`；三项为 null 或包含 `count`、`firstMessageIndex`、`lastMessageIndex`、`earliestSentAt`、`latestSentAt` 的范围。条数来自实际候选消息，时间为发送时间极值，不用索引差推算。`contextIncompleteReasons` 包含 `window-evicted`、`history-trimmed` 或 `character-overflow`；任一原因使 `contextIncomplete=true`。该信息进入模型输入及执行快照，不含遗漏正文；旧执行不回填，显示“未记录覆盖范围”。范围区分消息窗口移出和字符裁剪，不代表被授权过滤或已清理内容的覆盖情况。

## 聊天归档工具合同

仅在现有长期检索全局开关、聊天授权和活动索引代际条件满足时，通过 Agent 工具注册表提供以下 5 个工具；不新增 HTTP 接口、工作流节点或单独配置。直接数据库查询不要求向量覆盖，不调用 embedding。

| 工具 | 参数及默认值 | 返回与排序 |
| --- | --- | --- |
| query_chat_messages | 共用筛选；order=asc/desc 默认 desc；limit 默认 20、1–50；可选 cursor | 原文及附件历史表示、消息 ID、完整时间、发言人、来源；按 sent_at、message_index 同方向排序 |
| search_chat_history | query、senderId 或 botWorkflowId、from、to、limit（默认 8，上限 20） | 保留关键词/向量混合召回与相关度排序；相关度不能证明最新 |
| read_chat_excerpt | 已返回的 ref，before/after（默认各 8，范围 0～20） | 按实际可读行展开，保留源正文；可接受查询和首末消息返回的引用 |
| count_chat_messages | 共用筛选；groupBy 默认 none，可选 day/sender；limit 默认 31、1–100；可选 cursor | 完整匹配集 SQL COUNT 后分页分组；none 返回 count；不伪造消息引用 |
| get_chat_message_extrema | 同计数；必填 pick=first/last | 整体或每组按发送时间、消息索引选首/末条；仅返回消息元数据及 ref，正文由展开工具获取 |

三个 SQL 工具共用以下筛选：

- senderId 为准确标识，不做姓名解析；chatId、触发消息上界、时区只能从服务端本次执行取得，模型不能覆盖。时区缺失的旧调用使用 UTC。
- from/to 为带时区 ISO 时间，包含端点，精度最多微秒；拒绝倒置。每日时段 dailyTime={from,to} 使用聊天时区，格式 HH:mm，起点包含、终点不包含；仅终点允许 24:00。23:00–02:00 表示跨午夜；分组日期仍是消息实际本地日期。拒绝相同时刻。
- keywords 接受 1–10 个非空词，每词最多 100 字符；提供时必须同时指定 keywordMode=all/any。对原始正文做大小写不敏感的字面子串匹配；%、_、正则字符无特殊含义。单位为消息条数，重复出现不重复计数。无关键词时附件消息也参与；附件衍生摘要不作为关键词正文。
- 仅当前授权聊天、message_index 严格小于触发消息且正文未清理的归档记录。与上下文裁剪、向量候选条数无关；没有读取到的记录不能据此推断不存在。

按天分组必须给出 from/to，最多 366 个本地自然日；跨时区及夏令时按实际本地日期计算。日期升序，空日期返回 count=0 或 message=null；按成员使用稳定标识排序，NULL 成员独立成组。整体计数 0 是成功，整体首末查询无匹配为 no-results。超出 JavaScript 安全整数范围的计数返回 unavailable，不近似处理。

SQL 返回 queriedAt 表示该条查询的数据库快照时间。每次调用重新查询，不跨模型轮次维持事务；补录和清理可能改变后续页面。cursor 是会话内不透明 UUID，绑定工具、规范化筛选、排序、分组、取值和授权范围；允许调整 limit，不可跨会话使用，不接收客户端时间/索引位置。原文使用包含微秒的时间与索引进行 keyset 分页，不使用 OFFSET。

返回包含 filters、timeZone、hasMore、nextCursor、complete、truncated；仅第一页已覆盖全部匹配时 complete=true。分组计数即使分页，每个已返回组仍是精确值（countsExact=true）；不能将部分分组的和称为总数。字符预算只丢弃完整项目，cursor 始终绑定实际返回的最后一项；不足以容纳一项时返回 unavailable/tool-output。字符裁剪同时触发统一预算收尾。重复查询复用来源，但照常计次、计字符。无结果不等于权限失效，查询失败或预算不足绝不返回伪造的零。

查询、统计和联网继续共享单次运行 10 次 / 24,000 字符 / 60 秒默认预算，不按天发额度。数据库单次操作仍受 5 秒和当前剩余工具时长较小值约束；取消后销毁连接，迟到结果不登记来源。普通轨迹仅保留工具名、结果条数、状态和预算元数据，不新增关键词或消息正文日志。


## Bot 角色配置与归属维护

GET/PUT `/api/v1/workflows/:workflowId/bot-identity` 管理昵称。PUT 输入 nickname（去除首尾空白，1–120 字符，无控制字符）与 expectedVersion；未配置版本为 0，冲突返回 409。首次保存后只能改名不能清空。管理权限及审计与 AI 全局设置一致，不激活或发布工作流；保存只影响后续执行。workflowId 是稳定角色 ID，同名允许。

GET `/api/v1/bot-attributions` 返回精确匹配预览、最近任务和派生历史状态；POST `/api/v1/bot-attributions/backfill` 启动只读原文的元数据回填；POST `/api/v1/bot-attributions/:jobId/retry` 重试失败任务。POST `/api/v1/chats/:chatId/bot-identity/rebuild` 仅启动索引重建，不处理聊天摘要。

原文查询、计数、首末和语义搜索新增可选 botWorkflowId（UUID），与 senderId 互斥，不能扩大聊天权限。senderId 仍表示网关成员，不接受角色昵称。返回作者 kind 为 participant、bot 或 unknown-self；Bot 包含 workflowId、nickname、version、basis、revision。按 sender 分组分别统计各 Bot 工作流和未知本账号来源，不混成一个发送账号。游标绑定角色筛选，证据哈希包含作者元数据。

工作流 Manifest metadata.botNickname 是可选昵称建议；导出不带身份 ID 或历史关联。导入预览与结果返回建议昵称，角色区保存后生效；新建工作流产生新身份，已有工作流导入不覆盖身份配置。

角色归属状态新增 `workflows`：每项含 `workflowId/name/nickname/total/bound/unbound/nicknamePending`。统计单位为可精确匹配发送记录的归档消息，`total = bound + unbound`；来源未知和多重匹配单独保留在账号级预览，不猜测其所属自动化。已绑定但尚待首次昵称补充的消息计入 `nicknamePending`，不算未绑定。无消息的未删除工作流仍返回零计数。

角色弹窗通过 GET `/api/v1/bot-attributions?workflowId=<uuid>` 仅查询当前工作流统计、归属任务和有发送记录的聊天；不返回全局未知/冲突预览。回填接口可选请求体 `{workflowId}` 限定工作流，省略仍为全局回填。两者校验工作流存在。聊天重建范围仍为整段聊天共享历史，索引记录在历史索引中查看。

角色历史索引重建使用 reason=rebuild 标识，分批、重试及暂停恢复保留该类型；不能用 request_key 是否为空判断是否为增量任务。重建任务首次领取时初始化固定范围进度，之前显示“等待初始化进度统计”。旧的未完成无统计补建任务下次领取时仅统计剩余范围并重置旧采样；已完成任务不回填。

## 聊天上下文配置与摘要退休（迁移 0052）

`GET/PUT /api/v1/ai/context/settings` 使用管理员权限。PUT 写入 `ai.context.settings.update` 审计，通过 `expectedVersion` 检查冲突（409），不要求敏感操作二次解锁。字段为 `includeFromMe`（默认 true）、`baseMessageWindow`（1～50）、`redundancyMessageWindow`（1～50）、`characterLimit`（100～20000）；默认值分别为 true、10、10、6000。返回增加 source、version、updatedAt。未保存使用默认值；保存只影响之后创建的触发快照。

聊天摘要设置、压缩列表／详情／正文／重新生成、聊天摘要清空／重置接口全部删除（404）。Bot 归属重建仅接受 `target=memory`，缺省为 memory，summary/both 返回参数错误；归属状态不再返回 summaries 或 bot_summary_* 字段。模型调用用途只保留 workflow-reply 与 image-summary。

`load-context` 输出 messages、count、participants，不再输出 summary 或 summaryCoveredThroughIndex。已有工作流显式引用这些输出时，校验报告节点及缺失端口，不静默渲染空值。

`historyCoverage` 包含 retained（最终原文）、omitted（字符裁剪）、windowEvicted（消息窗口移出）。范围为空或包含 count、firstMessageIndex、lastMessageIndex、earliestSentAt、latestSentAt；计数和时间均来自实际允许读取的记录。contextIncompleteReasons 分别使用 window-evicted、history-trimmed、character-overflow，模型输入与执行快照一致，不包含移出正文。旧快照缺少覆盖信息不回填。

### 生成与检索统一策略

共享常量位于 modules/ai/execution-policy.ts，由前后端共同使用；运行时通过 resolveGenerationPolicy 解析新旧配置。ai-chat 新字段 targetOutputCharacters 为 1～4000 整数，派生保护值为 3 倍，不能与旧 maxOutputCharacters 同时设置；maxOutputTokens 仍允许 1～8192。新建模板显式使用 2000/8192，旧配置省略值维持 4000/1024。无新增全局接口、环境变量或数据库迁移。

图片摘要新请求使用 500 字符提示目标、1500 字符保护和 2048 Token；不自动重建已有摘要。

search_chat_history 返回 returnedCount（实际片段数）、candidateLimitReached（任一路触及候选上限，不能证明没有更多）、selectionLimited（已知融合候选超过 limit）、exhaustive=false，以及原有 coverage/truncated。未索引补充依然仅检视有限的最近 100 条记录；本轮不增加语义分页。内容预算裁剪按完整证据项移除并更新数量。

read_chat_excerpt 返回 returnedMessageCount、beforeCount/afterCount、hasEarlier/hasLater、coverage（实际索引和最早/最晚时间）及 truncated。预算不足时逐条移除最外围消息并更新覆盖和可用性，源消息不截断；源本身放不下则 unavailable/tool-output。权限撤销、正文清理或无效引用均 unavailable。共享 Agent 配额不变，不能用有限语义结果证明完整时间线或完整计数。

发送层渲染结果使用同源最大保护值 12000 字符，避免固定 4000 字符阻断已通过 AI 节点校验的完整结果；超出时失败、不切片。reply 文本模板自身仍限制 4000 字符，AI 节点仍按本次配置硬上限校验。


执行列表支持 `attention=unknown-outbound`，按未知出站且执行未关闭筛选，再应用游标分页；与 `status` 取交集。运行状态的未知出站数量排除所属执行已关闭的发送记录，原始发送状态不变。


### 历史引用格式与回答交付

`[M数字]` 是本次历史聊天工具返回的内部来源标记，不能用于网页、图片或当前上下文消息编号。网页来源遵循联网来源展示策略。引用有效性只核对标记，不等于事实审核。

未登记引用最多触发一次格式纠正，不开放新工具、不突破既有轮数；纠正保留用户原任务及可用网页、图片和上下文，不强制转为历史问答。仍有无效引用时，仅移除内部引用标记并保留回答内容，不将未知标记登记为来源；JSON 按结构处理字符串。无效 JSON 或清理后空文本以 `AI_OUTPUT_FORMAT_INVALID` 失败，不再发送“未找到历史线索”的固定兜底。权限复核与正文清理检查不变。

执行快照中的 `agentBudget.citationHandling` 为可选元数据，包含 `invalidResponses`、`correctionAttempts` 和 `finalAction`（`corrected`、`markers-removed`、`failed`）。执行详情以普通说明展示，旧快照不回填，普通日志不新增回答正文。原始模型响应沿用已有受保护诊断。

### 恢复队列批量关闭

`POST /api/v1/executions/recovery/close` 需要管理员敏感操作授权，审计动作为 `execution.bulk-close`。返回 `{ data: { closedCount: number } }`。一次数据库语句关闭执行时可见的全部 `retrying`、`failed`、`dead-lettered` 记录，不受列表分页限制；并发更新后已不符合条件的记录不会关闭。清空重试时间和当前节点，保留完成时间、错误码、出站状态及轨迹。空队列或重复操作返回 0；不发送消息，不修改运行中和已完成任务。


### 表情库与独立投递

`/api/v1/memes` 及其子接口均要求管理员认证，写操作审计，无需敏感密码。GET 支持 query（名称/标签字面匹配）、enabled、status、offset（默认0）、limit（默认24，上限100），返回 items/total。POST 使用 multipart：file、name、description、tags（JSON 字符串数组）；返回 asset/created，重复文件返回已有素材。素材不可换图。

`GET/PUT/DELETE /api/v1/memes/:id` 读取、编辑或逻辑删除。PUT 接收 name/description/tags、可选 summary/enabled 和必填 expectedVersion；DELETE 接收 expectedVersion。冲突返回409。`GET :id/thumbnail` 返回静态PNG，`:id/file` 返回原始格式；均不缓存到公共目录。

`POST :id/summary` 接收 expectedVersion、candidate（默认true），活动任务不能重复提交。`POST :id/summary/adopt` 接收 expectedVersion，采用候选。摘要状态 pending/processing/succeeded/failed，错误码与候选独立展示。

`GET /api/v1/meme-deliveries?executionId=` 返回执行的图片投递；省略时返回最近100条未关闭的失败/未知图片。`POST /api/v1/meme-deliveries/:id/retry|close` 要求敏感验证并审计；409 表示状态已变化或不可处置。旧投递 kind 默认为 text，历史快照不补写表情字段。

### 表情工具的空关键词浏览

`search_memes` 的 `query` 必填，可为 `""`；空白内容归一为空字符串，按创建时间降序和稳定 ID 返回有限的已启用、未删除候选。默认5条，上限10条。非空查询使用空白分词和任一词字面命中，不自动进行中文分词或语义检索。浏览和搜索共用 Agent 预算与候选选择授权范围，不新增公共接口。
