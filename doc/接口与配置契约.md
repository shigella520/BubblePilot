# BubblePilot 接口与配置契约

## 1. 契约分层

机器可校验的契约放在 `contracts/`，解释性约束放在本文档和相关设计文档中。首期至少规划：

```text
contracts/
├── openapi.yaml                    # 管理 API 和查询 API
├── bluebubbles-webhook.schema.json # 规范化入站事件
└── workflow.schema.json             # 工作流定义
```

实现这些文件前，不应在多个控制器或前端组件中复制同一份字段约定。

## 2. API 约定

- 管理 API 使用版本前缀，例如 `/api/v1`。
- 写入请求包含幂等键或明确的版本条件。
- 错误响应包含机器可读 `code`、用户可读 `message`、`correlationId` 和可选 `details`。
- 分页、搜索、时间和排序字段使用统一格式。
- 认证、二次验证和资源授权在服务端完成。

## 3. Webhook 约定

- 接收端返回快速、明确的 HTTP 结果；耗时工作异步进入执行队列。
- 事件必须携带供应商事件标识或可计算的稳定幂等键。
- 未知事件类型进入可观测的忽略或失败状态，不静默丢弃。
- 事件 Schema 升级使用新版本或兼容字段，不直接改变旧字段含义。

## 4. 工作流契约

工作流定义必须包含：

- `schemaVersion`；
- 唯一节点 ID；
- 节点类型和节点版本；
- 节点配置；
- 合法的边引用和结束节点；
- 超时、重试和资源上限；
- 发布版本和创建来源。

已发布定义不可原地修改；编辑会生成草稿，发布后创建新的不可变版本。

## 5. 环境变量契约

新增环境变量时必须在同一个 PR 中记录：

| 项目 | 说明 |
| --- | --- |
| 名称 | 全大写下划线格式 |
| 是否必填 | 启动时必填或功能启用时必填 |
| 敏感性 | 普通、敏感或 Secret |
| 默认值 | 无默认值时明确写明 |
| 生效时机 | 启动、热加载或下一次执行 |
| 迁移策略 | 重命名、废弃或兼容方式 |

所有 Secret 环境变量都必须在日志、诊断接口和错误响应中脱敏。
