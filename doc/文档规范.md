# BubblePilot 文档规范

## 1. 语言策略

- 产品、需求、架构、数据、安全、开发、部署和发布文档以简体中文为主。
- `README.md` 是仓库默认入口，使用简体中文。
- `README.en.md` 提供英文项目介绍、部署概览和文档导航。
- `README.zh-TW.md` 提供繁体中文项目介绍；无法及时同步时，以 `README.md` 为准。
- 代码、类名、接口名、环境变量、JSON/YAML 字段名、错误码和 Git Commit 使用英文。
- BlueBubbles、OpenAI、Docker Compose、Webhook、Workflow 等专有名词保留英文，首次出现时可附中文解释。

## 2. 文档职责

| 文档 | 权威内容 |
| --- | --- |
| `doc/目标需求.md` | 产品范围、需求编号和验收标准 |
| `doc/典型用户交互故事.md` | 面向用户的端到端场景、异常路径和验收映射 |
| `doc/概要设计.md` | 架构分层、依赖方向和演进边界 |
| `doc/数据模型与生命周期.md` | 实体、状态、幂等和数据保留 |
| `doc/事件与工作流设计.md` | 事件匹配、节点合同和执行语义 |
| `doc/BlueBubbles集成说明.md` | 外部 API、Webhook 和适配器假设 |
| `doc/接口与配置契约.md` | API、Schema 和环境变量契约 |
| `doc/开发指南.md` | 本地开发、测试和变更流程 |
| `doc/代码管理规范.md` | 分支、Commit、PR 和合并规则 |
| `doc/安全与数据隐私.md` | 认证、Secret、消息保护和审计 |
| `doc/部署与运维.md` | Compose、升级、备份和故障处理 |
| `doc/版本与发布规范.md` | SemVer、Tag、镜像和 Release |

实现与文档冲突时，先更新对应的权威文档，再修改代码；同一 PR 必须说明两者是否保持一致。

## 3. 文件与命名

- 中文说明文档放在 `doc/`，文件名使用简洁中文名，例如 `事件与工作流设计.md`。
- 机器可校验的契约放在 `contracts/`，文件名和字段使用英文。
- README 的多语言文件只放在仓库根目录。
- 图表使用 Mermaid 或仓库内可追踪的 SVG/PNG，不引用个人电脑绝对路径。

## 4. 维护要求

- 新增功能先更新需求、架构或工作流文档中的适用章节。
- 修改 API、配置、权限、数据库或消息语义时必须更新对应契约和升级说明。
- 翻译文档可以暂时落后，但不能改变中文源版本的产品含义。
- 文档示例只能使用虚构聊天、令牌和域名；不得复制生产消息。
