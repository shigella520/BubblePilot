# BubblePilot 产品与范围

## 产品定位

BubblePilot 是面向 BlueBubbles 的自托管消息归档、自动化与 AI Bot 平台。它接收 BlueBubbles 消息事件，转换为统一消息信封，只归档已启用监听的聊天，再按配置执行版本化工作流并把结果回复到原聊天。

BubblePilot 不替代 BlueBubbles。BlueBubbles 是外部消息网关；PostgreSQL 才是 BubblePilot 聊天元数据、归档消息、工作流、执行、凭据元数据和审计记录的权威来源。

目标用户包括：

- 希望保存和搜索指定 iMessage 对话的个人用户；
- 希望用可视化流程创建群聊 Bot 的自动化维护者；
- 希望接入多个 AI 服务并按需联网搜索的 AI 应用维护者；
- 负责私有部署、备份、升级和故障恢复的运维者。

## 当前范围

首个大版本的功能闭环已经完成。当前可用范围如下：

| 编号           | 能力                 | 验收结果                                                                           |
| -------------- | -------------------- | ---------------------------------------------------------------------------------- |
| `REQ-MSG-001`  | BlueBubbles 消息接入 | 合法 Webhook 可追踪入库，非法来源和无效 Payload 被拒绝                             |
| `REQ-MSG-002`  | 选择性监听与归档     | 未监听聊天不保存正文；监听变更只影响后续消息                                       |
| `REQ-MSG-003`  | 消息幂等             | 同一外部事件重投不重复保存、执行或回复                                             |
| `REQ-MSG-004`  | 对话成员身份         | 按聊天为历史出现的 sender ID 配置本名和昵称，AI 只使用当前上下文实际出现成员的映射 |
| `REQ-FLOW-001` | 触发和工作流编排     | 支持聊天、发送者、消息类型、文本和时间条件，以及版本化节点图                       |
| `REQ-FLOW-002` | 执行追踪与恢复       | 可解释每次匹配、节点、AI 尝试和回复状态，失败可按安全边界人工处理                  |
| `REQ-AI-001`   | 多 AI Provider       | OpenAI 兼容 Provider 可配置、测试、排序、启停和加密保存 API Key                    |
| `REQ-AI-002`   | Provider 路由        | 支持有界 Retry、Fallback、自动降级、冷却恢复和版本快照                             |
| `REQ-AI-003`   | Agent 联网搜索       | 支持 `disabled`、`auto`、`required`，托管搜索或 Function Calling + SearXNG         |
| `REQ-AI-004`   | 原生图片理解         | 支持当前附件、卡片主图和有限历史图片，按已验证视觉 Provider 路由并安全降级         |
| `REQ-AI-005`   | AI 用量与缓存观测    | 按 Provider 展示今日、本周、本月 Token/请求汇总及最近小时级缓存命中趋势            |
| `REQ-WEB-001`  | Web 管理             | 完成聊天、消息、工作流、AI、执行、设置和受控导出的管理闭环                         |
| `REQ-AUTH-001` | 两级认证             | 登录和敏感操作密码相互独立，服务端逐请求授权并记录审计                             |
| `REQ-OPS-001`  | 私有部署与可靠性     | Compose、健康检查、限流、有界队列、死信、备份、升级和诊断工具可用                  |

非功能基线：

- **可靠**：接收、归档、执行和回复都有明确状态；可恢复但不重复回复。
- **可解释**：保存关联 ID、版本、耗时、错误码、Provider Attempt 和有界工具轨迹。
- **安全**：Secret、完整 Prompt、原始 Webhook 和消息正文不进入普通日志。
- **可扩展**：供应商适配器、工作流节点、AI Provider 和执行调度通过接口隔离。
- **可部署**：默认模块化单体和进程内队列，不要求微服务或外部消息队列。

## 核心用户闭环

### 1. 从新实例到可用自动化

1. 运维者配置 Secret、两套密码、BlueBubbles 回退连接和数据保留期，启动 Compose。
2. 管理员在 BlueBubbles 中创建 `New Messages` Webhook。
3. 第一条消息发现聊天；管理员完成二次验证并启用监听，可为历史出现的成员 ID 补充本名和昵称。
4. 管理员按需创建 AI Provider 和路由。
5. 自动化维护者在画布中创建“消息触发器 → 动作节点 → 回复 → 结束”，保存并启用。
6. 第二条符合条件的消息被归档、匹配、执行并回复；管理端可查看完整轨迹。

未完成任一步时，系统应显示可以继续行动的状态，而不是把“未发现聊天”“未监听”“无匹配触发器”和“执行失败”混为一类。

### 2. 一次成功的 AI 回复

工作流启动时锁定消息、工作流版本和 Provider 路由快照。加载上下文动作同时解析本次窗口和当前消息实际出现成员的身份映射，AI 节点自动按 sender ID 区分每句话的发言者，不加载群外映射；启用原生图片输入时，当前附件、卡片主图和有限历史图片只发送给已验证的视觉 Provider，失败时明确降级为文本；首选 Provider 失败时按路由有界切换。输出通过长度与格式检查后，由回复节点使用稳定幂等键发送。聊天参与者只看到一次回复，管理员能查看每次 Provider、工具和脱敏图片轨迹，但看不到 API Key、原图或不必要的完整 Prompt。

### 3. 不误触发、不重复回复

- 未监听聊天不保存正文，也不进入生产工作流。
- 条件未命中时保存可解释的自动化判定，不创建执行。
- 生产触发器拒绝 Bot 自身消息，防止回复循环。
- Webhook 重投沿用外部事件键；执行和回复分别有稳定幂等键。
- 同一消息可能命中多个触发器时，配置端提示潜在重复回复，但不替代真实运行匹配。

### 4. 从故障中恢复

明确未生效的临时故障可以在配置的有限尝试次数内自动重试；结果未知的外部发送不能盲目重发。达到上限的执行进入失败或死信状态。人工恢复会创建关联的新执行，并继续使用原消息、Trigger 和 Workflow Version；人工关闭保留全部轨迹。出站状态为 `sending`、`unknown` 或 `confirmed` 时禁止人工重发。

### 5. 搜索和导出敏感数据

敏感操作授权统一通过顶部栏 GitHub / 登出旁的入口打开弹窗完成；成功后自动关闭，顶部显示授权状态，已解锁时可查看有效期。页面与模块不再嵌入密码表单，授权到期仍自动隐藏敏感内容并禁用相关操作。

管理员必须完成二次验证才能查看正文、修改监听、维护成员身份或导出数据。导出限定一个已监听聊天、最长 31 天、最多 10,000 条且预计不超过 25 MB；流程为冻结预览、明确确认、短时下载，并为预览、确认、下载和取消分别写入审计。

## 非目标

当前不承诺：

- 替代 BlueBubbles 的同步、联系人或设备管理；
- 运行用户提交的任意服务器脚本；
- 无审计地批量删除或导出生产消息；
- 用 AI 判断替代权限控制或业务事实；
- 在没有实际负载和隔离需求前引入微服务、Kafka 或任意脚本运行时；
- 多租户和细粒度角色权限。

## 后续方向

后续能力只有在现有数据和执行合同保持稳定时进入实现：

- 更多消息来源适配器；
- 可复用工作流模板和版本仓库；
- 外部持久队列与独立 Worker；
- 多用户、角色和租户隔离。

这些方向不是当前部署的依赖，也不应提前改变模块化单体的边界。

## 长期聊天检索（开发分支，发布验收中）

`REQ-MEM-001`～`REQ-MEM-009` 的需求追溯见[长期聊天检索规划](迭代需求-长期聊天检索.md)。管理员配置 Embedding 服务并授权当前聊天后，AI 对话节点可自主调用历史搜索与原文展开工具，无需新增工作流节点。全局与聊天授权默认关闭，历史补建单独启动。保留双窗口近期原文；仅检索已归档、未清理、当前授权聊天且早于触发消息的内容。

管理闭环为配置与探测 → 聊天授权 → 有限历史补建 → 人工检索核对 → AI 按需查证 → 来源追溯。无答案、覆盖不足和工具不可用必须区别表达。首期支持 Ollama 与 OpenAI 兼容 Embedding API，不提供跨聊天知识库、结构化偏好记忆或图像向量检索。真实模型质量验收未完成前不发布该能力。

### 历史补建任务进度

聊天整体覆盖与单次补建任务分开展示。任务详情弹窗显示范围、模型代次、已处理/初始总数、百分比、剩余量和清理移除量；旧任务缺失统计时明确标注。仅当前处理任务估算完成时间，排队任务不预估。新增消息索引的范围可增长，不显示固定百分比或 ETA。完成只说明所选任务范围已处理，不代表整个聊天历史已覆盖。

长期记忆遵循现有页面导航与工作区布局：执行与审计的“历史索引”、消息页聊天监听列表中的“长期记忆授权 / 配置”和 AI 服务的配置均置于工作区内。聊天长期记忆通过逐聊天弹窗管理，固定当前聊天，提供授权、历史补建、检索测试和该聊天的索引任务；不再单独占据下方栏目和侧边导航。任务使用分页列表与详情弹窗；来源原文在授权后通过弹窗查看。聊天选择覆盖全部聊天，历史补建与人工检索使用独立时间范围。

历史检索回复延续原有角色和日常聊天语气，不自动附加日期、参与者列表或来源括号，不逐条汇报无关命中。用户需要时间或人物信息时自然回答；没有相关证据时简短表达不确定，不能编造。后台继续保留受保护的来源查看。


聊天 AI 摘要已移除：不生成、不重建、不展示存量聊天摘要。保留基础与缓冲消息窗口、图片摘要和五个历史工具；模型自行组合检索获取更早证据。窗口缺口说明不等于事实审核，不承诺消除错误回答。


### 表情包库与 AI 选图

新增一级「表情包」页面（`/#/memes`），全局共享素材库，管理员登录即可上传、编辑、启停、删除及管理摘要，不需要敏感解锁。支持 JPEG、PNG、静态 WebP 和 GIF，单图10 MiB。上传弹窗提供图标选图按钮、拖放反馈、选图预览、文件大小与上传进度；摘要参考名称、描述及标签，只输出素材内容与场景，不复述内部规则。上传后素材立即可用，摘要异步处理；GIF 列表及摘要使用首帧，详情可播放原图。

AI 节点按需开启「允许使用表情包」，仅文本模式可用，旧工作流默认关闭。模型可检索并选择一张表情，也可只回答文字。文字确认成功后再发送原图。图片失败不重新生成回答或重发文字，在操作概览和执行详情独立跟进。暂不支持仅发表情、混合气泡、Private API 原生引用或自动采集。

### 表情合集与批量管理

表情包页面提供桌面左侧合集导航和移动端顶部选择器，固定包含“全部表情”“未分类”。每张素材最多属于一个合集，标签继续用于情绪和场景。合集展示静态封面、名称和未删除素材数（包含停用素材）；支持新建、重命名、说明和成员封面，封面失效自动回退至最早加入的有效成员。删除合集只把成员移入未分类，不改变图片或启用状态。

上传默认使用当前具体合集，全部或未分类入口默认未分类；全库哈希去重不会移动已有素材。筛选和页码写入 URL；切换合集或筛选清空多选，选中素材期间暂停自动刷新。支持当前页或全部筛选结果的固定选择、批量移动、启停与逻辑删除。最多选择 5,000 张，每批 100 张依次处理，展示进度、逐项失败和核对入口；停止只阻止后续批次，不能撤销已提交请求。

本轮不包含多级合集、多合集归属、批量上传、自动分类、分享或工作流限定合集。合集管理沿用管理员登录和审计，不要求敏感解锁。


### 表情使用统计与排序

表情卡片显示累计成功使用次数，详情显示最近确认时间；零次显示“尚未使用”。次数仅代表 BlueBubbles 确认发送成功，不代表已读。表情库支持最新上传、最早上传、使用最多、使用最少和最近使用排序，适用于全部、未分类和具体合集。统计不参与 AI 检索排序。
