# BubblePilot 部署与运维

## 1. 部署目标

首期使用 Docker Compose 部署模块化单体、数据库和必要依赖。生产实例至少包含：

```text
reverse proxy / HTTPS
        ↓
BubblePilot application
        ↓
database
```

消息队列和独立 Worker 不是首期必需组件，只有当吞吐、隔离或故障恢复需求明确后才引入。

## 2. 环境配置

环境变量或外部 Secret 至少覆盖：

```text
APP_BASE_URL
DATABASE_URL
BLUEBUBBLES_SERVER_URL
BLUEBUBBLES_ACCESS_TOKEN
APP_LOGIN_PASSWORD_HASH
SENSITIVE_OPERATION_PASSWORD_HASH
AI_PROVIDER_BASE_URL
AI_PROVIDER_API_KEY
AI_PROVIDER_MODEL
MESSAGE_RETENTION_DAYS
```

真实值不写入 Compose 文件、仓库、镜像标签或日志。密码应保存为应用支持的强哈希，而不是明文。

## 3. 启动流程

1. 准备 `.env` 或外部 Secret。
2. 检查 BlueBubbles 可连通、Webhook 地址可访问。
3. 执行 `docker compose config` 检查配置展开结果。
4. 启动服务并等待数据库迁移完成。
5. 检查应用健康接口、数据库连接和 BlueBubbles 适配器状态。
6. 在测试聊天发送一条消息，确认入站、归档、匹配和回复链路。

## 4. 健康检查

健康检查应区分：

- 进程是否存活；
- 数据库是否可用；
- Webhook 接收是否启用；
- BlueBubbles REST 是否可访问；
- AI Provider 是否配置（不应通过健康检查泄露密钥）；
- 未处理、重试和死信数量。

## 5. 备份和恢复

- 备份数据库、工作流定义、配置元数据和审计记录。
- Secret 不与数据库备份放在同一个无保护位置。
- 定期进行恢复演练，记录恢复时间和失败项。
- 恢复后检查迁移版本、工作流版本、Webhook 幂等记录和回复状态。

## 6. 升级和回滚

升级前：

- 阅读 Release Notes；
- 备份数据库；
- 检查迁移是否可前向升级；
- 确认 BlueBubbles 和 AI Provider 兼容性；
- 准备上一版本镜像和回滚步骤。

回滚应用版本不能自动回滚数据库迁移。若迁移不可逆，必须在发布说明中明确恢复策略。

## 7. 故障处理

排查顺序：

1. 按 `correlationId` 查看入站和执行记录。
2. 确认是否为重复事件、监听范围过滤或工作流版本问题。
3. 区分 BlueBubbles、AI Provider、数据库和应用节点错误。
4. 检查重试次数和死信，不直接手动重复发送消息。
5. 修复后通过幂等重试或人工重试恢复，保留原始失败记录。
